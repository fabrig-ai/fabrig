## A. Codec generator (S docs/design/codec.md)

**Crates.** `skein-codec` (S crates/skein-codec) holds what generated code shares: the failure reasons, bounded reads, the version read and the "piece" helpers (codec.md:41-47). `skein-codegen` (S testing/skein-codegen) is the generator, ordinary Rust; a consumer depends on it only in tests (codec.md:48-49). A consumer's codec crate holds its schema, the generated code, its golden bytes and its drift test (codec.md:50-53).

**Schema file.** Plain text, one file per family and version, e.g. `crates/<c>/schema/<name>-v<N>.schema`. Parser: `skein_codegen::parse(&str) -> Result<Schema, Error>` (src/parse.rs:181).
- First line: `family <name> <u16>`.
- Declarations: `record`, `versioned record` (parse.rs:203, starts with a u16 version) and `enum`.
- A variant can be `name: boxed Rec` (parse.rs:162). `#` starts a comment (parse.rs:34).
- Field types (parse.rs:116-126, lib.rs:72):

| Type | Encoded as | Rust |
|---|---|---|
| `u8/u16/u32/u64` | big-endian | same |
| `bool` | one byte | `bool` |
| `duration` | u64 nanoseconds | `lib::Duration` |
| `fixed N` | N bytes | `[u8;N]` |
| `bytes N` | u32 length + ≤N | `Box<[u8]>` |
| `secret N` | as bytes N | `skein_lib::Secret` |
| `text N` | as bytes N, UTF-8 checked | `Box<[u8]>` |
| `list N T` | u32 count | `lib::List<T>` |
| `option T` | 0/1 byte + value | `Option<T>` |

The table is codec.md:85-97 and emit_types.rs:16-17.
- **`secret` and `text` both exist, and both require a bound N**: `self.bound()` refuses a missing number (parse.rs:101-104).
- A type may only use types declared before it. There are no imports: a foreign record travels as `bytes N`.

Example:
```
family temper-worker-wire 1
# comment
enum Kind { plain, rich }
record Item { tag: u64 hash: fixed 32 note: option text 256 }
record Identity { token: secret 1024 login: text 256 name: text 256 email: text 256 }
record Batch { items: list 64 Item body: bytes 65536 kind: Kind }
enum Outcome { done: Batch, big: boxed Batch, failed }
versioned record Kept { at: duration }
```

**Running the generator.**
- Library: `skein_codegen::generate(&Schema) -> Output { rust: String, goldens: Vec<Golden{name, bytes}> }` (lib.rs:90-137).
- Binary `skein-codegen <schema> <out-dir>` (Cargo.toml `[[bin]]`; src/main.rs:10, 19, 23). It writes `<out-dir>/v{N}.rs` and `<schema-dir>/../golden/v{N}/*.bin`. It takes one schema file only.
- There is no build.rs. **The generated code is committed.** Its first line reads `// Generated by skein-codegen from <family> <N>. Do not edit.`
- The consumer keeps it out of formatting with `#[rustfmt::skip] #[path = "generated/vN.rs"] pub mod vN;` (J crates/jig-protocol-worker-wire/src/lib.rs:9-11).

**What is generated per family:**
- `Limits`, `CEILINGS`, `check_limits(&Limits) -> Result<(), Problem>`, `Path` and `Problem { path, reason: skein_codec::Reason }` (emit_limits.rs:53-95).
- Per record: `XParts`, `X::new(&Limits, XParts) -> Result<X, Problem>`, accessors, `into_parts`, `measure() -> u32`, `encode(&mut Writer) -> Result<(), Overflow>`, `decode(&Limits, &mut Reader) -> Result<X, Problem>`.
- `worst_case_bytes(&Limits)` and `worst_case_heap(&Limits) -> Option<u64>`, per type and per family (emit_worst.rs:62-115).
- **No version constant is generated.** The consumer writes it by hand.

**Tests.**
- Generated, inside `#[cfg(test)] mod golden_tests` in the generated file (emit_tests.rs:307):
  - golden cases, smallest and full, for every record and every enum variant;
  - bound cases, each field at its limit and one past;
  - batched about 64 per `#[test]` (emit_tests.rs:260-305).
- The golden `.bin` files are also checked by the consumer's drift test.
- Written by the consumer (codec.md:239-243): the fuzz test (decode random bytes, never panic, re-encode to the same bytes), the memory test, and the drift test.

## B. Network libraries (all are step machines with `new / up / down`)

**skein-http client** (crates/skein-http/src/client.rs):
- `Client::new(&Limits) -> Client` (:334).
- `up(&mut Client, &Env<Limits>, Up, &mut Queue<Event>, &mut Queue<Down>)` (:359); `down(.., Request, ..)` (:373).
- `Request` (:157): `Call(Call) | Upload(Down) | Body(Down) | Discard | Close`.
- `Call { method, target, headers, body: Body::{None, Length(u64)}, close }` (client/request.rs:15-38).
- `Event` (:182): `Response | Upload | Body | Done(Reuse) | Failed(Error) | Closed`.
- `Error` (:253):
  - `Closed(Option<Fault>)` (:259): the server saw none of the request, so it can be retried on another connection.
  - `Truncated { answered: bool }` (:266): unknown whether the server acted.
  - `Stream(Fault)` (:268): failed after the request began going down.
  - Also `Refused, Status, Version, Header, HeadTooLong, ...`.
- `Limits.request` is the longest request head (:77).

**skein-http server** (server.rs):
- `Server::new` (:441); `up` (:484); `down` (:499).
- `Request` (:184): `Next | Respond(Response) | Body | Discard | Reply(Down) | Close`.
- `Respond` can be sent at any point in the exchange. A response given before the body is read gives the body up (:188-193, 228-231).

**skein-json** (crates/skein-json/src):
- `Tokenizer::new(&Limits)` (tokenizer.rs:279); `up` (:353); `down` (:388).
- `Request` (:188): `Next | Text(u32) | Skip | Close`. `Text(cap)` keeps a string up to `cap` bytes; a longer one is answered `Event::Long(u64)` with its full length (:193, :206).
- `Token`: `ObjectStart, ..., Key, String, Number(Box<[u8]>), True, False, Null` (token.rs:11).
- Sized writer, two passes: `Encoder::measure(&Limits)` (writer.rs:136), then `.measured() -> Result<u32, Refusal>` (:395), then `Encoder::write(len, &Limits)` (:147), then `.finish() -> Box<[u8]>` (:412).

**skein-tls client:**

- `client::Client::new(&Config, Name, &Limits) -> Client` (client.rs:205).
- Roots come from skein-shell: `Trust::{Machine { ssl_cert_file: Option<PathBuf> }, Der(PathBuf)}` (startup.rs:49) and `read_trust_roots(&Trust, &RootBounds) -> Result<Roots, RootsRefusal>` (:90).

**skein-kv** (crates/skein-kv/src):

## F. Mismatches between the temper design and the pins

- **channel.md §6** writes `record Identity { token: secret  login: text ... }` with no bounds. The parser refuses that; it must be `secret N` / `text N`.
- **channel.md §6** says "The record's `Debug` shows lengths only (skein-lib's `Secret`)". Only the `secret` field hides its bytes (secret.rs:30-34). The `text` fields (login, name, email) are `Box<[u8]>` with derived `Debug`, so they print in full.
- **protocol.md §5** says crate `temper` holds "the four commands of section 4, copied from jig's reference binary". jig's only binary, `jig-test`, has just `serve | agent` (J testing/jig-test/src/lib.rs:17). `open` and `sign-in` have no jig binary to copy from.
- **domain/testing.md §4.1** says the process tier runs the fake peer "as a process". At the pin it is a `Host` in `skein_world::real::World` on the test thread, not an OS binary, and it uses fixed port 34443.
- **protocol.md §11** says "the fake git program, on skein's fake machine". The fake machine only answers files and fixed fixtures; a fake git needs a `HostedProgram` registered with skein-world.
- **Regeneration:** jig's worker-wire drift test has no `SKEIN_CODEGEN_WRITE` mode; client-wire's and store-codecs' do. Copy the client-wire pattern.
- Present and correct: `skein_shell::open_root` (ring.rs:1595), `Io::adopt_read_pipe` / `adopt_write_pipe` (layer.rs:158/167), and `skein_lib::Intake` (intake.rs:25: allocated once at its cap, never grows).

## Missing at the pin
1. `ByteRing` in skein-lib: absent. temper's performance.md already plans its own module. The nearest thing is smith-host-protocol's `keep_tail` (process.rs:486), which keeps the last N bytes but rebuilds the list on every write.
2. A capped, doubling growth buffer in skein-lib: absent. `List`, `Writer` and `Intake` all allocate their capacity up front.
3. A fake-peer or fake-issuer binary: none. Both are in-process `Host`s.
4. Command-line program faces in skein-fake-machine: none beyond the echo/exit/never/fork fixtures. Use skein-world's `HostedProgram`.
5. Generated version constants: none. Families write `VERSION`/`MAGIC` by hand, and `versioned record` embeds the version in the bytes.
