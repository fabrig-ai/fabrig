# Session 04: temper's families in jig's store

`temper-protocol-store`, a crate of step code: temper's families under
jig's application tag in jig's store (store/README.md). One family per
variant of the forge connector's `Stored`, in its order, keyed by a
family byte and the key's fields as skein-kv's key writer writes them, so
that bytes sort as `Key` derives its order; one schema of records,
generated by skein's generator, and total translations from the forge's
`Stored` to the generated `Row` and back; the restart's one interval;
`STORE_VERSION`; and the largest key and value of temper's families,
from the forge's limits, for jig's size check. The store's routing,
which calls this crate, is `temper-service`'s (08.2a); the engine worlds
run it from 18.1.

## What the design asks

- **One family per forge record** (store/README.md, 2): "One per variant
  of `temper_engine_domain_forge::Stored` ... in the order of its
  variants, which is also the order of its `Key`", bytes 0 (`Call`) to 15
  (`Application`).
- **Keys** (3): "temper's own bytes start with the family's byte ...,
  then the key's fields"; "a variant's index as a tag, then its fields in
  order; every number big-endian as eight bytes, narrower ones widened; a
  byte string escaped and terminated; a commit as its 32 bytes, a byte
  string; a list of byte strings (a branch's segments) as each string
  marked, then an end mark"; "Written out, not generated ... A property
  test holds each encoder to the order `Key` derives, on generated keys of
  every family, and each decoder to its encoder; a decoder refuses a tag
  it does not know, a number past its field's width, and trailing bytes."
- **A key and its record agree** (3): "the routing checks that a decoded
  record's key encodes to the row's key, and a row where they differ is
  one that does not decode, which stops the engine".
- **Records** (4): "One schema ... with a record for each family and for
  every value those records carry ... translated to and from the
  generated ones by small total functions, exhaustive both ways";
  "Collections the domain bounds by their bytes in all are one piece, and
  those it bounds by a count of its own are counted lists"; "The
  schema's limits are made from the forge's limits, and checked against
  the schema's ceilings at start".
- **`STORE_VERSION`** (4): "one number for all of temper's families, 1 at
  first, moved once per plan"; README: "`STORE_VERSION` stays 1 in this
  plan".
- **Sizes** (4): "`temper-protocol-store` computes, from the forge's
  limits, the largest key and the largest value of its families, and
  hands them with `STORE_VERSION` to jig's component"; findings: the
  check is jig's `sizes::check`, a function the caller runs (08.2b).
- **The restart's interval** (5): "every key under temper's tag";
  "`Range::contains` admits every forge key and no core key; a test
  checks the interval against it on generated keys of both".
- **Tests** (6): "each family's key encoder against the derived order,
  and its decoder against its encoder; the interval ...; each codec both
  ways, with golden bytes; each translation both ways, a domain value
  equal to itself after a round trip; the schema's bounds at their limit
  and one past; the sizes against the forge's limits"; "Fuzz targets for
  each family's decoder and for the key decoder."

## Choices this plan makes

- **The crate follows jig's reference application's** (`jig-test-store`):
  `keys::{encode, decode}`, `records::{encode, decode}`, `interval`,
  `application`, `Undecodable`, `STORE_VERSION`, one `versioned record
  Row { value: Value }` whose `Value` enum has one variant per family in
  `Stored`'s order. It has no connector number in its keys: temper has
  one connector, and the family byte leads (store/README.md, 3).
- **Key encodings,** field by field, by `KeyWriter` (`tag` one byte,
  `u64` eight, `bytes` escaped and terminated): `Call`: task, attempt,
  completion, position as `u64`s; `ProposedEffect`, `Names`, `Entry`,
  `Change`, `Issue`, `Release`, `Application`: one `u64`; `Repository`:
  forge, repository as `u64`s; `Hold`, `BranchHead`, `PullState`: a
  `Name`, which is forge, repository, then `What`'s tag (0 repository; 1
  branch, each segment `tag(1)` then `bytes`, then `tag(0)`; 2 pull and
  3 issue, each with its `u64`); `Subscription`: task, then `Topic`'s tag
  (0 `Landings`, 1 `Ci`, 2 `Pull`, 3 `Participation`), forge and
  repository, then the branch's or the commit's `bytes` or the number's
  `u64`; `Ci`: forge, repository, the head's `bytes`; `Landed`: the
  commit's `bytes`; `Client`: tag 0 `Live` (forge, repository, then
  `client::What`'s tag, its branch one `bytes`, its numbers `u64`s) or 1
  `Repository` (forge, repository).
- **The largest key** under the forge's limits is `max(3 × name_bytes +
  19, 2 × name_bytes + 28, 92)`: a `Name` whose branch is `name_bytes`
  empty segments (each costs one byte of the domain's bound and three
  encoded), a `Landings` topic's branch, and a `Ci` subscription's fixed
  92 bytes. `keys::largest` computes it; a test checks it against an
  encoded key.
- **Times are their nanoseconds:** every `skein_lib::Time` and `Wall` a
  domain record holds is a `u64` of `as_nanos`, read back with
  `from_nanos`; durations are the schema's `duration`.
- **A signed number** (`ChangeRow.priority`, `i32`) is its two's-complement
  bits in a `u32` (`u32::from_be_bytes(priority.to_be_bytes())` and back).
- **`api::Error` is numbered explicitly** (Finding 14): the schema lists
  its variants in `api.rs`'s declaration order, and a table test pins each
  variant's tag byte, 0 `Unavailable` to 17 `Busy`, so a reorder of the
  domain's enum fails a test instead of changing stored bytes silently.
- **Pieces and counted lists:** a collection of items that hold bytes,
  bounded by the domain by a sum, is one piece written and split with
  `skein_codec::piece` (codec.md, 3), each item decoded by its record's
  code: a branch's segments (limit 4 × `name_bytes`), and every list of
  an answer (a summary's labels, items, comments, reviews, statuses,
  remarks, branches, files, a protection's contexts: limit the client's
  `answer_bytes` + 4 × `rows`). Collections of fixed-size items are
  counted lists bounded by the domain's count.
- **`change::State` nests itself** (`Held { was: Box<State>, why }`); a
  schema is a tree of fixed depth. A state is stored as `ChangeState {
  live, holds }`: the innermost state that is not held, and the holds
  that wrap it, outermost first; at most 8 (see the questions).
- **Each generated limit's source,** set by `bounds(&forge::Limits)`
  (the client's limits are `forge.client`):

## Rules that bind it

- "**Codec crates** link `skein-lib` and `skein-codec`, and, for the store
  crate only, `skein-kv`, `jig-protocol-store` and
  `temper-engine-domain-forge` (its translations' domain side), with the
  forge's three children whose types `Stored` and `Key` hold,
  `temper-engine-domain-forge-client`, `temper-engine-domain-forge-change`
  and `temper-engine-domain-forge-issues` (decisions.md, ruling 101). No
  codec crate links an engine or worker root." (code-organization.md,
  section 3) `temper-engine-domain` (for `Range::contains`), `jig-domain-core`
  and `jig-domain-tasks` (core keys) are dev-dependencies only.
- "No increment of this plan ... adds a field or predicate that its
  counterpart across a boundary lacks: a record mirrors its domain type
  field for field." (code-organization.md, section 6) A domain field
  this schema lacks breaks the translation's build, which is the check.
- "**An increment above about 600 lines** of production code is split by
  its session before it starts" (code-organization.md, section 8); a
  codec increment lands within 2.5 times its Size, its split parts
  counted together (ruling 106).

### 04.4a The client's rows, changes and issues

src/{records.rs, records/client.rs, records/change.rs, records/issues.rs,

Shape: the schema's 04.4a blocks. `encode_change_state(&change::State)
-> w::ChangeState` walks `Held` by a bounded `for` loop of at most 8
steps, collecting each `why`, outermost first, and ending at the first state
that is not held; `decode_change_state` wraps the live state in each
hold from the last to the first. In 15 lines:

```rust
fn encode_change_state(state: &change::State) -> w::ChangeState {
    let mut holds = List::with_capacity(8);
    let mut current = state;
    for _ in 0..=8_u32 {
        let change::State::Held { was, why } = current else {
            break;
        };
        holds.push(encode_hold(*why)).expect("at most 8 holds (change_state_holds)");
        current = was;
    }
    let parts = w::ChangeStateParts { live: encode_live(current), holds };
    w::ChangeState::new(&w::CEILINGS, parts).expect("admitted state fits the schema")
}
```

## Interface sketches

the same text. `v1` is a stand-in for the generated code.

```rust
//! Sketches of session 04: `temper-protocol-store`, temper's families in
//! jig's store (store/README.md), a crate of step code.
//!
//! The records are generated by skein's generator from one schema (the
//! session file holds it) into `src/generated/v1.rs`, declared as `pub mod
//! v1`; the `v1` module below is a stand-in for it. The keys are written
//! out, not generated (store/README.md, section 3). The crate links
//! `skein-lib`, `skein-codec`, `skein-kv`, `jig-protocol-store`,
//! `temper-engine-domain-forge` and its children `-client`, `-change` and
//! `-issues` only (ruling 101); the store's routing, which calls it,
//! is `temper-service`'s (08.2a). Until 04.4a (or 04.4b, when `Stored` has
//! `Application`), `records::encode` returns `Option`, none for a family a
//! later increment of 04 writes.

/// `crates/temper-protocol-store/src/lib.rs`.
pub mod temper_protocol_store {
    use temper_engine_domain_forge as forge;

    /// temper's store version: one number for every family of temper's,
    /// moved once per plan at the first landing that changes an encoding of
    /// temper's in the store (store/README.md, section 4). It stays 1 here.
    pub const STORE_VERSION: u32 = 1;

    /// Stand-ins for `src/generated/v1.rs` (family `temper-store 1`).
    pub mod v1 {
        /// Generated: one limit per bound of the schema, from
        /// `segments_segments` to `projected_milestones`, in schema order.
        #[derive(Clone, Copy, PartialEq, Eq, Debug)]
        pub struct Limits {
            _generated: (),
        }
        /// Generated `versioned record Row { value: Value }`: one stored row
        /// of any family, the value of the row's key.
        #[derive(Clone, PartialEq, Eq, Debug)]
        pub struct Row {
            _generated: (),
        }
    }

    /// A row that does not decode: a version, a bound, a tag or a key that
    /// disagrees with its record. The routing stops the engine on it.
    #[derive(Clone, Copy, PartialEq, Eq, Debug)]
    pub struct Undecodable;

    /// The generated limits made once from the forge's limits and checked
    /// against the ceilings once, where the routing is made; opaque.
    #[derive(Clone, Copy, PartialEq, Eq, Debug)]
    pub struct Bounds {
        limits: v1::Limits,
        forge: forge::Limits,
    }

    impl Bounds {
        /// The generated limits decoders are given.
        #[must_use]
        pub const fn limits(&self) -> &v1::Limits {
            &self.limits
        }
        /// The forge's limits keys are decoded against.
        #[must_use]
        pub const fn forge(&self) -> &forge::Limits {
            &self.forge
        }
    }

    /// The bounds for `limits`, by the session's table of each limit's
    /// source; none when one passes its ceiling (`v1::check_limits`).
    #[must_use]
    pub fn bounds(_limits: &forge::Limits) -> Option<Bounds> {
        unreachable!("sketch")
    }

    /// Every key under temper's tag: the one interval of `Range::Forge`,
    /// relative to the tag (store/README.md, section 5).
    #[must_use]
    pub fn interval() -> skein_kv::Range {
        unreachable!("sketch")
    }

    /// The largest key and value of temper's families under `limits`, with
    /// `STORE_VERSION`, for jig's `sizes::check` and the component's format
    /// row (store/README.md, section 4); none past a ceiling.
    #[must_use]
    pub fn application(_limits: &forge::Limits) -> Option<jig_protocol_store::sizes::Application> {
        unreachable!("sketch")
    }

    /// `src/keys.rs`: each family's key, written with skein-kv's key writer
    /// so that bytes sort as `forge::Key` derives its order (store/README.md,
    /// section 3), relative to jig's application tag.
    pub mod keys {
        use alloc::boxed::Box;
        use temper_engine_domain_forge as forge;

        /// The key's bytes: its family's byte, then its fields; none past `limit`.
        #[must_use]
        pub fn encode(_key: &forge::Key, _limit: u32) -> Option<Box<[u8]>> {
            unreachable!("sketch")
        }

        /// The key of `bytes`, refusing an unknown tag, a number past its
        /// field's width, a branch past the forge's `name_bytes`, and trailing bytes.
        #[must_use]
        pub fn decode(_bytes: &[u8], _limits: &forge::Limits) -> Option<forge::Key> {
            unreachable!("sketch")
        }

        /// The longest key any family encodes to under `limits`.
        #[must_use]
        pub fn largest(_limits: &forge::Limits) -> Option<u32> {
            unreachable!("sketch")
        }
    }

    /// `src/records.rs` and its modules: the forge's `Stored` to the
    /// generated `Row` and back, total both ways, no wildcard arm.
    pub mod records {
        use super::{Bounds, Undecodable};
        use alloc::boxed::Box;
        use temper_engine_domain_forge as forge;

        /// One row's value bytes, encoded measured; a row the forge admitted
        /// fits the schema's ceilings (`expect("admitted row fits the schema")`).
        #[must_use]
        pub fn encode(_row: &forge::Stored) -> Box<[u8]> {
            unreachable!("sketch")
        }

        /// One row's value, decoded within `bounds`.
        pub fn decode(_value: &[u8], _bounds: &Bounds) -> Result<forge::Stored, Undecodable> {
            unreachable!("sketch")
        }

        /// A restored row: its value decoded, and its key checked to be the
        /// key its record encodes to (`forge::stored_key`); a row where they
        /// differ is undecodable (store/README.md, section 3).
        pub fn row(_key: &[u8], _value: &[u8], _bounds: &Bounds) -> Result<forge::Stored, Undecodable> {
            unreachable!("sketch")
        }
    }
}
```

- **Who owns what:** this crate owns temper's keys, records and sizes;
  the routing that asks jig's component, encodes commits and decodes
  pages is 08.2a's; the size check against skein-kv's limits is 08.2b's.
- **What ends what:** nothing here has a lifetime; a row that does not
  decode is the routing's to report, and it stops the engine.

## Questions to raise when reached

- **A held change nested more than 8 times.** The change policy holds a
  held change again when its gates or clean heads pass their limits
  (`crates/temper-engine-domain-forge-change/src/domain.rs:19-23`), and
  its release asserts a held state's predecessor is live (`:158`).
  Default: 8 holds, the encoder's `expect` naming the bound; the
  designer may bound the nesting in the domain instead.
- **A field the domain bounds otherwise than the table.** Default: the
  domain's bound, named in the report.
- **`Application`'s refusal by the core,** if 02.4's outcome holds a
  type jig's reference application's refusal records do not mirror.
  Default: mirror 02.4's type field for field in records of this schema,
  copied from jig's `people-v2.schema` where it has one.
