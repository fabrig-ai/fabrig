# Session 03: temper's parts on jig's channel, and the forge family's client records

Two codec crates of step code, generated by skein's generator from one
schema each, version 1: `temper-protocol-worker-wire`, temper's parts
inside jig's channel records (the workspace items down; what a run left,
what it saved and a failed preparation up; a git identity's value inside
a grant) with `PAYLOAD_VERSION`; and `temper-protocol-client-wire`, the
forge family's records on jig's client wire (the keyed `Adopt` and its
outcome) with `FORGE` and `CLIENT_VERSION`. Each record is channel.md's or
client.md's, field for field. The session writes schemas and the little
Rust around them, and the world `tests/codecs` (drift and fuzzy tests)
that 04 and 06 extend. It writes no translation: the engine's and the
worker's are `temper-service`'s (08.3, 09.1), the client's 12.1's.

## What the design asks

- **One codec crate for the channel** (channel.md, 1): "generated by
  skein's generator from a schema (skein's `codec.md`), used by the
  engine's service and the worker's. It holds `PAYLOAD_VERSION`".
- **The records, as channel.md writes them** (sections 4 to 6):
  `Items`, `Repository`, `Start`, `Merge`, `Branch`, `Commit`, `Access`,
  `Writable`; `Left`, `Landed`, `Saved`, `SavedRepository`, `Landing`,
  `Files`, `PushFailure`, `PushReason`, `Diagnostic`, `Preparation`,
  `Missed`, `Tag`, `Missing`; `Identity { token: secret  login: text
  name: text  email: text }`. "Enums are numbered in this order."
- **By tag, never by place** (5): "a part must name its repositories
  itself"; `PushFailure`'s `repository` "stays the domain's own, a place".
- **Shown nowhere** (6): "The record's `Debug` shows the token's length
  only (skein-lib's `Secret`, the schema's `secret`)".
- **Within jig's ceilings** (8): "Each must fit the ceiling jig's schema
  gives its field" (items 1,048,576 bytes, left and saved 65,536,
  resource 1,024, grant 8,192); the largest parts are "each the generated
  codec's worst case under the side's limits".
- **Tests** (9): "each record at its smallest and fullest, golden bytes
  per record, bounds at their limit and one past, the worst cases ...;
  `Identity`'s `Debug` holding no byte of its token"; fuzz targets "on
  arbitrary bytes and on mutated golden bytes".
- **The forge family** (client.md, 4.6): "`FORGE`: the forge connector's
  number, 1"; "`CLIENT_VERSION`: the version of every record below, 1 at
  first"; "The request, `Adopt`: the project (u32); the forge's number
  (u16); the owner, the name, the prefix and the landing branch (byte
  strings); the role (owned, fork or context); home and ci (booleans);
  the checks (a list of u32)"; its outcome: "*adopted*", "*refused by the
  core* ... jig's refusal facts, carried whole as
  `jig-protocol-client-wire` encodes them", "*refused by the forge*, with
  the forge connector's reason: no such forge; not found; no access;
  refused; in flight; too large; unreachable; invalid answer".
- **No read or subject record** (client.md, 4.2): "the forge's side reads
  and watches nothing: `temper-protocol-client-wire` has no read or
  subject record".

## Choices this plan makes

- **Families and files:** `crates/temper-protocol-worker-wire/schema/worker-wire-v1.schema`
  (`family temper-worker-wire 1`) and
  `crates/temper-protocol-client-wire/schema/client-wire-v1.schema`
  (`family temper-client-wire 1`); each crate's `src/generated/v1.rs`,
  `golden/v1/`, `src/lib.rs` as jig's client wire's (`#[rustfmt::skip]
  #[path = "generated/v1.rs"] pub mod v1;`). The schemas are below; the
  planner ran `skein_codegen::parse` and `generate` on both (98 and 52
  goldens).
- **Ceilings are generous; limits are the side's.** A schema's bound is a
  ceiling the generated worst case must fit a `u32` at; each side's
  limits come from its domain's numbers through `Bounds` and `limits`.
  That the largest parts under a side's limits fit jig's ceilings is
  10.2's start check, which calls `largest`.
- **Names and branches 1024, a remote 1024, repositories 64, conflicted
  paths 1024 of 4096 bytes, the diagnostic 512** (`PushDiagnostic::CAPACITY`,
  its limit always the ceiling), an identity's token `secret 4096`, its
  login, name and email `text 256`.
- **Parts are not `versioned`:** `PAYLOAD_VERSION`, checked at the
  link's opening, picks their code (codec.md, 5: "Bodies carry no version
  of their own"). **`Adopt` and `AdoptAnswer` are `versioned`:** `Adopt`
  is kept in the client's small store (codec.md, 3: "A record kept beyond
  a channel carries its version"), and jig's reference application marks
  both its request and its outcome so.
- **`Adopt` mirrors `forge::Adoption` in its field order** (boundary.rs:128-141)
  with the provider's repository id gone and its forge number in its
  place, and without `host`, which the engine fills (client.md, 8): 02.3
  owns that type; landed code wins where 02.3's order differs.
- **`Role` has the domain's four variants in its order** (`owned`,
  `adopted`, `fork`, `context`, as `forge::Role`), so that both
  translations are total; the client never sends `adopted` (client.md,
  4.4 offers three). See the questions.
- **The core's refusal is `bytes 16777209`:** jig's client wire's
  `Refusal` at jig's `VERSION` (7 at the pin), whose worst case at jig's
  ceilings is 16,777,232 bytes; 16,777,209 makes `AdoptAnswer` at its
  ceiling (7 bytes of framing more) fit jig's `Owned.record`, 16,777,216.
  The engine's limit for it is jig's `Refusal::worst_case_bytes` under the
  engine's client limits (08.5b).
- **Hand-written:** each crate's version constants; `Bounds`, `limits`
  and the encoders of the top-level records; the worker wire's `Largest`
  and `largest` and `valid` (the identity's field rules, shared by 09.1's
  decoding and 10.2's start check). Nothing else.
- **`tests/codecs`,** package `temper-codecs-world`, ordinary Rust after
  jig's `tests/client-wire` (its `Cargo.toml` lints table, temper's
  `tests/clippy.toml`): one drift test and one fuzzy test per codec
  crate, extended by 04 and 06. Drift tests write the code and goldens
  again under `SKEIN_CODEGEN_WRITE=1`, as jig's client wire's does.
- **The generator at `opt-level = 3`** in the workspace's
  `[profile.dev.package.skein-codegen]`, as jig's `Cargo.toml:192-193`,
  so drift tests stay within their ceiling.
- **`boxed`:** a variant is marked `boxed` only where clippy's
  `large_enum_variant` fires on the generated code; the report names it.

## Rules that bind it

- "**Codec crates** link `skein-lib` and `skein-codec` ... No codec crate
  links an engine or worker root." (code-organization.md, section 3)
- "No increment of this plan ... adds a field or predicate that its
  counterpart across a boundary lacks: a record mirrors its domain type
  field for field." (code-organization.md, section 6) A field the domain
  type lacks, or one it has that the design's record lacks, is a
  question, never added.
- "**Keeping the pins.** Adding to any `Cargo.toml` a crate of jig, smith
  or skein that `Cargo.lock` does not hold yet moves that repository's git
  source ... The increment that adds one then runs, in this order, and
  commits the lock" the three `cargo update --precise` commands
  (code-organization.md, section 3). `skein-codegen` (03.1) and
  `jig-protocol-client-wire` (03.2, a dev-dependency of the world) are not
  in the lock at the base.

```text
family temper-worker-wire 1

# Down: the workspace items (channel.md, 4). Names, branches and the save
# branch take Bounds.name_bytes; the remote Bounds.remote_bytes; the list
# Bounds.repositories.
record Merge { branch: bytes 1024 base: fixed 32 }
record Branch { branch: bytes 1024 }
record Commit { commit: fixed 32 }
enum Start { merge: Merge, base: Branch, branch: Branch, commit: Commit, saved: Branch }
record Writable { push: bytes 1024 expected: option fixed 32 }
enum Access { writable: Writable, read_only }
record Repository { tag: u32 name: bytes 1024 remote: bytes 1024 start: Start access: Access identity: u32 }
record Items { repositories: list 64 Repository save: option bytes 1024 }

# Up: what a run left and saved, a failed preparation (channel.md, 5).
# Lists of repositories take Bounds.repositories; Files Bounds.conflicts
# paths of Bounds.path_bytes; the diagnostic its ceiling, the domain's
# PushDiagnostic::CAPACITY.
record Landed { tag: u32 commit: fixed 32 }
record Left { landed: list 64 Landed }
record Files { files: list 1024 bytes 4096 }
enum PushReason { missing_repository, missing_branch, missing_commit, refused, unreachable, broken, timed_out, cancelled, unavailable, busy, too_large, nothing, unknown }
record Diagnostic { output: bytes 512 cut: u64 }
record PushFailure { repository: option u32 reason: PushReason diagnostic: Diagnostic }
enum Landing { conflicted: Files, explained: PushFailure, landed: Commit, moved, failed, refused, unchanged }
record SavedRepository { tag: u32 from_saved: bool landing: Landing }
record Saved { repositories: list 64 SavedRepository }
enum Missing { repository, branch, commit }
record Missed { tag: u32 missing: Missing }
record Tag { tag: u32 }
enum Preparation { transient, missing: Missed, refused: Tag }

# Beside a grant: a git identity's value (channel.md, 6).
record Identity { token: secret 4096 login: text 256 name: text 256 email: text 256 }
```

Scope: the crate `crates/temper-protocol-client-wire` (step code): the
schema below, its generated code and goldens, `src/lib.rs` with `FORGE`,

`adopt_name`, `adopt_prefix`, `adopt_landing`, `adopted_owner`,
`adopted_name` and `rule_branch` to `field_bytes`; `adopt_checks` to
`checks`; `rule_contexts` to `contexts` and `rule_contexts_item` to

```text
family temper-client-wire 1

# The role, as temper-engine-domain-forge's Role, in its order.
enum Role { owned, adopted, fork, context }

# The keyed request (client.md, 4.6): forge::Adoption's fields in its order,
# the provider's repository id and the host left out. Byte fields take
# Bounds.field_bytes; checks Bounds.checks.
versioned record Adopt { project: u32 home: bool forge: u16 owner: bytes 1024 name: bytes 1024 prefix: bytes 1024 role: Role landing: bytes 1024 ci: bool checks: list 64 u32 }

# Its outcome (client.md, 4.6 and 4.7).
record Kinds { read: bool push: bool open: bool land: bool review: bool status: bool comment: bool issue: bool branch: bool }
record Rule { branch: bytes 1024 contexts: list 64 bytes 1024 approvals: u32 dismiss_stale: bool }
enum Protection { unknown, absent, rule: Rule }
record Adopted { forge: u16 repository: u32 owner: bytes 1024 name: bytes 1024 role: Role home: bool kinds: Kinds protection: Protection }
# jig-protocol-client-wire's Refusal, encoded at jig's VERSION; 16777209 so
# that AdoptAnswer at its ceiling fits jig's Owned.record (16777216).
record CoreRefused { refusal: bytes 16777209 }
enum ForgeReason { no_such_forge, not_found, no_access, refused, in_flight, too_large, unreachable, invalid_answer }
record ForgeRefused { reason: ForgeReason }
# unknown: the outcome's retention ended (02.2's Delivery::Application
# outcome None; client.md, 4.7, "unknown past the retention").
enum Outcome { adopted: Adopted, core_refused: CoreRefused, forge_refused: ForgeRefused, unknown }
versioned record AdoptAnswer { outcome: Outcome }
```

```rust
// tests/codecs/tests/client_wire.rs
use jig_protocol_client_wire as jig;
use skein_lib::{Reader, Writer};
use temper_protocol_client_wire::v1;

#[test]
fn a_core_refusal_carries_jigs_refusal_bytes_unchanged() {
    let refusal = jig::Refusal::NotWaiting;
    let mut writer = Writer::new(usize::try_from(refusal.measure()).expect("measured length"));
    refusal.encode(&mut writer).expect("measured room");
    let carried = v1::CoreRefused::new(&v1::CEILINGS, v1::CoreRefusedParts { refusal: writer.finish() })
        .expect("within the ceiling");
    let parts = v1::AdoptAnswerParts { outcome: v1::Outcome::CoreRefused(carried) };
    let answer = v1::AdoptAnswer::new(&v1::CEILINGS, parts).expect("an answer");
    let bytes = temper_protocol_client_wire::answer(&answer);
    let decoded = v1::AdoptAnswer::decode(&v1::CEILINGS, &mut Reader::new(&bytes)).expect("decodes");
    let v1::Outcome::CoreRefused(kept) = decoded.into_parts().outcome else { panic!("a core refusal") };
    let back = jig::Refusal::decode(&jig::CEILINGS, &mut Reader::new(kept.refusal())).expect("jig's refusal");
    assert_eq!(back, refusal);
}
```
