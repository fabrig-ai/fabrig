# Step temper-08.s1: the process tests wait for the state they read

Ruling 133, after 09.3's gate failed on `the_new_process_holds_no_descriptor_but_the_standard_three` (ruling 132) and
passed on its retry. A diagnosis at temper 70e329d9d found three races in the tests' observation, none in production:

- `Programs::marker` (`crates/temper/tests/support/owned.rs:152-180`) reads `/proc/<pid>/fd` once `comm` reads
  `sleep` (:159); the kernel renames the process at exec, while `sleep`'s loader still holds a transient fd 3: 16 of 300
  runs of the test alone failed with `[0, 1, 2, 3]`.
- `Programs::hung` (:67-74) returns once the `hung` file exists; the script creates it before `echo $!` writes the
  pid, so it can read it empty (`sleep pid: ParseIntError Empty`, :72): 3 of 20 runs of the whole file.
- `a_termination_signal_kills_the_commands_group_and_ends_the_preparation_interrupted` reads `/proc/<sleep>/stat` once
  (`crates/temper/tests/forge.rs:112`), as the killed sleep may still be exiting: 1 of 60 runs of the whole file.

Files: `crates/temper/tests/support/owned.rs` (**hotspot**), `crates/temper/tests/forge.rs`.
Shape: `marker` also waits for `/proc/<pid>/stat`'s state `S` (parsed after the last `") "`); `hung` takes the file
  once its pid parses; the test at :112 polls the stat until it is gone or `Z`, within `WITHIN` (`support/mod.rs:6`).
  The diagnosis's patch for the first two, which passed 300 of 300 alone and 1000 of 1000 under 16 busy loops:
  `~/src/rust/tmp/temper/forge-setup/logs/supervisor/temper-descriptor-race.patch`.
Test shape: no new test.
Proof: `cargo nextest run -p temper --test forge --retries 0 --no-fail-fast --stress-count 100` ends with every
  iteration passed, once; then the gate.
Don't: change production code, a test's assertion or `WITHIN`; add a retry or a sleep of fixed length.
