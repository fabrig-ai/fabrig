# fabrig

These lines add fabrig's rules to the ones above.

- **Its rules for agents:** the root `AGENTS.md` and each tree's `AGENTS.md`; whoever writes or reviews design reads `DESIGN.md` too.
- **Upgrades are supported before v0.1.0:** a stored format's change moves its version and brings its patch; a wire between engine, workers and agents moves its version and bridges the previous one both ways, or is declared breaking; a client's wire moves its version unbridged, and a client of another version is refused by name (`temper/docs/design/draft/redeploys.md`). The change's report names each version it moves.
- **Suites:** a plan's runs use the focused and fuzzy suites alone: never `tools/tiers/run`, a `<tier>-<tree>` profile or `scripts/browser.sh`, even where a spec says to. A story in a slow tier is written and compiled (`--no-run`), not run, and the report says so; after-landing runs it, and a red comes back as a repair, which may run the flagged test, by name, alone. No run of the product in a browser, a terminal or a box, no render check and no throwaway driver: a plan is complete when it lands.
- **Budgets and timeouts are the user's,** never raised by a role. Over budget is red (`skein/docs/foundation/testing-strategy.md`, 8.1). A layer is judged in instructions: red past its budget, or grown past main's count by more than its allowance (2%, at least a billion, or the user's accepted level where higher; `tools/tiers/budgets.md`, 8). The gate refuses it; the goal's close refuses it or warns where it is near (`tools/pre-pr/design.md`, 4.1), naming the layer and its most grown binaries. It is repaired by asking, in order: does the test belong to its tier (moving it to escape a budget is raising it, forbidden); can it be made faster, which means the same checks for less (a lower sample, fewer seeds, cases or assertions, a shorter story, or a test removed or ignored, in the code or in a design's words, is checking less, and is raising it, forbidden); if neither, the measurements go up as a question that only the user answers, with a figure for `tools/tiers/budgets.toml` that no role writes: never decide it yourself, and never answer it for a change, a goal or a milestone below you. Fewer checks done than main's are red at the gate too (`tools/tiers/budgets.md`, 13): restore them, or write a check reason only when the loss answers no budget: the tested code is gone, another test already makes the same checks, or a move to the tier it belongs to. Never write a `budget` reason or `by = "the user"`. Tests main ran that the change doesn't are only noted. A cut the gate doesn't red is still forbidden. The wall hard limit is a backstop: a run past it is starved, a warning, never red on that account; the tests it didn't run are unobserved, never passed, and the report names them.
- **A goal's reds,** failing on g and owned by no live change, are temper's records, which the goal's coordinator keeps with the `red` tool. Each is keyed as the delivery check names a failure (`test <binary_id> <name>`, `lint <package> <code> <file>`) and recorded at a commit of g. A change's check passes it when its base contains that commit.
