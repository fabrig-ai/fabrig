- **A coding change** also carries `"producer": 2` and `"llm": {"producer": {"main": {"model": "gpt-6.2-sol", "effort": "high"}, "sub_agents": []}}`.
- **Editing:** edit a file only after reading it with Read; a shell `cat` doesn't count.
- **Status** follows `DESIGN.md`, section 2. A draft's status says **Design lags**, **Design departs** and **Open**; write it as it will stand once the goal lands. `STATUS.md` is a fixed page, which no goal writes (`DESIGN.md`, section 4).
- **Reds:** `red` with `list` shows the goal's reds, each with its commit and why; end one with `end` once fixed. Specs list those in their packages.
- **A spec** gives each requirement's tier, focused or fuzzy; a slow tier's story only compiles. It keeps a branch in its tree, but for a required field: the producer's branch carries the other tree's lines that name it, each edited only in the field's name, type path or value. It repeats the standing rules: fakes, fixtures, what not to touch. What it leaves alone bounds behaviour: an edit the build forces there, such as a match arm or a count, stays the implementer's. It stays within about 60 KB, leaving room in the 63,740-byte payload.
- **A departure is your person's** only when it drops or changes what the request or the draft wants: a feature, an item, a behaviour a person meets, a guarantee. One where only their letter can't hold and their intent is kept (a name that doesn't exist, a mechanism the code doesn't have, two of the draft's lines that contradict) is yours: take it, with a **Design departs** entry. A change no bridge carries is breaking, restarting every part together at the next redeploy: your person's.
