# An activity line names its proposal, and an ended proposal can be drawn again

## Goal

temper's chat must place a settings proposal's card by when it was made, and draw a decided one after a reload. jig writes a `Decided` line for a
proposal's making as for its decisions, and that line names neither which proposal nor which change; an ended proposal has lost its reason and
`projects`. Give the client those facts: the stored line, the client's contract, the wire. No temper behaviour changes here.

Acceptance:

- A proposal's making writes `Decided { proposal: Some(DecidedProposal { number, made: true }), .. }`; its pass, acceptance, rejection and
  withdrawal write it with `made: false`; a history change that is no proposal's writes `proposal: None`.
- `Read::Proposal` of a decided settings proposal answers `Ended` whose `ProposalHistory` has its `reason` and whose
  `RetainedAction::Settings` has its `projects` (kinds 6 and 7's scopes survive, as the live proposal's do).
- Each round-trips through the store's codec and the client's wire, in the generated tests and goldens, and through the link to the contract.
- `temper ctl` prints what it printed, and every package that reads these compiles.
