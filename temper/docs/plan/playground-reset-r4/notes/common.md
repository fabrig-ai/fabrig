# Standing rules for every task of the playground-reset run

Every task of `temper/docs/plan/playground-reset-r4/` names this note.
Where a task departs from it, the task says so and wins.

- **Read first:** fabrig's `AGENTS.md`, your tree's `AGENTS.md`, then
  `temper/docs/plan/playground-reset-r4/notes/contracts.md` (the run's
  binding shapes), then the design sections your task names. The draft
  is `temper/docs/design/draft/playground-reset.md`; read it whole, it is
  short. The surveys in `notes/surveys/` hold file and line facts as of
  the run's base; check a fact against the code before you build on it.
- **Machines:** your slot is on a builder. hetzner6's hostname,
  `debian-16gb-hel1-6`, contains "hel1", but it is a builder, not hel8:
  build there through `heavy` as anywhere.
- **Not yours:** `docs/design/` (what the code taught you goes in your
  report), drafts, `docs/help/`, `docs/plan/`. A design's status file is
  its designer's too.
- **The old form stays only as D1 says** (contracts, section 1): no new
  reader of a forge from the document, but the seed's.
- **Tests:**
  - the focused tests of each package you change and of its direct
    dependents, in the `default` profile; `fuzzy` for a codec or a
    world your change reaches, the failing test alone;
  - never the slow tiers (`tools/tiers/run`, the `qa-*`, `process-*`,
    `browser-*` profiles). Test code in those tiers must still build
    (the queue builds every test binary): change it where your change
    breaks its build, and where an expectation there is plainly made
    wrong by your change, update it and list it in your report;
  - a world or fixture that names forges in its document keeps doing so
    (D1); a new test of records builds its forges as records.
- **Generated code:** temper's store and client wire schemas are
  generated by skein's generator; regenerate and refresh golden bytes by
  the drift test's write mode (`temper/tests/codecs/tests/suite/drift.rs`,
  its header), never by hand.
- **Old forms:** `scripts/old-forms.txt` of a tree only falls; if you
  remove an old form's use, lower its count with `python3 -I -B
  scripts/old_forms.py --write` from the tree's root.
- **Names:** the draft's words. `Playground`, not `Demo`, for anything
  you rename or add; leave a name you do not otherwise touch.
- **Report:** besides fab's sections, list under `## Interfaces` every
  public item you added or changed (path and signature), so the tasks
  after yours can be checked against it.
