## Goal

The forge connector's asks and the client wire take their run's shape
(the run's contracts, section 5): `SetUp` names no forge, `Connect`
names a kept forge or one to make, and `RemoveForge`, `StartPlayground`
and `EndPlayground` exist end to end, from the client's wire through the
service and the root's deployment-scope admission to the connector,
which refuses the three *not offered* until their bodies land. The
`forges` rows gain `finished` and `playground`. `StartDemo` stays as it
is. Every caller in temper compiles with the old behaviour.

Acceptance:

- Each new and changed request round-trips the client wire; each new
  outcome round-trips; a `ForgeRow` carries `finished` and
  `playground`. Goldens regenerated by the drift test's write mode.
- The service decodes `remove_forge`, `start_playground`,
  `end_playground` and the new `connect` forms into the domain's asks,
  and encodes their answers.
- The root admits the three new asks at the deployment's scope, as
  `SetUp`.
- The connector answers `RemoveForge` *remove refused, not offered*,
  `StartPlayground` *start refused, not offered*, `EndPlayground` *end
  refused, not offered*; `Connect` on a forge to make (GitHub, Forgejo)
  *connect refused, no such forge*; `Connect` on a kept forge and
  `SetUp` do what they do today, `SetUp` on the lowest-numbered
  configured forge that is owned, asked and not ended, and *not offered*
  when there is none.
- A row's `finished` is true when the forge is connected and has at
  least one adopted repository; `playground` is true for the demo's
  forge (`DemoConfig.adoption.forge`). Both get their record-based
  meaning in later tasks.
- Every temper package that names the changed items builds its tests.

## Steps

1. **Domain asks, `temper-engine-domain-forge/src/boundary.rs`:**

   ```rust
   pub enum Ask {
       Adopt(Adoption),
       /// Sets up the box's owned Forgejo, the machine's (contracts, 5 and 6).
       SetUp { org: Box<[u8]>, repository: Box<[u8]>, project: SetUpProject, playground: bool },
       StartDemo,
       /// The playground, made when chosen (draft 6.1).
       StartPlayground,
       /// The playground's reset (draft 6.2).
       EndPlayground,
       Connect { forge: ConnectForge, how: How },
       /// A forge removed whole (draft 4).
       RemoveForge { forge: u16 },
       Install { .. }, Accept { .. }, Reachable { .. },   // unchanged
   }
   /// The forge a `Connect` connects: one kept, or one it makes (contracts, 5).
   #[derive(Clone, PartialEq, Eq, Debug)]
   pub enum ConnectForge {
       /// A kept forge: GitHub's "Go on", a reconnect, or a seeded forge.
       Existing(u16),
       /// GitHub's, at its public addresses.
       GitHub,
       /// A Forgejo at the origin the person gave (`https://host[:port]`).
       Forgejo { address: Box<[u8]> },
   }
   #[derive(Clone, Copy, PartialEq, Eq, Debug)]
   pub enum RemoveAnswer { Removing, Refused(RemoveRefusal) }
   #[derive(Clone, Copy, PartialEq, Eq, Debug)]
   pub enum RemoveRefusal { NotOffered, NoSuchForge, Role }
   /// The reset's one answer, once the playground is gone (draft 6.2).
   #[derive(Clone, Copy, PartialEq, Eq, Debug)]
   pub enum EndAnswer { Reset, NotOffered }
   ```

   `Answered` gains `RemoveForge(RemoveAnswer)`,
   `StartPlayground(StartAnswer)`, `EndPlayground(EndAnswer)`. `Row`
   gains `pub finished: bool` (connected with its first repository
   adopted: draft 6.3) and `pub playground: bool`, with a doc line each.

2. **The connector, `asks.rs`, `domain.rs`, `connect.rs`.**
   `Event::Application`'s dispatch sends the three new asks to
   `asks::refuse` (or one function each), which answers through the
   connect state's answer table (`connect::State::answer`, made
   `pub(crate)`), as connect's refusals answer, and pushes
   `Request::ApplicationDone`. `application_answer` already reads that
   table. `SetUp`: `asks::set_up_forge(d) -> Option<u16>`, the lowest
   configured number whose `Configured` is `Mode::Owned`, `asked`, and
   not `forge_ended`; none answers `SetUpRefusal::NotOffered`;
   otherwise today's body with that number. `connect::start`:
   `ConnectForge::Existing(n)` runs today's path with `n`;
   `GitHub` and `Forgejo { .. }` answer
   `ConnectAnswer::Refused(ForgeRefusal::NoSuchForge)` (a carried key
   named unused, as today's refusals do). `forges()` fills `finished`
   and `playground` as the Goal says.

3. **The root, `temper-engine-domain`.** `ApplicationAnswer` gains
   `RemoveForge(forge::RemoveAnswer)`, `StartPlayground(forge::StartAnswer)`,
   `EndPlayground(forge::EndAnswer)`; `route/applications.rs` puts the
   three asks with `SetUp` at `ApplicationScope::Deployment` and
   translates the three answers in `answer`. `StartPlayground` takes no
   `application_demo` context (that is the playground part's).

4. **The wire, `temper-client-protocol-wire/schema/client-wire-v1.schema`**
   (in place, `CLIENT_VERSION` stays 11: client/README.md, 4.6):

   ```
   record SetUp { org: bytes 1024 repository: bytes 1024 project: SetUpProject playground: bool }
   record ExistingForge { forge: u16 }
   record NewForgejo { address: bytes 2048 }
   enum ConnectForge { existing: ExistingForge, github, forgejo: NewForgejo }
   record Connect { forge: ConnectForge how: How }
   record RemoveForge { forge: u16 }
   enum Request { ..., accept: Accept, remove_forge: RemoveForge, start_playground, end_playground }
   enum RemoveRefusal { not_offered, no_such_forge, role }
   record RemoveRefused { why: RemoveRefusal }
   enum EndRefusal { not_offered }
   record EndRefused { why: EndRefusal }
   enum Outcome { ..., accepted: AcceptedInstallation, removing, remove_refused: RemoveRefused, reset, end_refused: EndRefused }
   record ForgeRow { ...today's fields..., finished: bool playground: bool }
   ```

   New variants and fields go last. `StartPlayground`'s answers are
   today's `running`, `start_refused`, `start_failed`. `lib.rs`'s
   `decode_requesting` refuses a `forgejo` connect whose address is
   empty, and lets the three new requests through. Regenerate by the
   drift test's write mode (`temper/tests/codecs/tests/suite/drift.rs`).
   Update the wire's own tests (`src/tests.rs`) for the changed records.

5. **The service, `temper-service/src/family.rs`:** decode
   `remove_forge`, `start_playground` and `end_playground` into
   `Application::Forge(Ask::...)` as `SetUp` is decoded (its
   `PartyInput::Application` shape); `connect`'s `ConnectForge` into the
   domain's; the three answers into `removing` / `remove_refused`,
   `running` / `start_refused` / `start_failed` (the `start_answer`
   helper), `reset` / `end_refused`; `forges()` writes the two new row
   fields.
