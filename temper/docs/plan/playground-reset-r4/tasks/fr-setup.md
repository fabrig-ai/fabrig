## Goal

`SetUp` sets up the box's owned Forgejo, the machine's (contracts,
sections 5 and 6): it sets up the owned forge already kept and not
removing, if there is one (a seeded one, or one made before and not
finished), and otherwise makes its record from `application.owned`
(`bx-machine`'s `settings::Engine::owned`) through `make::make`, then
asks the box for it as `SetUp` does today. With no `application.owned`
and no owned record, `SetUp` is *not offered*. The `forges` subject says
whether `SetUp` is offered when no owned row exists (the playground
designer's contract problem in `notes/progress-playground.md`).

Acceptance:

- `forge-asks`' `asks::set_up_forge` becomes: the lowest kept owned
  record not removing (asked, as today's offer requires); else, with an
  owned template configured, `make::make` of the template's record, its
  number; else none (*not offered*). A make refused `Busy` answers
  `SetUpRefusal::Busy`, `Full`/`Invalid`/`Exhausted` `NotOffered`. All
  other refusals (invalid names, not under the box, busy setting up) are
  decided before the make, as today, so a refused `SetUp` makes nothing.
- The template's record (service, `startup/owned_record.rs`): from
  `Template::entry(0)` less its number, `asked` true; api `Socket(listen)`,
  `Plaintext`; git `http://LISTEN/`; web none; identity login the entry's
  bot login, author `Temper` and the bot's email; no files; `playground`
  false. It reaches the connector as `forge::Domain::configure_owned(
  Option<crate::Forge>)` (in `make.rs`, held on `make::State`), called by
  the root beside `configure_demo` from `Config.owned`.
- The client wire's `Forges` record gains `owned: Offer` (the deployment's
  `SetUp` offer when no owned row is listed: `offered` with a template
  under the box and no listed owned row, `not_under_the_box` with a
  template not under the box, `not_offered` otherwise); the service
  fills it in `family.rs`'s `forges`. Goldens regenerated by the drift
  test's write mode.
- A seeded owned forge (the template's forge 3) is set up exactly as
  today; a deployment with only the template makes forge N and sets it
  up; a second `SetUp` while it sets up answers `Busy`.
