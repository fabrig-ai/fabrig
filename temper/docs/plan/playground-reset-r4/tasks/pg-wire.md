## Goal

The client wire's playground read: `Read::playground`, answered by the
service from the forge connector's `Playground` row (contracts, 2) and
the deployment's `application.demo`, so the client reads the
playground's state, running or resetting, with the forge, project and
account the start made (draft `temper/docs/design/draft/playground-reset.md`,
6.1, 6.2: "the page shows the reset under way until the row is none").
And the start's one new failure, `project`, for the playground's
project refused at its making (`pg-start`). `Read::demo` and
`DemoAnswer` stay as they are until the demo goes.

Acceptance:

- `Read::playground` and `PlaygroundAnswer` round-trip the wire;
  `StartFailure::project` round-trips; goldens regenerated by the drift
  test's write mode;
- the service answers a `Read::playground`: no record when the
  deployment has no `application.demo`; else a `PlaygroundAnswer` whose
  `state` is `not_started` with no `Playground` row, `running` or
  `resetting` as the row says, `forge`, `project` from the row (none
  without one), `provider`, `owner`, `name` and `cues` from
  `settings::Demo` as `Read::demo`'s answer takes them;
- `forge::StartFailure::Project` exists and the service encodes it as
  `start_failed { why: project }`;
- every temper package that names the changed items builds its tests.

## Steps

1. **Schema** (`schema/client-wire-v1.schema`, in place, new variants
   and records last where order is visible):

   ```
   enum StartFailure { group: GroupFailed, account, adoption, not_connected, project }
   # The playground's state (draft playground-reset.md, 6.1, 6.2):
   # the Playground row's, not_started with none.
   enum PlaygroundState { not_started, running, resetting }
   enum Read { demo, playground }
   versioned record PlaygroundAnswer { state: PlaygroundState forge: option u16 project: option u32 provider: u32 owner: bytes 1024 name: bytes 1024 cues: list 8 text 256 }
   ```

   `lib.rs`, beside `demo_answer` / `decode_demo_answer`:

   ```rust
   /// Encode the playground's answer; no playground offered is no record.
   #[must_use]
   pub fn playground_answer(record: &v1::PlaygroundAnswer) -> Box<[u8]>
   /// Decode a complete playground answer, refusing empty cues, as the demo's.
   #[must_use]
   pub fn decode_playground_answer(bytes: &[u8], limits: &v1::Limits) -> Option<v1::PlaygroundAnswer>
   ```

   Regenerate by the drift test's write mode
   (`temper/tests/codecs/tests/suite/drift.rs`, its header), then run it
   without.
2. **Service** (`temper-service/src/family.rs`): in the `Read` arm, a
   `w::Read::Playground` branch beside `Read::Demo`'s, with the same
   `demo` guard, building `PlaygroundAnswer` as the Goal says
   (`forge::PlaygroundState::Running` → `running`, `Resetting` →
   `resetting`, no row → `not_started`); `start_answer` encodes
   `StartFailure::Project`.
3. **Tests:**
   - `temper-client-protocol-wire/src/tests.rs`:
     `playground_answer_round_trips_each_state` (each state; options
     none and at `u16::MAX`/`u32::MAX`; eight cues);
     `a_playground_answer_with_an_empty_cue_is_refused`;
     `start_failed_project_round_trips`.
   - `temper-service/src/tests/family.rs`, after the file's demo-read
     test (`to_root` with `Some(demo)`):
     `a_playground_read_answers_the_rows_state` (no `demo`: no record;
     `demo` with `playground: None`: `not_started`, no forge or
     project; a `Running` row with forge 4, project 7: `running`, 4,
     7; a `Resetting` row: `resetting`);
     `a_project_failure_encodes_start_failed_project`.
   - Narrow runs: `heavy cargo nextest run -p temper-client-protocol-wire
     --lib`; `-p temper-service --lib -E 'test(family::)'`; the drift
     test and `-E 'test(client_wire)'` in `temper-codecs-world`'s
     `suite`; `fuzzy` for the client wire's fuzzy test alone if it
     enumerates the reads.
4. `cargo fmt`; `heavy cargo clippy -p temper-client-protocol-wire -p
   temper-service --all-targets -- -D warnings` and each neighbour
   package you edited; focused tests of `temper-client-protocol-wire`
   and `temper-service`; `heavy cargo check --tests` for each of
   `temper-client-domain temper-client-view temper-client-tools
   temper-client-shell-cli temper-client-shell-web
   temper-client-shell-terminal temper-client-gallery temper-client-world
   temper-codecs-world temper-engine-domain temper
