## Goal

A request to delete a project crosses the client wire both ways, and
an owner's project document offers it (draft 5, "Its client: Delete on
the project's settings, confirmed by its name, for its owners"; the
confirmation is the view's, temper's Delete the playground designer's):
the wire's `Ask::RemoveProject`, `OwnerOutcome::ProjectRemoved` and
`ActKind::RemoveProject`; the engine's translations; the core's offered
act `acts::Act::RemoveProject`, the project's owners' alone; the
client's contract values and the link's translations. The engine still
refuses the request *not offered* until `pd-close`: this task carries
the words, not the decision.

Acceptance:

- the client wire carries the three values, appended to
  `client-v19.schema`/`client-v19-part1.schema` in place (no version
  move: as `235df29ae0` appended to them), its generated code and
  golden bytes regenerated by the drift test's write mode;
- jig-acts' "Translated from pd-wire on." arms are gone: the engine
  translates wire `RemoveProject` to `people::Ask::RemoveProject` and
  `people::Outcome::ProjectRemoved` to the wire's outcome;
- an owner's project document lists `RemoveProject` among its acts; a
  member's who is no owner does not (tests below);
- `jig_client_domain::contract::Ask::RemoveProject { project }`,
  `OwnerOutcome::ProjectRemoved { project }` and the client's
  `ActKind::RemoveProject` exist, and the link translates each both
  ways.

## Steps

1. Schema: `remove_project: RemoveProject` in `Ask` (record `RemoveProject
   { project: u32 }`), `project_removed: OwnerOutcomeProjectRemoved {
   project: u32 }` in `OwnerOutcome`, `remove_project` in `ActKind`,
   each appended last. Regenerate: `SKEIN_CODEGEN_WRITE=1 heavy cargo
   nextest run -p jig-client-wire-world --test suite -E
   'test(/drift/)'`.
2. Engine (`jig-protocol-engine-clients`): `translate/asks.rs` wire to
   people; `translate/answers.rs` the owner outcome; `translate/task.rs`
   `acts::Act::RemoveProject => w::ActKind::RemoveProject`; `llm.rs`,
   `request.rs` arms as `Rename`'s.
3. Core (`jig-domain-core/src/acts*`): `acts::Act::RemoveProject` ("delete
   the project whole"); `acts/requests.rs` maps `people::Ask::RemoveProject
   { project }` to `(Act::RemoveProject, Subject::Project { project })`;
   `acts/objects.rs` offers it on the project's owner document and admits
   it in `project_admission` iff the party's role in the project is
   `people::Role::Owner` (`core.people.role(party, project)`), never by a
   policy permission. `pd-close` admits the request through this same
   `project_admission`.
4. Client: the contract values; the link's `translate/asks.rs`,
   `translate/answers.rs`, `translate/documents_part2.rs` (and every
   other link arm the compiler names) both ways.
5. Tests:
   - `jig-client-wire-world` fuzzy and round trips cover the new values
     (the drift goldens; add the three to its fuzzy generators where the
     file lists each variant: `tests/suite/fuzzy/client_wire.rs`);
   - `jig-protocol-engine-clients` `src/tests/asks.rs` and
     `src/tests/answers.rs`: `remove_project_translates_both_ways`,
     `project_removed_is_an_owner_outcome`;
   - `jig-domain-core` `src/tests/` (beside the owner-document offer
     tests, e.g. `owner_project.rs`/`acts.rs`):
     `an_owner_is_offered_remove_project_and_a_member_is_not`;
   - `jig-client-protocol-link` `src/tests/projects.rs`:
     `remove_project_and_its_outcome_cross_the_link`.
6. Checks: `cargo fmt`; clippy on each package changed; focused tests
   of `jig-client-protocol-wire jig-client-wire-world
   jig-protocol-engine-clients jig-domain-core jig-client-domain
   jig-client-protocol-link`; `heavy cargo check --tests` for
   `jig-client-view jig-client jig-client-scripted-engine
   jig-client-world jig-client-protocol-world jig-engine-clients-world
   jig-core-world jig-ops-domain temper-client-domain temper-client-view
