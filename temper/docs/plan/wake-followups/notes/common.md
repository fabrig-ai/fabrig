# wake-followups: what every task holds to

- **Focused and fuzzy alone.** Never `tools/tiers/run`, a `<tier>-<tree>` profile,
  `scripts/browser.sh`, a walk, a render check or a throwaway driver. A story in a slow
  tier is written and compiled (`--no-run`), not run: say so in the report.
- **Tests stay cheap.** The gate rejects a plan that adds cost. A new case of one
  behaviour is a row of the existing table test the spec names; a new test is only one
  the spec sketches, in a world below the real loop. No test reaches a real host. The
  engine's domain world's focused suite (`temper-engine-domain-world`) is over its guide
  on main already; its owner knows, and no task moves or raises it: a task that adds to
  it reports the CPU time of what it added, beside a neighbour's, measured in one run.
- **The failing test first.** Write the spec's rows, run them, see them fail for the
  rule's reason, then build. The report quotes the failure seen.
- **A new test must bite** (the implementer's text): break the rule once by hand, see
  the row fail, restore.
- **The shapes are `temper/docs/plan/wake-followups/notes/contracts.md`'s,** where a spec
  cites it. A name, field, member or word it gives is spelled as it gives it. One it
  doesn't give is yours, inside your files.
- **No stored format or protocol changes but the one the contracts give.** The request
  answers one, a charter's stored policy in jig's refusal detail, in place, with no
  version bump (`contracts.md`, section 1). Any other change to a stored record, a
  journal, the client wire, a refusal vocabulary that crosses a wire, or a schema file is
  a `Question:` first.
- **Trees.** skein names none of smith, jig or temper; jig never names temper. A branch
  stays in its tree but where its spec says otherwise: a change to a shared type carries
  its readers' compiler-forced edits in the other trees, each edited only for that, as the
  spec lists them.
- **Generated files your change makes stale are yours,** regenerated by their own tool
  (`SKEIN_CODEGEN_WRITE=1` with the test that writes them; `temper/docs/help/reference/`
  by its tests), never by hand, and named in the report with what moved.
- **`docs/design/` stays closed** but for the status sentences a spec says to delete,
  as a stated departure from the implementer's text: the design is written, and its
  status must say what is built when the branch lands.
- **`temper/docs/design/draft/reference-code-production.md` stays unedited:** tests and
  stage one's judge read it.
- **Before calling a failure "outside the change",** run it once on the pristine base.
  If the base passes and your branch fails, it's yours.
