## What was decided

- **Emphasis in a draft has two causes,** and two tasks. skein's reader takes `*` alone, so `_Draft, with the user._`, which the stock instructions ask agents to write, stays literal; and temper's draft pane draws its first paragraph as plain text, past the reader. The first is skein's (`md-underscore`, released first, as it needs nothing); the second is `terminal-draft`'s. `_` follows CommonMark's rule within a word, so `snake_case` and `read_branch` stay as written; this cut wrote it in `skein/docs/design/ui.md`, 10. It changes how agents' words read wherever Markdown is drawn, the conversation's too, which the task's readers' tests check.
- **Three generic mechanisms go into skein first** (`AGENTS.md`, 1): the browser keeps no choice across tabs (its small store is the tab's session storage), nothing asks for full screen or holds Escape, and no key but Enter and Escape reaches a field's owner. `web-screen` gives the first two, written in `skein/docs/design/ui-web.md`, 10 and 11; `field-options` the third, written in `ui.md`, 3.2, and `ui-web.md`, 6 and 7. A field's options take no new act: Enter presses the active option and Tab's completion is the field's input, so temper's view binds them as it binds any item. PageUp and PageDown already scroll the log from a field.
- **Two skein-ui-web tasks at once,** against one writer per crate: `web-screen` owns its platform, store and a new `screen` module, `field-options` its mapping and page; no file and no interface is shared, so they run side by side.
- **The terminal is the chat page drawn otherwise,** in a browser alone: the same state, reads and acts, so no protocol changes (the request's *Commands are client actions*). The conversation keeps its nodes and tokens, which the terminal's rules restyle under `.temper-terminal`, rather than a second drawing of every line; its new parts (top line, running line, quiet line, list, notes) take tokens of their own. The request's selectors are re-selected onto temper's tokens, each named in the account. The design is `temper/docs/design/client/README.md`, 3.5, *A chat's terminal*, and `browser.md`, 2.5 and 7.2, written by this cut. `temper open`'s terminal client is untouched.
- **The look is one record for the browser,** `Look { terminal, theme, font }` on `Pages`, kept in skein's new kept store under `look`; theme and font are kept with the mode, since a person who chose light should not be given dark again by the next chat. Dark and DejaVu Sans Mono first. The page's Chat, Split and Draft mode stays page state, as it was; the terminal's "Draft" is Split.
- **Where the terminal draws:** `Chat`, `NewChat` and `Configure`, the three pages of a chat's layout, so `/new`, `/chats` and Start over stay in it; the frame drops the rail and the tab bar there. ">_" is on all three bars, which reprints `chat-draft`'s and `welcome-playground`'s pages; no recording goes stale.
- **The commands decide nothing new.** Each is the page's own act (`Act::Stop`, `Act::Close`, `Act::StartOver`, `Act::OpenStart`, `choice::Act::Model`, `Act::Go`); a confirmation of two acts draws as a list under the box. `/chats` reads the project's chats as `NewChat` already does; a goal's question is read from the inbox by the chat's subtree, as a tracked task's page reads its own, and only while the terminal draws, so no recorded journey's requests change.
- **Words the requests don't draw, decided here:** `/goal`'s "Start a goal from the draft", where "Start goal…" is offered (the request says another chat has `/goal` in `/start-over`'s place); a closed chat's note "This chat is closed. /new starts another."; "Answer in Needs you ›" for a question with no choices; the running line says the bar's status words and no clock, since no part of the client ticks by the second and the page's seconds are a mock's timer. Each is in the design.
- **Left out:** "All models" in the terminal's `/model` list (the browser's look keeps it), a reply to a question in the terminal (Needs you keeps it), and a seconds clock on the running line. The account names each.
- **Tests stay cheap:** one or two new table tests per temper task, named in its spec, and rows of existing tables; no browser story. The gallery gains nine `chat-terminal-*` states, the request's pages 02 to 06 and the states its messages name, so temper/ui's render check has pages to compare after landing.
- **One account per request,** in `terminal-close`'s four commits, written from what landed: each earlier task reports, rule by rule, what the account needs, and the close reads the requests and the code again.
- **Status:** each part's gap is one **Not yet** entry per temper status file, deleted by `terminal-close` as a whole, so that parallel tasks never edit one line; the skein tasks delete their own.

No stored format, protocol or public interface changes but these, each free under the request: skein-ui's new state `Options` (additive), skein-ui-web's `Platform` methods with defaults and its `screen` module, temper's client `Event` and `Request` variants and the shell's `Duties` fields, and a new kept-store record `look` of three bytes.
