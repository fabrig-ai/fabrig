## Goal

A worker that shuts down closes admission on its own side alone: the
engine can place a retry on its still-linked channel, the hub refuses it
busy, the fleet's busy mark lifts as a slot leaves the channel, and the
attempt pinned there is rechecked and journaled as a further attempt
refused (3 in 85 runs of temper's 4.6 cluster story, all under load).
The design now has the worker's hub say it drains, on its link, before
anything its cancelled runs send, and the fleet place nothing more on
that channel until it is lost. Build the notice end to end, and the
cluster story runs again.

Acceptance:

- **The hub** (`jig-domain-host`): `LinkUp::Draining`, a unit variant.
  On `Event::CancelAll { reason: Reason::Shutdown }` the hub pushes
  `Request::Up(LinkUp::Draining)` before anything the cancellation
  sends, and after each `Event::Opened` while `shut`, after that
  opening's own sends. Lib tests in `src/tests.rs`:
  `a_shutdown_says_draining_before_any_cancelled_runs_answer` (two runs
  hosted; the first `Up` is `Draining`, every run's answer after it) and
  `a_shutting_hub_says_draining_again_after_each_opening`.
- **The wire** (`jig-protocol-worker-wire`, still version 9): a record
  `Draining` with no field, its kind `0x010b`, `FromInitiator`, beside
  `ListRead`'s `0x010a`; `Kind::Draining` in `src/kinds.rs`, its row in
  `KINDS` and its arm in `schema`. The generated code and goldens are
  regenerated by the drift test, never by hand:
  `SKEIN_CODEGEN_WRITE=1 heavy cargo nextest run -p jig-worker-wire-world --test suite -E 'test(=drift::worker_wire_schema_matches_generated_code_and_goldens)'`,
  then the same without the variable, passing.
- **Both translations:** `jig-protocol-worker-link`'s `translate::up`
  frames `LinkUp::Draining` as the record, and
  `jig-protocol-engine-workers`' `translate::decode` gives it back as
  `LinkUp::Draining`; each crate's translate tests gain the round trip.
  The worker link sends it as it sends a notice (`src/component.rs`'s
  arm beside `Logins`).
- **The fleet** (`jig-domain-fleet`): `Event::Draining { channel: Token }`,
  from `jig-domain-hub-link`'s `payload.rs`, sets a mark on the channel
  that no slot's leaving clears (`attempt.rs`, `follow`, clears only the
  busy mark), and that goes with the channel when it is lost. Every
  placement predicate that skips `draining` skips it too (`channel.rs`'s
  `choose`, the constrained check and `choose_job`; `reads.rs`;
  `domain.rs`'s host views, whose `draining` reads true for either
  mark). An attempt the fleet chose for the channel and has not yet
  assigned is placed again as after a busy refusal, with no
  `Refusal::Recheck` for the drain (`jig/docs/design/domain/engine.md`,
  section 8). Lib tests in `src/tests.rs`, beside
  `a_busy_worker_takes_work_again_once_it_frees_a_slot`:
  - `a_draining_worker_takes_nothing_even_once_it_frees_a_slot`: a run
    and a job due, the worker draining with a slot freed: neither is
    placed there; another worker with a slot takes them.
  - `a_draining_workers_next_channel_is_placed_on`: the channel lost,
    the worker dials again, its logins answered: it takes work.
  - `a_chosen_attempt_on_a_draining_channel_is_placed_again_unrefused`:
    an attempt chosen for a channel and not yet assigned when it
    drains is placed on another worker, or waits, with no recheck
    refusal.
- `temper/crates/temper/tests/process.rs`,
  `a_restarted_workstation_keeps_the_directors_question_and_answers_it_once_as_processes_without_a_hang_past_the_grace`:
  no `#[ignore]`, and it passes run by name and alone in its profile
  (common notes), count 1:
  `heavy cargo nextest run -p temper --profile process-temper --test process -E 'test(=a_restarted_workstation_keeps_the_directors_question_and_answers_it_once_as_processes_without_a_hang_past_the_grace)'`.
  Its body doesn't change. Nothing else of `process-temper` runs. Its
  failure was 3 in 85 runs under load: one pass shows it runs, not that
  the race is gone; the fleet's tests above hold the rule.

  `jig-domain-fleet`, `jig-fleet-world`, `jig-host-world`,
