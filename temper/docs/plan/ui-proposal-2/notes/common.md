# ui-proposal-2: rules every task names

The request's own list holds: `temper/docs/plan/ui-proposal-2/inputs/request.md`, *For every task of this plan*. Read it. In short, and where this plan adds to it:

- **Focused and fuzzy alone.** No browser, process or live tier, no walk, no render check, no throwaway driver. No new browser test: the tier is over its cap. A browser story whose words change is updated and compiled (`heavy cargo check -p temper-client-browser-world --tests`), not run. This plan's survey found none.
- **Decide, don't ask.** A small edit a task needs just outside its list (a re-export, a `mod` line, a design line, a golden) is made and named in the report.
- **`temper.css`:** a new rule goes under its area's marker comment, `/* ==== ui: AREA ==== */`, never at the end of the file. A replaced rule changes where it stands.
- **Goldens, prints, the gallery's `names.txt` and `tests.rs`:** regenerate rather than hand-merge; keep `names.txt` sorted.
- **Generated files your change makes stale are yours,** regenerated by their tool.
- **A test's oracle your change's correct behaviour trips is yours to repair** in the same task, keeping what it checks for everything else, and named in the report.
- **Before calling a focused or fuzzy failure outside the change,** run it once on the pristine base.
