# ui-stop-coding-row: what every task holds to

- **The request binds:** `temper/docs/plan/ui-stop-coding-row/inputs/request.md`, all of it, *For every task of this plan* first. It wins over a spec where they differ.
- **The design this plan's cut wrote binds:** jig's `jig/docs/design/domain/engine.md`, 6.1, *Stopping* (the bullet on a run in the engine's own process) and section 6, step 3; `jig/docs/design/domain/tasks.md`, 5.2 (a claim interrupted by its engine's stop); `jig/docs/design/protocol/service.md`, 5, step 2 and *Runs in the engine*, and 10, *Starting and ending together*; temper's `temper/docs/design/protocol/README.md`, 8, *Starting and ending together*. In one line: on hearing it stops, the core settles each agent claim on a host in its own process as interrupted (`tasks::End::Recheck`: no try, no backoff, its committed turns, calls and saved work kept, the task due again), the fleet forgetting the attempt; a crash still leaves those claims to the next start, lost or not started.
- **Runs:** focused and fuzzy alone, each build and test through `heavy`, one command at a time. No `tools/tiers/run`, no `<tier>-<tree>` profile, no `scripts/browser.sh`, no walk, no render check, no throwaway driver.
- **Failing test first.** Each task's first commit holds its new or changed rows, failing on the trunk's code for the reason its spec names, before the fix. Then the bite (the implementer's text): the fix undone once by hand, the row failing for the rule's reason, restored. A task whose spec says its rows pass on arrival (they build on a fix already merged) does the bite instead, by undoing that fix locally.
- **Tests stay cheap.** A new case of one behaviour is a row of an existing table test (`skein/docs/foundation/testing-strategy.md`, 8); a new test is only one your spec allows. temper's and jig's focused and fuzzy suites stand over their budgets already (`temper/docs/development/limits-worlds.md`): name each new or changed row's CPU time alone in the report, and keep its story the shortest that shows the rule. No deadline widens, no limit or grace changes, and no story is skipped or ignored.
- **One tree per branch.** A jig branch edits nothing in temper, a temper branch nothing in jig, skein or smith. A cause your spec doesn't name in another tree is a `Question:`, with the evidence and the fix you'd make there.
- **`docs/design/` stays closed** but for the status entries your spec names.
- **Logs:** filter every line holding `secret=` from anything you quote, commit or put in a report. A log is read by `grep` and `tail` around what you need, never whole.
- **A test's oracle or helper that your change's correct behaviour trips is yours to repair,** keeping what it checks for everything else, and named in the report.
- **Before calling a focused or fuzzy failure "outside the change",** run it once on the pristine base. If the base passes and your branch fails, it's yours.
- **Before pushing:** `cargo fmt`; `python3 -I -B <tree>/scripts/old_forms.py` for each tree you touched; `python3 -I -B tools/citations/citations.py --base origin/main`.
