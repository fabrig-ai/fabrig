# look-outside-pages: what every task holds to

- **Every commit carries the trailer `Look-request: outside-pages`,** directly above the
  other trailers (`temper/docs/design/draft/look-requests.md`, 3 and 5), a fix of what an
  earlier commit missed included. A commit without it hides the work from
  `temper/scripts/look-refresh.sh`; amend it before you push.
- **The request is the spec's picture.** It is the commit `43a18a5042` (on
  `origin/look-requests`): read its message with `git show -s 43a18a5042`, a page with
  `git show 43a18a5042:temper/docs/design/client/journeys/outside-pages/0N.html`, its
  stylesheet for the server's pages with `git show
  43a18a5042:temper/docs/design/client/journeys/outside-pages/pages.css` and its rules
  with `git show 43a18a5042 -- temper/docs/design/client/journeys/overlay.css`. Its pages
  are hand-made, values written in by hand: a test draws the same roles, names, words and
  looks from fixture values, never the pages' bytes. Never edit the request's files or
  `temper/docs/design/client/journeys/overlay.css`, and never touch the `look-requests`
  branch.
- **The plan's own rules** are `temper/docs/plan/look-outside-pages/inputs/request.md`,
  *For every task of this plan*: read them; they hold for every task.
- **Focused and fuzzy alone.** Never `tools/tiers/run`, a `<tier>-<tree>` profile,
  `scripts/browser.sh`, a walk, a render check, a screenshot or a throwaway driver. A
  story in a slow tier (browser, process, live: `temper/tests/client-browser`,
  `temper/tests/one-process`, `temper/tests/real-loop`, `temper/tests/system`,
  `temper/crates/temper/tests`) is written and compiled (`heavy cargo check -p PKG
  --tests`), not run: say so in the report. `temper-client-journeys again` is
  generation, not a walk: the task that names it runs it (retry up to three times on "a
  key mark caught a moving page", each on a fresh fake box; if all fail, widen the
  mark's wait in the recording driver and say so).
- **Tests stay cheap.** A new case of one behaviour is a row of the existing table test
  the spec names; a new test is only one the spec sketches, beside its siblings'
  fixture. A browser case is a row of an existing table test, within its cap of 12.
- **A new test must bite** (the implementer's text): break the rule once by hand, see it
  fail, restore; the report names the rule and the failure seen.
- **The shapes are `temper/docs/plan/look-outside-pages/notes/contracts.md`'s.** A name,
  token, word, tree shape or markup it gives is spelled as it gives it. One it doesn't
  give is yours, inside your files.
- **`temper.css`:** this plan's rules go under its marker comment
  `/* ==== ui: outside ==== */` (the task `outside-frame` puts it just above
  `/* ==== ui: public ==== */`), never at the end of the file. A rule the change replaces
  is removed where it stands only by the task that the spec says removes it.
- **No compatibility before v0.1.0.** A stored format, a protocol or a public interface
  may change; a spec that changes one says so, and the report names it.
- **Generated files your change makes stale are yours,** regenerated by their own tool,
  never by hand, and named in the report with what moved: the journeys' prints by
  `temper-client-journeys` (`temper/docs/design/client/journeys.md`, 8), the terminal
  shell's goldens by their test's write mode where it has one, `docs/help/reference/*`.
  On a catch-up, regenerate rather than hand-merge; keep the gallery's `names.txt` sorted
  as it is.
- **A test's oracle or helper your change's correct behaviour trips is yours to repair**
  in the same task, keeping what it checks for everything else, and named in the report.
- **Before calling a focused or fuzzy failure "outside the change",** run it once on the
  pristine base. If the base passes and your branch fails, it's yours.
- **Builds set `TEMPER_BUNDLE=none`.**
- **The account.** Your report ends with `## Account`: one row per item of the request
  your task lands (an overlay rule's selector, a page change, a state the message names),
  each `landed`, `differs` and why, or `deferred` and to whom. The plan's last task
  gathers them into the landing's account (`look-requests.md`, 5).
