# The client reads the deployment's fact, and the welcome waits for it

## Goal

The domain reads the deployment's read (contracts K5) and the welcome's decision and the
playground's offer wait for it, both shells alike. Every test world answers `welcome: true, owned:
true`, so nothing a person sees changes yet. Later tasks act on `Some(false)`.

Acceptance:

- `forge::deployment` and `Side::deployment` are K5's; the read goes out with a link's first live,
  and again after each gap; none is sent at any other time; a test of each in
  `temper-client-domain/src/tests/deployment.rs`: `the_read_goes_out_once_a_link_is_live`,
  `the_answer_is_kept_across_a_gap_and_a_read_with_no_record`,
  `a_read_that_ends_with_no_record_reads_as_no_welcome`.
- `pages::welcome::decision` returns `None` until `root.forge().deployment()` is `Some`.
- `pages::welcome::playground_offered` returns `None` until then, and `Some(false)` with no welcome.
- The world answers of K5 exist and are used: `temper-client-view`'s `deliver_deployment`, the
  domain's, `Joint.deployment`, the terminal's chat fixture and the gallery's worlds.
- Story A's log regenerated by its writer, and both replays pass (`notes/common.md`).
- `heavy cargo nextest run -p temper-client-domain -p temper-client-view -p
  temper-client-shell-terminal -p temper-client-world -p temper-client-gallery -p
  temper-playground-world -p temper-one-process-world` pass.
