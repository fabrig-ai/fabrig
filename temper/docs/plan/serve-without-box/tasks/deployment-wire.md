# The deployment's read on the client wire

## Goal

The wire carries the deployment's read (contracts K2): `Reading`'s `deployment`, answered by the
versioned record `DeploymentAnswer`. No side serves or sends it yet; `deployment-read` and
`client-reads-deployment` build on this surface.

Acceptance:

- The schema holds K2's two lines; `generated/v1.rs` and the goldens are regenerated by the writer
  (`notes/common.md`), `CLIENT_VERSION` still 11, the family's header still 11.
- `wire::deployment_answer` and `wire::decode_deployment_answer` exist (K2), a `decode` refusing
  trailing bytes as `decode_playground_answer` does.
- A test in `temper-client-protocol-wire/src/tests.rs`, `deployment_read_and_answer_round_trip`,
  round-trips a `Reading { read: Read::Deployment }` and `DeploymentAnswer` at `welcome` `true`
  and `false`, and refuses an answer with a trailing byte.
- `heavy cargo nextest run -p temper-client-protocol-wire` and `-p temper-codecs-world` pass;
  `heavy cargo check -p temper-service --tests` and `-p temper-client-domain --tests` pass.
