# look-round-25: what every task follows

- **The request binds:** `temper/docs/plan/look-round-25/inputs/request.md`, all of it, *For every task of this plan* first. It wins over a spec where they differ.
- **The target** is the whole story's mockups on main: `temper/docs/design/client/web/whole-story/how.html` with its `README.md` (and `pair/how.html`, `team/how.html` for the other ways' Roles), and, for Ask temper's ways, the look request `ask-temper-ways` (`git show 98322b3565`, its pages under `temper/docs/design/client/journeys/ask-temper-ways/` and `temper/docs/design/client/journeys/overlay.css` at that commit; read with `git show COMMIT:PATH`, never from `origin/look-requests`' tip, and leave that branch alone). Where a draft and a page disagree on a mechanism, the draft wins (`stock-ways.md`, 4; `surfaces.md`, 7 and 13).
- **Draw what the engine holds** (`temper/docs/design/draft/whole-story.execution.md`, section 2): words saved with a setting (P3e) and a goal's "design" and "close-out" stops (P3f) are milestones of their own. Nothing is drawn by hand, as a placeholder or a made-up value.
- **The design this plan follows,** written by this cut, is cited by each spec's *Inputs*. Each task deletes the **Not yet** entries naming it and `look-round-25` in the status files its spec names, and edits no other design text: that departs from the implementer's text, which closes `docs/design/`.
- **The account** (`temper/docs/design/draft/look-requests.md`, 5): each task's last commit carries a table `| Item | Result |`, one row per item its spec gives it: landed and where, differs and why, or deferred and to whom; its last row the render check's, which follows landing, owned by temper/ui, since compiling, prints and focused tests establish no rendered equality.
- **Runs:** focused and fuzzy alone, each build and test through `heavy`, one command at a time. No `tools/tiers/run`, no `<tier>-<tree>` profile, no `scripts/browser.sh`, no browser story run, no walk, no render check, no screenshot, no throwaway driver. A slow-tier crate a task touches is compiled alone (`heavy cargo check -p PKG --tests`).
- **Prints:** a task that changes the view's markup or a drawing reprints the journeys whose pages change (`heavy cargo run -p temper-client-journeys`, no arguments, reprints the saved recordings; a recording it reports stale is recorded again with `again NAME`, the request's retries holding) and runs `heavy cargo nextest run -p temper-client-journeys`. Today only `chat-draft`'s `01.html` and `02.html` show How work runs. A task that changes a stylesheet alone reprints nothing: the prints link `temper.css` by path. The terminal's goldens are regenerated by their own tests' tool, never by hand. The gallery's print is made by its tests into a scratch directory and never committed.
- **Tests stay cheap:** no new test function but where a spec names one; each case is a row or an assertion of an existing test, named in its spec. The gallery's tests are over their budget already (`temper/docs/design/client/browser.status.md`, 7.3): add no state and no test to them, only what a spec names.
- **Shared registries in `temper-client-view`:**
  - `look.rs`'s `NAMES` is positional, a token its index: a name that goes keeps its slot, renamed `temper-reserved-N` (N its token), its constant deleted; a new name is appended at the end, with its constant, by the one task of this plan that appends (`path-marks`), or takes a reserved slot its spec names.
  - `words.rs`: this plan's new keys are 5100 to 5149, `path-marks` 5100 to 5119 and `roles-page` 5120 to 5149; a word that goes is deleted with its key.
  - `temper.css`: the path's drawing rules stay where they stand (the `ask-temper-ways` block under `ui: chats`), the ways' tabs, card, legend and acts where theirs stand (under `ui: settings`), How work runs' under `ui: how`. Never at the end of the file. Replaced rules are removed where they stand.
- **A stored format, a protocol or a public interface** may change freely, with no compatibility and no family version: a wire or store schema change regenerates its generated code and goldens by their own tool, and names them in the report.
- **Before pushing:** `cargo fmt`; `python3 -I -B <tree>/scripts/old_forms.py` for each tree the branch touches; `python3 -I -B tools/citations/citations.py --base origin/main` (it reads committed work: commit first); clippy as the implementer's text says, naming every package changed.
- **Leave alone:** `origin/look-requests`; the drafts (`temper/docs/design/draft/*.md` and their status files) but where a spec names a status entry; the mockups (`temper/docs/design/client/web/whole-story/**`); `docs/help/` but where a spec names a page; `temper/docs/design/client/journeys/overlay.css`.
