# The ways' wire: a longer fact, a gate's charter, a rule's view

## Goal

The surface the request's tasks 5 and 6 build on (`temper/docs/plan/look-round-24/inputs/request.md`): a fact's value may be 184 bytes on the wire, so that an agent's "Asked to" holds its first sentence; a gate's stop names its reviews' charter, so that "Open the reviewer ›" can open the reviewer's role; and a view may be a landing rule's card. This task changes the shapes alone: the engine still makes every value at most 128 bytes (`asked-sentence` lengthens "Asked to"), and nothing makes a `rule` view yet (`rule-view` does).

Acceptance, by `temper/docs/design/client/README.md`, 4.6, *A path* and *A view*, and `temper/docs/design/domain/forge.md`, 8.13, *A stop's card* (a review's stop names its gate's charter), as this cut wrote them, and `temper/docs/plan/look-round-24/notes/contracts.md`, *The wire* and *The engine*:

1. **The schema:** `Fact.value` `text 184`; `OpensGate { number: u32 charter: u32 }`; a new `record RuleView { kind: u32 number: u32 card: Card }` beside `CharterView`; `View` gains `rule: RuleView` after `charter`. Nothing else. The generated `src/generated/v1.rs` and the goldens are regenerated by the drift test with `SKEIN_CODEGEN_WRITE=1` (the note's command), never by hand; then the same test runs without it and passes.
2. **The engine's shapes** (`temper-engine-domain-ways`): `Opens::Gate { number, charter }` in place of `Opens::Gate(u32)`; `derive.rs`'s review stop sets `charter` to the charter whose card it draws (`agent_card(inputs, charter, &who, name)`, about line 103); `View::Rule { kind: u32, number: u32, card: Card }` after `Charter`; `pub const ASKED: usize = 184;` beside `VALUE`, with its comment, used by nothing yet but its export (`lib.rs` re-exports the path's constants as it does `VALUE`; follow it).
3. **The service** (`temper-service/src/family/ways.rs`): `Opens::Gate { number, charter }` maps to `w::OpensGate { number, charter }`, `View::Rule` to `w::View::Rule(w::RuleView { kind, number, card })` as `Charter` maps to `CharterView` (about line 78).
4. **Compiler-forced arms,** each edited for the new shape alone, in any file of temper's tree: the engine's matches on `Opens::Gate(_)` (`temper-engine-domain/src/route/ways/view/charter.rs`, about line 17: `Opens::Gate { .. }`) and `View` (`route/ways/view.rs`); the client's matches on `w::View` (`temper-client-domain/src/pages/chat/views.rs` and its tests, `temper-client-view/src/views.rs`: a `rule` view draws its card exactly as a `charter` view does, `who`, `name` and `facts`, through the same function); `w::Opens::Gate` in `temper-client-view/src/pages/ask_page.rs` and its tests (no change of behaviour: the link still goes to Settings until `role-links`); the gallery's worlds (`temper/tools/gallery/src/worlds/ways.rs`, `worlds/views.rs`: a gate's `charter` is the world's reviewer, 4) and the engine's world (`temper/tests/engine/domain/tests/suite/ways.rs`). A literal's new field takes the value the code beside it already knows; name each file in the report.
5. **The rows, no new test function:** the drift test passes; `temper-client-protocol-wire`'s own tests pass as regenerated (`src/tests.rs`); `cards_open_the_setting_and_stay_within_the_bounds` (`temper-engine-domain-ways/src/tests/derivation.rs`, about line 405) asserts the review stop's `Opens::Gate { number, charter }` with the reviewer's charter, where it asserts the gate today; the client view's `views.rs` test table (`temper-client-view/src/tests/views.rs`, the charter view's row, about line 254) gains a `rule` row drawing a card with `who` "a landing rule · holds a merge until it is met", `name` "the project's rule 1" and one fact, ("Covers", "every branch").
