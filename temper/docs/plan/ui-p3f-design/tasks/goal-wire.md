# `TemplateGoal` and the path's two new steps, on the wire and in the store

## Goal

The client wire and the store learn the shapes this plan's other tasks build on:
the client wire's `PathStep` gains `design` and `close_out`, both schemas gain a
`TemplateGoal` record, and the store's `SettingValue` gains `goal`. Nothing fills
them yet: no derivation draws the steps and no forge value is a `TemplateGoal`
until `goal-path` and `goal-value`.

Acceptance:

1. **The schemas,** exactly `temper/docs/plan/ui-p3f-design/notes/contracts.md`,
   section 2: `PathStep`'s two steps appended, every earlier tag kept;
   `record TemplateGoal { design: bool close_out: bool }` on the line right after
   `record ForgeCharter { charter: u32 }` in the client wire's schema and right
   after `record CharterValue { number: u32 }` in the store's; `SettingValue`'s
   `goal: TemplateGoal` last. Placed exactly there, so that the two plans adding
   kinds beside this one (`notes/common.md`, *Beside this plan*) merge with it.
2. **Generated** Rust and goldens of both schemas regenerated by the codecs
   world's drift test (`notes/common.md`, *Generated files*), never by hand; the
   drift test then passes without writing.
3. **The store's codec** (`temper/crates/temper-protocol-store/src/records/settings.rs`,
   the setting row's decode): `w::SettingValue::Goal(_)` answers `Undecodable`, a
   stand-in `goal-value` replaces; the encode side has no forge value to write
   yet. Any other `match` the new variants force, in any crate of temper's tree,
   takes the arm its neighbours' nearest case takes, and is named in the report.
4. **Status:** delete the bullets naming `goal-wire` in
   `temper/docs/design/client/README.status.md` (4.6) and
   `temper/docs/design/protocol/store.status.md` (2) (`notes/common.md`, *Status
   files*).
