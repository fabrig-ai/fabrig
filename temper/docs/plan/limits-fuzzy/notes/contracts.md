# limits-fuzzy: the state's `Hash`, which crosses tasks

The binding calls `state-hash` and `engine-sweeps` build to. `skein/docs/design/lib.md`, 5.1, says a state is digested through its types' derived `Hash`, and a service's state types derive it as they derive `Debug`; `skein/docs/foundation/testing-strategy.md`, 6, says a seed replays to the same digest. `temper/docs/design/domain/testing.status.md` lists this as not yet built.

## The calls

- **Each type below derives `Hash`.** Add the one word to its existing `#[derive(..)]`, just before `Debug`. Nothing else on the line or near it changes. `cargo fmt` may wrap a line. No imports: the derive macro is in the prelude.
- **No hand-written `Hash` in `skein`, `jig` or `temper` crates.** The survey below found no reachable type that needs one: no `f32`, `f64`, closure, `fn` pointer, `dyn`, `Rc`, `RefCell` or raw pointer, and no hand-written `PartialEq` on a type that needs a new derive (`clippy::derived_hash_with_manual_eq`).
- **`skein_lib::Env<L>` derives `Hash`,** with the derive's own `L: Hash` bound. `Slot`, in `skein/crates/skein-lib/src/slab.rs`, needs none: `Slab`'s hand-written `Hash` covers it. `skein_lib::Writer` takes it only if the compiler asks: the survey reached it, and may have done so through the branch this plan leaves out.
- **The world's test `Store` has a hand-written `Hash` over the four fields its `Debug` prints:** `applied`, `rows`, `pending` and `held`. That's what's compared today, no more and no less, and its comment says so, as 5.1 allows. So these aren't reached, and take no derive for this plan: `jig-protocol-store`, `skein-codec`, `skein-kv`, `skein-io`, `temper-protocol-store`, `temper-service`, `jig-test-store-files` (158 sites), and the world's `Delayed`. No domain crate depends on any of them: `Cargo.toml` shows it.
- **The compare is the world's,** in `temper/tests/engine/domain/src/replay.rs` (`tasks/engine-sweeps.md`).

## How this list was made

A read-only survey computed it, by field, from the declarations at the plan's base. Nothing was compiled. **The compiler has the last word:** a type it asks for that isn't listed takes the same one word, in whichever tree, and your report names it. A listed type it never asks for may stay as it is, and your report says so.

## What `Hash` and `Debug` don't agree on

Comparing digests isn't the same as comparing text. These are the differences the survey read:

| Type | `Debug` prints, `Hash` leaves out | `Hash` covers, `Debug` leaves out |
|---|---|---|
| `List`, `Map`, `Set`, `Queue` | `capacity` | |
| `Slab` | `capacity`, `len` | |
| `Deadlines` | `by_key` (it hashes `by_time`) | |
| `Journal` | `release`, its queues' capacities | |
| `Buffer` | capacity | its bytes |
| `Secret` | | its bytes, beyond its length |
| The test `Store` | | nothing: by the call above, the two agree |

5.1 has each of lib's types hash what its later answers depend on. As read, a capacity and `release` are set at construction with no setter, from limits both worlds share, and a `len` and `by_key` follow from what is hashed. So the left column can't differ while the digests agree, and each settled seed still ends on one comparison of the complete text (`tasks/engine-sweeps.md`), which would show it if it did. `engine-sweeps` checks that reading against the code and says so.
