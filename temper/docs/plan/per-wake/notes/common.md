# per-wake: what every task holds to

- **Focused and fuzzy alone.** Never `tools/tiers/run`, a `<tier>-<tree>` profile,
  `scripts/browser.sh`, a walk, a render check or a throwaway driver. A story in a slow
  tier is written and compiled (`--no-run`), not run: say so in the report.
- **Tests stay cheap.** The focused and fuzzy limits are being tightened, and the gate
  rejects a plan that adds cost. A new case of one behaviour is a row of the existing
  table test the spec names; a new test is only one the spec sketches, in a world below
  the real loop. No test reaches a real host.
- **The failing test first.** Write the spec's rows, run them, see them fail for the
  rule's reason, then build. The report quotes the failure seen.
- **A new test must bite** (the implementer's text): break the rule once by hand, see
  the row fail, restore.
- **The shapes are `temper/docs/plan/per-wake/notes/contracts.md`'s.** A name, field or
  signature it gives is spelled as it gives it. One it doesn't give is yours, inside your
  files.
- **jig never names temper.** A jig change carries no temper word
  (`tests/boundary/tests/outward.rs`). A temper file is edited only where the spec says,
  and only in the field's name, type path or value (a `parts: Box::new([])`, a
  `later: None`).
- **Formats change in place.** This plan changes jig's settings, tasks and people
  families and the client wire 19 in place, as `contracts.md`, section 6 and 8 give them;
  versions stay. Any other stored format or protocol change, a new refusal variant
  among them, is a `Question:` first.
- **Generated files your change makes stale are yours,** regenerated by their own tool
  (`SKEIN_CODEGEN_WRITE=1` with `jig/tests/codec-families.rs`'s drift tests, the store's
  layout drift writer), never by hand, and named in the report with what moved.
- **Memory pins that move** only because a type you touched grew are updated where they
  are pinned, each named in the report with its old and new value.
- **`docs/design/` stays closed** but for the status sentences a spec says to delete,
  as a stated departure from the implementer's text: the design is written, and its
  status must say what is built when the branch lands.
- **A chat keeps one choice.** Nothing here changes what a chat does: a chat's picker
  writes its task's whole LLM choice, which carries no `later`.
- **Before calling a failure "outside the change",** run it once on the pristine base.
  If the base passes and your branch fails, it's yours.
