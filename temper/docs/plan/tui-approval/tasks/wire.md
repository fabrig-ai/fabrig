## Goal

jig's client wire carries a sign-in approved by a browser: the eleven records of `temper/docs/plan/tui-approval/notes/contracts.md`, 2.1, added to `jig-client-wire 19` in place, and the approval's code, `ApprovalCode` (2.2), in a hand-written module of the wire crate that both ends and temper's codec use.

Acceptance:

- The schema holds 2.1's records, in its order, after `SignOutAnswer`; `src/generated/v19.rs` and `golden/` are regenerated by the family checker, never by hand; the drift tests pass.
- `jig_client_protocol_wire::ApprovalCode` and the constants of 2.2 exist, with their table test.
- `ApprovalAsked`'s and `ApprovalSignIn`'s `Debug` show the secret's length, never its bytes (a canary test, as `link_sign_in.rs`'s).
- The client wire's fuzzy decoder list checks the new records.
- No existing record, enum or variant changes: nothing outside this crate and its world needs an edit.

## Steps

1. **The schema.** Add 2.1's records to `schema/client-v19.schema` right after `enum SignOutAnswer { .. }`, exactly as written there. Regenerate:

   ```sh
   TEMPER_BUNDLE=none SKEIN_CODEGEN_WRITE=1 heavy cargo nextest run -p jig-client-wire-world -p jig-store-codecs-world -E 'test(drift::)'
   ```

   then the same without `SKEIN_CODEGEN_WRITE=1`, which must pass. Only the client family's files should change; a store family's change is a red.
2. **The code, `src/approval.rs`,** step code under the crate's lints, as 2.2 sketches:

   ```rust
   //! An approval's code (jig/docs/design/protocol/client.md, 8).
   pub const CODE_ALPHABET: [u8; 20] = *b"BCDFGHJKLMNPQRSTVWXZ";
   pub const CODE_LETTERS: usize = 8;
   pub const CODE_TYPED_BYTES: usize = 32;
   #[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
   pub struct ApprovalCode([u8; 8]);
   impl ApprovalCode {
       pub fn parse(bytes: &[u8]) -> Option<Self>;
       pub fn from_indexes(indexes: [u8; 8]) -> Option<Self>;
       pub const fn letters(&self) -> &[u8; 8];
       pub fn shown(&self) -> [u8; 9];
   }
   ```

   `parse` reads at most `CODE_TYPED_BYTES` bytes (longer is none), skips `-` and ` ` wherever they are, upper-cases ASCII letters, and wants exactly eight letters, each in `CODE_ALPHABET`. `shown` is the four first letters, `-`, the four last. Export them from `lib.rs`: `pub use approval::{ApprovalCode, CODE_ALPHABET, CODE_LETTERS, CODE_TYPED_BYTES};`.
3. **Tests, in `src/tests/approval.rs`:**
   - `an_approval_code_reads_typed_and_carried_forms`, one table, rows `(&[u8], Option<&[u8; 8]>)`: `WDJB-MJHT`, `WDJBMJHT`, `wdjb mjht`, ` WDJB - MJHT `, each to `WDJBMJHT`; seven letters, nine letters, a vowel (`WDJA-MJHT`), a digit, a letter off the alphabet (`Y`), any other byte (`WDJB_MJHT`), and 33 bytes of hyphens around a good code, each none.
   - `an_approval_code_is_shown_as_four_a_hyphen_and_four`: `shown()` of a parsed code, and `parse(&code.shown())` gives it back, for every row that reads.
   - `from_indexes_takes_the_alphabet_and_refuses_past_it`: indexes `[0; 8]` give `BBBBBBBB`, `[19; 8]` `ZZZZZZZZ`, any index 20 none.
   - `debug_of_an_approval_shows_the_secrets_length_never_its_bytes`, beside `link_sign_in.rs`'s, as its form: an `ApprovalAsked` decoded from bytes holding a 32-byte canary secret, and an `ApprovalSignIn` holding a 13-byte one, each `{:?}` and `{:#?}` free of the canary's text and its byte list, and the round trip exact.

   Break each rule once by hand (drop the vowel check; show without the hyphen; give `Secret`'s field as bytes in a scratch `Debug`) and see its test fail, then restore.
4. **The fuzzy list:** a `check!` line for each new record and enum in `jig/tests/client-wire/tests/suite/fuzzy/client_wire.rs`, beside `LinkSignIn`'s.
5. `cargo fmt`; `heavy cargo clippy -p jig-client-protocol-wire -p jig-client-wire-world --all-targets -- -D warnings`; `heavy cargo nextest run -p jig-client-protocol-wire` and `-p jig-client-wire-world`. Its direct dependents compile unchanged, since nothing existing changes: check `heavy cargo check -p jig-protocol-engine-clients -p jig-client-protocol-link --tests` once.
6. Commit (the schema and its regenerated files in one commit, the code and its tests in another) and push.
