# ui-forge-setup: what every task holds to

- **Focused and fuzzy alone.** Never `tools/tiers/run`, a `<tier>-<tree>` profile, a browser, a walk, a render check or a live run. `github-conformance`'s new case runs on its fake (`--fake`, or its lib tests); its live side is written and compiled, not run: say so in the report.
- **Tests stay cheap.** A new case of one behaviour is a row of an existing table test, and skein's budgets apply (`skein/docs/foundation/testing-strategy.md`, 8). Each spec names the tables; a new test is only one the spec sketches.
- **Skein names no product.** Nothing in skein names temper, a box or a system: `person`, `the owner`, `the App's account` are its words (`tests/boundary/tests/outward.rs`).
- **Decide, don't ask.** A stored format or a public interface here may change in place, with no compatibility and no version bump, before v0.1.0. A small edit just outside your list (a re-export, a `mod` line, a golden) is made and named in the report.
- **Generated files your change makes stale are yours,** regenerated by their own tool: temper's codecs and goldens by `SKEIN_CODEGEN_WRITE=1 heavy cargo nextest run -p temper-codecs-world --test suite -E 'test(drift::)'`, the command the drift test itself prints.
- **`docs/design/` stays closed** but for what your spec lists: the design is already written, and each spec names the status entries it removes.
- **`temper/crates/temper-service/src/startup/checks.rs` is left alone.** `AppMade` encodes as `AppId` does, so its row for `User` and `AppId` still bounds it, and two other drafts are changing that file.
- **Before calling a failure "outside the change",** run it once on the pristine base. If the base passes and your branch fails, it's yours.
