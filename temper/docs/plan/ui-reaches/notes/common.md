# ui-reaches: what every task follows

- **The request binds:** `temper/docs/plan/ui-reaches/inputs/request.md`, all of it, *For every task of this plan* first. It wins over a spec where they differ. The draft is `temper/docs/design/draft/what-reaches-you.md`, sections 2 to 6; its design is the sections each spec's *Inputs* names, written by this cut. Nothing in the draft is reopened.
- **The contracts** that cross tasks are `temper/docs/plan/ui-reaches/notes/contracts.md`: names, types, signatures and records there bind every task that touches them. A task that finds one wrong stops and asks; it never builds a second shape.
- **Design and status:** each task deletes the **Not yet** entries naming it in the status files its spec names, and edits no other design text unless its spec says so. That departs from the implementer's text, which closes `docs/design/`.
- **Runs:** focused and fuzzy alone, each build and test through `heavy`, one command at a time. No `tools/tiers/run`, no `<tier>-<tree>` profile, no `scripts/browser.sh`, no browser, process or live story run, no walk, no render check, no screenshot, no throwaway driver. A slow-tier crate a task touches is compiled alone (`heavy cargo check -p PKG --tests`).
- **Generated files:** the client wire's and the store's generated Rust and goldens come from their schemas by the codecs world's drift test, filtered to the one the task changed: `TEMPER_BUNDLE=none SKEIN_CODEGEN_WRITE=1 heavy cargo nextest run -p temper-codecs-world --test suite -E 'test(drift::)'`, then the same without `SKEIN_CODEGEN_WRITE`. Never edit `generated/*.rs` or a golden by hand. `docs/help/reference/*` pages come from their tests with `SKEIN_CODEGEN_WRITE=1` (`temper/crates/temper/src/tests/commands.rs`, `temper/crates/temper/src/tests/settings_fields.rs`, `temper/crates/temper-client-tools/src/tests/help.rs`).
- **Schema writers go one at a time:** `client-wire-v1.schema` and `store-v11.schema` are edited by `reach-wire`, then `decide-forge`, then `keep-asking`, then `ways-away`, each after the one before has merged (their `needs` say so); no other task of this plan edits them.
- **Tests stay cheap:** a new case of one behaviour is a row of an existing table test, not a new test; a new story goes beside its siblings' fixture. temper's focused and fuzzy suites go to 30 and 120 CPU seconds in the gate; a fuzz test sweeps 64 seeds, as `temper/crates/temper-engine-domain-ways/src/tests/fuzzy.rs` does.
- **The strict subset** holds in step crates (`AGENTS.md`, 2): no `std`, every `match` lists every variant, no indexing, no unchecked arithmetic, no `as`, no `unwrap`; a lint exception is a scoped `#[expect(..., reason = "...")]`.
- **Before pushing:** `cargo fmt`; `python3 -I -B temper/scripts/old_forms.py`; `python3 -I -B tools/citations/citations.py --base origin/main` after committing (it reads `HEAD`); clippy as the implementer's text says, naming every package changed.
- **Leave alone:** the drafts (`temper/docs/design/draft/*.md` and their status files); `docs/help/` but what a spec names or a bound forces; the TUI's crates (`temper-client-tui`, `temper-client-shell-tui`), which temper/tui owns; jig, smith and skein.
