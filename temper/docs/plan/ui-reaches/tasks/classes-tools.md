# `project-classes` in `temper ctl settings` and settings files

## Goal

A person reads and sets a project's classes from the terminal as they do its ways and questions: `temper ctl settings show project-classes PROJECT`, the value stored or the stock's marked so, and a settings file's `{"kind": "project-classes", "project": P}` with the JSON value `temper/docs/design/client/tools.md`, 5.3 gives. The help pages say what kind 8 is.

Acceptance, by `temper/docs/design/client/tools.md`, 5.2 (`settings show project-classes`) and 5.3 (a settings file's SETTING and VALUE for a project's classes), and `temper/docs/design/domain/forge.md`, 5.10 (the table's names and bounds):

1. **`settings show`** (`temper-client-tools/src/settings.rs`, `settings/value.rs`): `project-classes PROJECT [--revision REVISION]` beside `project-ways` and `project-questions`, its word mapped to kind 8; the value decoded by `temper_protocol_reaches::classes_from`, the stock's (`Classes::stock(Way::AgentsReview)`) with none stored, marked so as theirs are; printed in words and, with `--json`, as the file's VALUE.
2. **The settings file** (`temper-settings-form`): the SETTING `{"kind": "project-classes", "project": P}` (a project required, no number); VALUE `{"items": [...], "sets": [...]}`, each item `{"kind": KIND, "words": TEXT, "class": CLASS}` or `{"set": N, "words": TEXT, "class": CLASS}`, `words` optional and empty by default, KIND `Kind::name`'s, CLASS `"decide"`, `"ask"` or `"ask-away"`, each set `{"number": N, "name": TEXT, "patterns": [TEXT, ...]}`; decoded bounded and refused, naming the field, where a member is unknown or a value past its bound, and as `Classes::check` refuses, its refusal in words; rendered back to the same JSON, so that `show --json` round-trips through a file. Its shape, choice, fields and descriptions in the form's tables (`fields.rs`, `fields/jig.rs`, `fields/render.rs`, `render.rs`, `kinds.rs`, `file.rs`) as kind 7's are.
3. **The help:** `temper/docs/help/settings.md` names `project-classes` where it names the project settings (its names, its command forms, the kinds an agent proposes); `temper/docs/help/project.md` says in a short paragraph what a project's classes are: agents decide and tell you, ask you, ask you even when away, and four kinds that always wait, set by the project's way and changed as any setting. Each page within its byte bound (the request's *Help pages*). `temper/docs/help/reference/settings-fields.md` and `ctl-settings.md` regenerated by their tests (`notes/common.md`, *Generated files*).
4. **Rows,** no new test function: the form's shapes and rendered kinds (`fields/tests.rs`, about lines 64, 266 and 597); the settings file's whole-record round trip, selector rules and malformed values (`settings_file_tests.rs`, about lines 509, 532 and 552): a table with an item of each class, a worded item, a set; a table `check` refuses (an item of `money`); a CLASS `"wait"` refused; the tools' `settings show` tests and fixtures beside `project-ways`' (`temper-client-tools/src/tests/`), with the help golden `help_settings_show.txt` regenerated if it moves.
5. **Bite:** let VALUE take CLASS `"wait"`, see its row fail; restore.
6. Runs, counts in the report: `heavy cargo nextest run -p temper-client-tools -p temper-settings-form -p temper -p temper-docs`; clippy for every package changed. The reference pages' tests and `temper-docs`' help bounds pass.
7. Status: delete the **Not yet** entry naming `ui-reaches/classes-tools` in `temper/docs/design/client/tools.status.md`.
