# tools-store: the settings store keeps a charter's tools

## Goal

The settings family's `RunPolicy` record carries the charter's `tools` (contract C1), so a
charter changed through the settings keeps its host-family mask across a restart. The schema
stays `settings-v1`, changed in place, as jig's store does before the baseline.

Acceptance:

- `jig/crates/jig-protocol-store/schema/settings-v1.schema`, `record RunPolicy`, gains
  `tools: u64` after `call_timeout`.
- The generated `settings_v1.rs`, the layout fingerprint in `generated/layouts.rs` and the
  goldens under `golden/settings/` that embed a `RunPolicy` are regenerated by the drift
  tests, never by hand.
- `codec/settings.rs`'s `encode_run_policy` writes `policy.tools.0` and `decode_run_policy`
  reads it into `RunPolicy.tools`, in place of `tools-surface`'s `EVERY_FAMILY` filler and
  its comment.
- A step test in `src/tests/settings.rs`, `a_charters_tools_survive_the_store`: a charter
  whose policy has `tools` 1,536, and one with `RunPolicy::EVERY_FAMILY`, each encode and
  decode equal.
- The focused tests of `jig-protocol-store` and of the store codecs' world
  (`jig/tests/store-codecs`) pass; `heavy cargo check --workspace --all-targets` is clean.

## Owns and may change

- Owned: the files in this spec's `files`.
- Reader files: none expected. A test elsewhere that holds a settings record's bytes or the
  settings layout's fingerprint (a store world's golden) and fails only because the record grew
  by its `u64`: regenerate it by its own drift or golden-writing test, and list it.
- Options, pre-approved:
  - Regenerate with `SKEIN_CODEGEN_WRITE=1 heavy cargo nextest run -p jig-store-codecs-world
    -E 'test(drift::)'` (the package name as `jig/tests/store-codecs/Cargo.toml` gives it),
    then run the same without the variable to see it clean.
  - If the drift test writes files outside this spec's `files` that embed the same
    record (another family's golden holding a settings value), keep them, and list them.
  - A computed size bound (`decoded_bound`, the memory test in
    `jig/tests/store-codecs/tests/suite/memory.rs`) that moves by the new field is the
    generator's; a pinned figure that fails: correct it and its comment alone, and list it.
    A production profile figure that no longer fits: stop and ask.
