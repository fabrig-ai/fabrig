## Goal

The gallery's four Only you states, from real client states: Needs you
with a question and two items, its done state with one, the first by
night, and Accounts with an expiring sign-in
(`temper/docs/design/client/browser.md`, 7.2: `needs-only-you`,
`needs-only-you-done`, `night-needs-only-you`, `accounts-expiring`).

Acceptance:

- `samples.rs` gains the four `Sample`s, each its world and address as
  7.2's row has it: the three Needs you states on `Address::Inbox {
  filter: Filter::ALL }`, the last on `Address::Accounts`; their accounts
  documents made as `account_states` (`samples.rs:2074`) makes
  `accounts-states`', from the sample's own document with the deciding
  source's `state` and `expiring` set: a ChatGPT sign-in `SignInAgain`
  and a Claude Code login `Granted`, usable and `expiring` for
  `needs-only-you`; the sign-in alone, with every card answered or none
  delivered, for `needs-only-you-done`; the ChatGPT sign-in `Granted`,
  usable and `expiring` for `accounts-expiring`. `night-needs-only-you`
  is `needs-only-you` with the night look, as `night-needs` is
  `needs-list`'s.
- `names.txt` regenerated by its tool, `SKEIN_CODEGEN_WRITE=1 heavy cargo
  nextest run -p temper-client-gallery -E
  'test(=tests::names_are_the_promised_ones)'`, then the same without the
  variable to see it hold; its order is the tool's.
- `tests.rs`'s `Holds` table gains a row each: `needs-only-you`, the
  region "Only you · 2", "Your ChatGPT sign-in is signed out. Sign in
  again?", "Your Claude Code login NAME is expiring. Sign in again?" with
  NAME the sample's login, and the link "Sign in again";
  `needs-only-you-done`, the heading "Nothing needs you." and the region
  "Only you · 1"; `night-needs-only-you`, the region; `accounts-expiring`,
  "Expiring: sign in again before it ends." and the button "Continue with
  ChatGPT".
- Delete `temper/docs/design/client/browser.status.md`'s **Not yet** entry
  `7.2, Only you's states`.
