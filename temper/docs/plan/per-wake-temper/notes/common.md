# per-wake-temper: what every task holds to

- **Focused and fuzzy alone.** Never `tools/tiers/run`, a `<tier>-<tree>` profile,
  `scripts/browser.sh`, a walk, a render check or a throwaway driver. A story in a slow
  tier is written and compiled (`--no-run`), not run: say so in the report.
- **Tests stay cheap.** The gate rejects a plan that adds cost. A new case of one
  behaviour is a row of the existing table test the spec names; a new test is only one
  the spec sketches, in a world below the real loop. No test reaches a real host.
- **The failing test first.** Write the spec's rows, run them, see them fail for the
  rule's reason, then build. The report quotes the failure seen.
- **A new test must bite** (the implementer's text): break the rule once by hand, see
  the row fail, restore.
- **The shapes are `temper/docs/plan/per-wake-temper/notes/contracts.md`'s.** A name,
  field, member or word it gives is spelled as it gives it. One it doesn't give is yours,
  inside your files.
- **jig is landed and stays as it is.** jig's half of the draft is on main (the plan
  `per-wake`): a charter's `parts`, an LLM choice's `later`, `tasks.charter_parts`, the
  client wire 19's records. This plan writes temper alone. A jig file is edited only
  where a spec says, and no task changes a stored format, the client wire or a refusal
  vocabulary: one that would is a `Question:` first.
- **The reference's settings file is kept by hand.** `temper/docs/examples/reference/settings.json`
  has no generator: its tests read it (`reference_settings.rs` and the readers
  `contracts.md`, section 5 lists). Edit it as JSON, keep its formatting (one item per
  line as it stands), and run every reader the spec names.
- **`reference-code-production.md` stays unedited** (`temper/docs/design/draft/`): tests
  and stage one's judge read it.
- **Generated files your change makes stale are yours,** regenerated by their own tool
  (`SKEIN_CODEGEN_WRITE=1` with the test that writes them: the settings-fields page by
  `temper/crates/temper/src/tests/settings_fields.rs`, `temper/docs/help/reference/` by
  its tests), never by hand, and named in the report with what moved.
- **`docs/design/` stays closed** but for the status sentences a spec says to delete,
  as a stated departure from the implementer's text: the design is written, and its
  status must say what is built when the branch lands.
- **Before calling a failure "outside the change",** run it once on the pristine base.
  If the base passes and your branch fails, it's yours.
