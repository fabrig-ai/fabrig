# per-wake-temper: `settings show` prints a charter's parts and a later choice

## Goal

In text, `temper ctl settings show charter N` prints each of a charter's parts with its `on`
and size, and `settings show template N` a template's later choice, after the value
(`temper/docs/design/client/tools.md`, 5.3, the bullet's last sentence); the help pages for
a charter and a template say what each is. The `form` task, merged, carries both through
the file, the view and `--json`; this task writes only what text prints and the help.

Acceptance:

- `settings_form::render::text` (`src/render.rs`), for a `Setting` read whose value is a
  charter with parts, prints after the value's JSON one line per part as
  `notes/contracts.md`, section 3 gives it, `parts[0]: on first; 4210 bytes`; for a
  template whose choice has a `later`, `later: claude-opus-5-5 high` (no effort: the model
  alone). A charter without parts and a choice without `later` print as today, so no
  existing golden moves.
- Rows in `temper/crates/temper-client-tools/src/tests/jig/settings.rs`'s text and JSON show
  test (near line 162) and its text goldens (`src/tests/golden/`, by the file's golden
  writer near line 522 with `SKEIN_CODEGEN_WRITE=1`): a charter with two parts, `on
  ["first"]` and `on ["question", "question_owed"]`, its two lines in that order, the second
  `parts[1]: on question question_owed; B bytes`; a template whose choice has a later choice,
  its line. The JSON goldens of the same values hold `parts` and `later` whole.
- `temper/docs/help/charter.md`, "What it is": a charter's `parts` in its list, in the
  page's voice: instructions for some reasons a run runs, each with its `on`, `first` (the
  task's first activation) or the kinds of message that woke it; a run reads the charter's
  instructions, then each part whose `on` meets why it runs, so "reads its charter, whole"
  says what is read whole and what by part; a charter whose runs resume takes none.
  `temper/docs/help/template.md`'s list: the models the task asks for, and a later choice
  for every run after its first activation's. Each within its page's bound
  (`temper/crates/temper-docs/src/lib.rs`), each member's type and bound left to
  `settings-fields` as the pages do. This is a stated departure from the implementer's
  text, which closes `docs/help/`: the pages are what an owner and the configuring agent
  read of the settings.
- `temper/docs/help/reference/ctl-settings.md`, regenerated by its tests
  (`temper/crates/temper-client-tools/src/tests/help.rs` near line 547,
  `temper/crates/temper/src/tests/commands.rs` near line 252, `SKEIN_CODEGEN_WRITE=1`) if
  the show's output description moves, never by hand.
- Delete from `temper/docs/design/client/tools.status.md` the bullet "**Not yet:** 5.3: in
  text, `settings show charter N` prints no line per part ..." and nothing else (a departure
  from the implementer's text, which closes `docs/design/`: the status must say what is
  built when this lands).
