# A change keeps up to 128 open questions, so its bound can be 80

## Goal

`forge.change_policy.questions` can be 80 (contracts K4): the forge refuses a bound at or past
`QUESTIONS_OPEN`, the open questions a change keeps on its record, which is 16
(`temper-engine-domain-forge-change/src/boundary.rs:482`; `temper-engine-domain-forge/src/limits.rs:103`),
and the store's `Questions.open` is `list 16`. Both become 128, the store's in place (the user's
decision for this pre-release format; `notes/common.md`), and the store prices a change's open
questions by its own bound, not by the ceiling, so a small deployment's change row does not grow.

Acceptance:

- `QUESTIONS_OPEN` is 128; `temper/crates/temper-protocol-store/schema/store-v11.schema`
  `Questions.open: list 128 Open` (was 16); generated code and goldens regenerated by temper's
  writer (`notes/common.md`), never by hand.
- The store's limits made from the forge's (`temper-protocol-store/src/lib.rs`, `bounds`, and
  `src/records.rs`, `limits`, wherever `v11::Limits` is built from `forge::Limits`) set
  `questions_open` to `change_policy.questions + 1`, the most a change holds open (its bound's
  questions and the one past it, which holds the change: `temper/docs/design/domain/forge.md`,
  8.11, "Bounded"), which the forge's `valid` keeps within `QUESTIONS_OPEN`; so today's stock (4)
  prices five.
- Tests that build lists at `QUESTIONS_OPEN` (`src/tests/relay.rs:303-314`,
  `temper-engine-domain-forge/src/tests/limits.rs:86-97`, `src/tests.rs:1060`) pass at 128,
  each edited only where it names the old figure; a store test in `temper-protocol-store`
  asserts a change row with `change_policy.questions + 1` open questions round-trips and one more
  is refused by the derived limits (name it `questions_open_follows_the_change_bound`).
- `heavy cargo nextest run -p temper-engine-domain-forge-change`, `-p temper-engine-domain-forge
  --lib`, `-p temper-protocol-store`, `-p temper-codecs-world` and `-p temper-engine-domain --lib`
  pass.
