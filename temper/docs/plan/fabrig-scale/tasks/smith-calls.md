# smith takes 48 calls in one response

## Goal

An agent declared with `calls_per_response` 48 and `conversations` 26 (a run and 25
sub-agents; contracts K5) passes smith's derivation with `temper init`'s two models. Today it is
refused by the transcript schema's ceilings (`smith-agent-service/src/profile.rs`, `transcript`):
a message's blocks, a completion's output items `2 × 48 + 2 = 98`, past `Message.blocks`'
`list 64`; and the opaque bytes, 98 output items times `gpt-6-luna`'s `reasoning_item` 65,536
plus the replay header, past `Opaque.bytes`' `bytes 3145728`. The ceilings change in place
(`notes/common.md`), so smith's own checks (`smith/docs/design/protocol/limits.md`, 4,
`calls-in-transcript`, `turn-in-transcript`, `turn-in-channel`) pass at these figures.

  `forty_eight_calls_per_response_derive_with_two_models`: smith's `standard` profile with
  `declared` `tool_payload` 10,662, `read_window` 256, `conversations` 26, `calls_per_response`
  48, `memory` 2,147,483,648, and `policy` `max_turns` 800, `check_timeout` 60,000 ms,
  `group_stop` 10, `inbox` 8, `unacknowledged` 8; two endpoints of dialect 3, one model each:
