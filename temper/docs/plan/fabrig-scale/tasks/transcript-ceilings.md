# A turn of up to smith's 16 MiB, stored and carried to a worker

## Goal

The codecs that hold one of smith's turns, or a worker's resumed transcript, take any turn
smith admits (contracts K3): smith's largest turn T is at most its channel's `turn_body`
ceiling, 16,777,216 bytes, but the store's `TurnRecord.transcript` and the worker wire's
`Turn.body` cap it at 8,388,608, and the worker wire's `Assignment.transcript` caps a worker's
resumed transcript (about four times T) at 8,388,608. The ceilings change in place, with no new
version (the user's decision for this pre-release format; `notes/common.md`).

Acceptance:

- `jig/crates/jig-protocol-store/schema/core-v6.schema`: `TurnRecord.transcript: bytes 16777216
  holds smith-transcript Turn` (was 8388608); nothing else of the schema.
- `jig/crates/jig-protocol-worker-wire/schema/worker-wire-v9.schema`: `Turn.body: bytes 16777216`
  and `Assignment.transcript: bytes 134217728` (each was 8388608); nothing else.
- Their generated code and the store's layout fingerprints regenerated by the writer
  (`notes/common.md`: `SKEIN_CODEGEN_WRITE=1 heavy cargo nextest run -p jig-store-codecs-world
  --test drift`), never by hand; no golden `.bin` changes (goldens fill one item whatever the
  ceiling). Commit only the generated files of these two schemas and `layouts.rs`.
- The tests that pin the old ceilings name the new ones: `src/tests/codec/core_rows.rs:94`
  (`turn_record_transcript`), `jig/tests/store/tests/suite/upgrades/frame_refusal.rs`
  (`CODEC_TRANSCRIPT_CEILING` and its comment, which cites store.md 8.1's quote, now
  `bytes 16777216`), and the worker wire's fixture limits
  (`jig/crates/jig-protocol-worker-wire/src/tests/fixtures.rs:388-389`) where they stand for the
  ceilings.
- `heavy cargo nextest run -p jig-store-codecs-world --test drift` passes without the writer;
  `-p jig-protocol-store`, `-p jig-protocol-worker-wire`, `-p jig-protocol-engine-workers`,
