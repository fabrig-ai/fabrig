# An inbox entry carries every goal it belongs to, 33 deep

## Goal

An inbox entry carries each goal it belongs to, its task's ancestors that are goals and the task
itself, so at most `tasks.depth` + 1: 33 in the `standard` profile (contracts K2; jig's
`client/domain/pages.md`, 3, "Filtered"). The client wire's `InboxSelection.goals` holds 32, so
the engine's encoding of an entry 33 deep fails and closes the read or the whole stream; and a
client receives only its `rows` of them (8 in temper's terminal), so an entry 8 deep is refused
there already. The wire's list grows in place (the user's decision for the client wire's counts;
`notes/common.md`), and a client receives the wire's whole list.

Acceptance:

- `jig/crates/jig-client-protocol-wire/schema/client-v19.schema`: `record InboxSelection {
  cursor: InboxCursor goals: list 64 u64 }` (was `list 32`), in place, client-v19 kept; its
  generated code and goldens regenerated by the writer (`notes/common.md`), committing only the
  client wire's generated file and goldens (and, if the writer also rewrites another family's
  file identically, nothing of it).
- `jig/crates/jig-client-protocol-link/src/limits.rs`: `wire.inbox_selection_goals` is the wire's
  ceiling (`w::CEILINGS.inbox_selection_goals`), not `client.rows`, with a comment: a selection is
  a handful of numbers, every one received whatever the client's rows (pages.md, 3).
- `jig/crates/jig-client-protocol-link/src/translate/pages_part4.rs`: `inbox_selection_fields`
  bounds `value.goals()` by `limits.wire().inbox_selection_goals`, not `limits.client().rows`.
- Tests:
  - in `jig-client-protocol-link`'s tests, `an_inbox_entry_33_goals_deep_is_received`: a client
    with `rows` 8 decodes an inbox row whose selection names 33 goals;
  - in `jig-protocol-engine-clients`' tests, beside the inbox translation's
    (`src/translate/inbox.rs`), an entry whose selection has 33 goals encodes at
    `v19::CEILINGS`.
- `jig/docs/design/client/domain/pages.status.md`: the entry "3: an entry carries at most 32
  goals, ... `inbox_selection_goals`)." removed.
- `heavy cargo nextest run -p jig-client-wire-world -E 'test(/drift::/)'` passes without the
  writer; `-p jig-client-protocol-wire`, `-p jig-client-protocol-link`,
  `-p jig-protocol-engine-clients`, `-p jig-client-protocol-world` and `-p jig-engine-clients-world`
  pass; `heavy cargo check -p temper-client-shell-terminal -p temper-client-tools --tests`.
