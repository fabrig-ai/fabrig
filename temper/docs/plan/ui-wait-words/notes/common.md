# ui-wait-words: what every task holds to

- **Focused and fuzzy alone.** Never `tools/tiers/run`, a `<tier>-<tree>` profile, a browser test, a walk, a render check or a live run. A plan is complete when it lands (the user, 2026-11-06). `temper-client-journeys again` is generation, not a walk: a task whose change leaves a journey stale runs it (below).
- **Tests stay cheap.** A new case of one behaviour is a row of an existing table test (skein's `docs/foundation/testing-strategy.md`, 8); each spec names its tables, and a new test is only one the spec sketches. temper's focused and fuzzy suites have 30 and 120 CPU seconds in the gate.
- **The contract binds:** `temper/docs/plan/ui-wait-words/notes/contracts.md`. Its types, fields, wire lines and words cross the two parts; a spec's sketch never departs from it.
- **Decide, don't ask.** The client wire and the client contract change in place, with no compatibility and no version bump, before v0.1.0 (the request). A small edit just outside your list (a re-export, a `mod` line, a golden, a design line) is made and named in the report.
- **Generated files your change makes stale are yours,** regenerated by their own tool, never by hand:
  - jig's client wire and its goldens: `SKEIN_CODEGEN_WRITE=1 heavy cargo nextest run -p jig-client-wire-world -E 'test(drift::)'`, the command its drift test prints;
  - a journey the focused replay calls stale: `heavy cargo run -p temper-client-journeys -- again NAME`; on "a key mark caught a moving page", retry up to three times, each on a fresh fake box, then widen the mark's wait in the recording driver and say so;
  - `temper/docs/help/reference/*` and ctl's help goldens, by the generator their test names.
- **A test's oracle or helper that your change's correct behaviour trips is yours to repair,** keeping what it checks for everything else, and named in the report.
- **`docs/design/` stays closed** but for the status entries your spec says to remove: the design is written. What the code taught goes in the report.
- **Help pages** (`temper/docs/help/`) that your change pushes past their byte bound are yours to condense, losing no fact; never raise the bound.
- **Left alone:** `temper/crates/temper-service/src/startup/checks.rs` and `problems.rs` (temper's startup reads jig-domain-fleet's own `AgentShortfall`, which already names its charter, and two other drafts are changing `checks.rs`); `temper.css`, the gallery and its goldens (no look changes here).
- **Before calling a failure "outside the change",** run it once on the pristine base. If the base passes and your branch fails, it's yours.
