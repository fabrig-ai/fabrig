# tui-launchpad: what every task holds to

- **Every commit carries the trailer `Look-request: tui-launchpad`,** directly above the
  other trailers (`temper/docs/design/draft/look-requests.md`, 3 and 5), a fix of what an
  earlier commit missed included. A commit without it hides the work from
  `temper/scripts/look-refresh.sh`; amend it before you push.
- **Focused and fuzzy alone.** Never `tools/tiers/run`, a `<tier>-<tree>` profile,
  `scripts/browser.sh`, a walk, a render check, a screenshot or a throwaway driver. A
  story in a slow tier (browser, process, live) is written and compiled
  (`heavy cargo check -p PKG --tests`), not run: say so in the report.
  `temper-client-journeys again` is generation, not a walk: the task that names it runs
  it (retry up to three times on a moving screen, each on a fresh fake box; if all fail,
  widen the mark's wait in the recording driver and say so).
- **The frames are the spec.** The user's hand-made frames are this plan's
  `inputs/launchpad-01.txt` to `-04.txt`, their pages `git show
  9b3942a123:temper/docs/design/client/tui/journeys/launchpad/0N.html` (a class `f-NAME`
  is a fore colour, `b-NAME` a background, from the palette). They are drawn at 80 by
  24, dark, with values written in by hand: a golden or a test row draws the same
  structure, words, glyphs, paints and places from fixture values, never the frames'
  bytes. Where your build differs from a frame, the report says where and why, for the
  account (`look-requests.md`, 5).
- **Tests stay cheap.** A new case of one behaviour is a row of the existing table test
  the spec names; a new test is only one the spec sketches, beside its siblings' fixture.
  No test opens a real terminal, a browser or a box but those that already do. Budgets
  and timeouts are the user's, never raised.
- **A new test must bite** (the implementer's text): break the rule once by hand, see the
  row fail, restore; the report names the rule and the failure seen.
- **The shapes are `temper/docs/plan/tui-launchpad/notes/contracts.md`'s.** A name,
  field, type, word or record it gives is spelled as it gives it. One it doesn't give is
  yours, inside your files.
- **No compatibility before v0.1.0.** A stored format, a protocol or a public interface
  may change; a spec that changes one says so, and the report names it.
- **Goldens are kept by hand** in `skein-ui-screen` (`src/tests/golden/`) and
  `temper-client-tui` (`src/tests/golden/`): a change the design asks for is written into
  them from the golden test's mismatch print, each changed line checked against the design
  and the frames; any other line that moves is a red. Where a golden test offers
  `SKEIN_CODEGEN_WRITE=1`, it may write them, and every changed line is still checked.
- **Generated files your change makes stale are yours,** regenerated by their own tool,
  never by hand, and named in the report with what moved: the TUI's journeys' prints
  under `temper/docs/design/client/tui/journeys/` by `cargo run -p
  temper-client-journeys` (a replay gone stale is recorded again only by the task that
  names `again`); `temper/docs/help/reference/*` by its own test. The browser's journeys
  (`temper/docs/design/client/journeys/`) are another owner's: a diff there is a red.
- **Help pages** (`temper/docs/help/`) are read by tests (`.config/gate/read-by-tests.txt`):
  a page your change makes wrong is yours to correct within its bound, condensed losing no
  fact if it must, and named in the report.
- **`docs/design/` stays closed** but for the **Not yet** status entries a spec tells
  you to delete, as a stated departure from the implementer's text: the design is
  written, and its status must say what is built when the branch lands. What the code
  taught goes in the report.
- **Before calling a focused or fuzzy failure "outside the change",** run it once on the
  pristine base. If the base passes and your branch fails, it's yours.
- **A test's oracle or helper that your change's correct behaviour trips is yours** to
  repair in the same task, keeping what it checks for everything else, and named in the
  report.
- **An item a later task of this plan constructs or reads** (a field, a variant, a
  function your task declares as the surface for it) may carry a scoped
  `#[expect(dead_code, reason = "read by the task TASK of tui-launchpad")]`,
  pre-approved; the later task removes it when it uses the item, and both reports say so.
- **Other drafts beside this one:** `ui-ask-drop`, `look-round-19` and
  `ui-account-again` change `temper-client-domain`, `temper-client-view` and
  `temper-client-shell-web` files; touch only the files your spec names there.
