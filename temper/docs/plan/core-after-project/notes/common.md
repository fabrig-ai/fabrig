# core-after-project: what every task holds to

- **Focused and fuzzy alone (`AGENTS.md`, 5; the user, 11-06).** Never `tools/tiers/run`, a `<tier>-<tree>` profile, `scripts/browser.sh`, a process, live or browser tier, a walk, a render check or a throwaway driver, even where a test's name invites it. The worlds this plan writes in (`temper-engine-domain-world`, `temper-service`'s tests, `temper-one-process-world`) are all in the focused suite. No test reaches a real host, account or repository.
- **The incident's evidence is the request's words alone** (`temper/docs/plan/core-after-project/inputs/request.md`). Nobody copies the deployment's store or log, which hold a login. The cause is reproduced from the acts.
- **The design is written:** `temper/docs/design/domain/root.md`, section 4 (*A stopped journal ends the engine, naming why*); `temper/docs/design/protocol/README.md`, 8.2 (*When the core does not answer*); `temper/docs/design/client/tools.md`, 8.1 (`sign-in`'s not-ready line). `docs/design/` stays closed to you, but for the status entries your spec names: what the code taught you goes in the report.
- **Red first.** Where your spec says so, commit the failing test before the code that makes it pass, so the branch's history shows it red; the report names what it failed on, with the log's lines that show it.
- **Tests stay cheap.** A new case of one behaviour is a row of an existing table test (`skein/docs/foundation/testing-strategy.md`, 8); a story goes beside its siblings, in a world below the real loop. One thread, one loop, a seed that replays. Budgets and timeouts are the user's, never raised; name your new tests' times in the report.
- **A stored format or a protocol** (jig's client wire, temper's store schemas, jig's store families) does not change in this plan without a question first. Formats change in place before v0.1.0, so a repair of records already stored, done at start within today's format, is no format change.
- **skein's and jig's interfaces:** a fix inside a skein or jig crate that keeps its public signatures is yours where your spec allows it, with a row in that crate's own tests first (`AGENTS.md`, 5: the lowest tier that shows it), and named in the report as the heads-up the request asks for. A change to a skein or jig public signature is a question.
- **A compiler-forced arm or field** your change makes in another crate is yours, in any tree, edited only for that, with the nearest existing behaviour; list each in the report.
- **A test's oracle or helper that your change's correct behaviour trips is yours to repair,** keeping what it checks for everything else, and named in the report.
- **Before calling a focused or fuzzy failure "outside the change",** run it once on the pristine base. If the base passes and your branch fails, it's yours.
- **Overlaps.** `ui-account-again` (cut in flight) repairs re-declaring a forgotten account: its accounts and people code (`jig-domain-accounts`, `jig-domain-core`'s `account_requests.rs`) and its words are not yours. Make a forgotten account's name declarable only if your spec says so; it does not. `ui-ask-m1` landed in `temper-engine-domain` and `temper-service`: keep your hunks to what your spec names; never reformat or move what you don't change.
