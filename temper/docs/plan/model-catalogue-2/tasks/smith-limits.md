# smith takes a model from the charter

## Goal

An agent's configuration holds no list of models. Each endpoint declares one set of limits for whatever it serves; a charter's LLM names any model on a configured endpoint within them, with any effort within its bound, and only the provider knows whether it serves that name. So a model added while an agent runs reaches it with no restart and no edit of `agent.json`.

Acceptance:

- `rg -n '"models"' temper/crates/temper-init/template/agent.json temper/crates/temper-init/template/bare-agent.json smith/crates/smith-agent-shell/README.md` finds nothing; `models` on an endpoint is refused as an unknown field, naming it.
- `rg -n 'ConfiguredModel|owned_bound|configured_model_bytes' smith jig temper -g '*.rs'` finds nothing but `smith-protocol-llm`'s local copy, if you keep it under another name.
- A charter with a model of any name on a configured endpoint is admitted within that endpoint's window and output. Past them it is `Invalid::Llm`; on no configured endpoint `Invalid::Endpoint`; with too little room `Invalid::Room`, as today. Any effort within its bound passes.
- `head`, `idle`, `protocol_allowance` and `drop_reasoning` come from the endpoint.
- A saved window's model that this charter doesn't name takes main's window, output and prices for its compaction, and is no longer `TranscriptRefusal::Malformed`.
- `run.models` is `charter_models - 1`; `temper init`'s agent gives 64 and its endpoints stock figures, so its largest turn is what smith measures, and every pin that follows from it is regenerated by its writer.
- `temper/crates/temper/src/agent.rs` makes its `EndpointBound`s from `Endpoint.limits`.
- Focused and fuzzy tests of each changed package pass, and `heavy cargo check --workspace --tests` compiles.
