# ui-box-children: what every task holds to

- **The request binds:** `temper/docs/plan/ui-box-children/inputs/request.md`, all of it, *For every task of this plan* first. It wins over a spec where they differ.
- **Runs:** focused and fuzzy alone, each build and test through `heavy`, one command at a time. No `tools/tiers/run`, no `<tier>-<tree>` profile, no `scripts/browser.sh`, no walk, no render check, no throwaway driver. **One exception, the request's:** this plan repairs the after-landing red `red-70`, so its task runs the flagged live story, `a_person_asks_claude_code_to_land_a_change_on_the_owned_forge`, by name, alone, as the spec says and no more often (`AGENTS.md`, 5: *That repair may run the test it repairs, by name, alone*). That departs from `temper/docs/design/domain/testing.md`, 2.7's *never run by an implementer*, on the director's word in the request. No other live, process or browser story runs, a new one among them: a story you add to `box_lifetime.rs` is written and compiled (`heavy cargo check -p temper --tests`), not run, and after-landing runs it.
- **Credentials:** the live story uses a held Claude Code login in place, named by `TEMPER_LIVE_CLAUDE` in the slot's environment. Nothing of that directory is read, listed beyond what `temper/scripts/proof-live.sh` itself does, copied or quoted: `stat` at most (`AGENTS.md`, 3). If `TEMPER_LIVE_CLAUDE` is unset, or `claude` isn't on `PATH`, never look for a login: the spec says what to do instead.
- **Logs:** filter every line holding `secret=` from anything you quote, commit or put in a report, and quote no token, link query or login path. A log is read by `grep` and `tail` around what you need, never whole.
- **Failing test first.** The fix's test is committed red before the fix, so the branch's history shows it failing; the report says what it failed on.
- **Tests stay cheap.** A new case of one behaviour is a row of an existing table test (`skein/docs/foundation/testing-strategy.md`, 8); a new test is only one your spec allows. temper's focused and fuzzy suites go to 30 and 120 CPU seconds in the gate: name your new test's CPU time in the report. No deadline widens, no story is skipped, and the live story's `no surviving children` check stays as it is.
- **The tree:** the fix stays in temper. A cause in skein or smith is a question, with the evidence and the fix you'd make (the spec's options), since a branch stays in its tree.
- **`docs/design/` stays closed** but for the status entry your spec names.
- **A test's oracle or helper that your change's correct behaviour trips is yours to repair,** keeping what it checks for everything else, and named in the report.
- **Before calling a focused or fuzzy failure "outside the change",** run it once on the pristine base. If the base passes and your branch fails, it's yours.
- **Before pushing:** `cargo fmt`; `python3 -I -B temper/scripts/old_forms.py`; `python3 -I -B tools/citations/citations.py --base origin/main`.
