# The worker's service runs a job's operations: its spec, its files, its process

## Goal

The worker's protocol layer serves its job capability (`temper/docs/design/domain/worker.md,
4.4`; `temper/docs/design/protocol/tooling.md, 2, 3 and 6`): it decodes a job's spec, temper's
`JobSpec` record, as it decodes a run's items; it carries out the capability's `Write`,
`Spawn`, `Kill` and `Read` (`notes/contracts.md`, section 8) with skein's io, the process's
environment exactly the four variables, its group killed at its deadline or on `Kill`, every
process known gone before `Gone`; and it bounds the job by the worker's limits for jobs.
`worker-jobs` left these as failing arms; this task replaces them.

Acceptance:

- `temper-protocol-worker-wire`'s schema (`worker-wire-v1.schema`, payload version 4 in place)
  has `record JobSpec { command: <bounded path bytes>, request: <bytes bounded by the file
  bound> }`; generated code and goldens regenerated by its drift test, never by hand.
- On a `LinkDown::AssignJob`, the service decodes the job's workspace items and its spec and
  hands the root `Event::AssignJob { job, items, spec }`, `Undecodable` where either fails.
- `Request::Job { owner, op }`: `Write` writes the file under the job's directory, no further
  than its bound; `Read` reads at most `most` bytes, `None` past it or missing; `Spawn` starts
  the program with exactly the given args, directory and environment (nothing inherited) in
  its own process group, answers `Spawned`, then `Exited { exit, tail }` with the last
  `tail_bytes` of its error output, killing the group at its deadline (`Exit::Deadline`), then
  `Gone` once the child and its pipes are released; `Kill` kills the group.
- The worker's limits for jobs are constants of the service's profile (`src/limits.rs`):
  `file_bytes` 1 MiB (`tooling_file_bytes`), `tail_bytes` 64 KiB (`tooling_log_bytes`),
  `path_bytes` 4096, `jobs` the worker's slots, `path` `/usr/bin:/bin`. No configuration key
  is added: the keys come with the first kind (`temper/docs/design/protocol/configuration.md`
  is not yours).
- The stories below pass; the service's existing worker tests pass unchanged.

no way to; `temper/tests/worker/**` fixtures that build the root's limits, a literal's new field.

Pre-approved options:

- **The process's capture:** reuse `temper-worker-protocol-git`'s `ByteRing` for the tail if it
  is public; otherwise a bounded ring in the service, beside the git wrapper's. Never more than
  `tail_bytes` held.
- **The deadline's clock:** the service's timers, as the git component's deadline is.
- If skein's io cannot start a process in its own group with an empty environment, stop and
  ask: that is a skein change.

## Steps

1. The `JobSpec` record; regenerate with the family's drift test (`rg -n 'worker-wire'
   temper/tests` for its world and command).
2. Decoding at the assignment; the root's `AssignJob`.
3. The four operations and their terminals.
4. The profile's job limits into the root.
5. Stories, each citing `temper/docs/design/protocol/tooling.md, 2`, in `src/tests/worker*.rs`
   (precedent `worker_admission::a_full_held_entrance_lets_a_passing_answer_pass`):
   - `a_jobs_command_gets_exactly_four_environment_variables_and_its_own_group`;
   - `a_job_past_its_deadline_has_its_group_killed_and_exits_deadline`;
   - `a_result_file_past_its_bound_reads_as_none`;
   - `a_job_spec_that_does_not_decode_reaches_the_root_undecodable`;
   - `a_kill_ends_the_group_and_gone_follows_the_release`.
6. `cargo fmt`; `heavy cargo clippy -p temper-protocol-worker-wire -p temper-service
   --all-targets -- -D warnings`; `heavy cargo nextest run -p temper-protocol-worker-wire`;
   `heavy cargo nextest run -p temper-service -E 'test(/worker/)'`; then `-p
   temper-worker-domain -p temper-worker-domain-world`.
7. Commits; push your branch.
