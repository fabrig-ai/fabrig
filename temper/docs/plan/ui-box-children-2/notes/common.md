# ui-box-children-2: what every task holds to

- **The request binds:** `temper/docs/plan/ui-box-children-2/inputs/request.md`, all of it, *For every task of this plan* first. It wins over a spec where they differ.
- **Runs:** focused and fuzzy alone, each build and test through `heavy`, one command at a time. No `tools/tiers/run`, no `<tier>-<tree>` profile, no `scripts/browser.sh`, no `scripts/proof-live.sh`, no walk, no render check, no throwaway driver. The live story `a_person_asks_claude_code_to_land_a_change_on_the_owned_forge` is not run: no worker holds its login, and after-landing runs it at every landing, its recorder (`temper/crates/temper/tests/support/forge_land/survivors.rs`) naming any survivor. `temper/crates/temper/tests/live.rs` and that recorder stay as they are.
- **Failing test first.** The fix's test is committed red before the fix, so the branch's history shows it failing; the report says what it failed on. Then the bite (the implementer's text): the fix undone once by hand, the test failing for the rule's reason, restored.
- **Tests stay cheap.** A new case of one behaviour is a row of an existing table test (`skein/docs/foundation/testing-strategy.md`, 8); a new test is only one your spec allows. temper's focused and fuzzy suites go to 30 and 120 CPU seconds in the gate: name your new row's CPU time in the report, run alone. No deadline widens, no limit or grace changes, and no story is skipped.
- **The tree:** temper's alone. A cause your spec doesn't name in skein, smith or jig is a `Question:`, with the evidence and the fix you'd make there.
- **`docs/design/` stays closed** but for the status entries your spec names. The design this plan's cut wrote is binding: `jig/docs/design/protocol/service.md`, 10, *Starting and ending together*; `temper/docs/design/protocol/README.md`, 8, *Agents and git as child processes* and *Starting and ending together*; `temper/docs/design/protocol/git.md`, 7, *At the worker's end*; `temper/docs/design/protocol/setup.md`, 7.2, *Its children*, and 15, *Agents in contained trees*.
- **Logs:** filter every line holding `secret=` from anything you quote, commit or put in a report. A log is read by `grep` and `tail` around what you need, never whole.
- **A test's oracle or helper that your change's correct behaviour trips is yours to repair,** keeping what it checks for everything else, and named in the report.
- **Before calling a focused or fuzzy failure "outside the change",** run it once on the pristine base. If the base passes and your branch fails, it's yours.
- **Before pushing:** `cargo fmt`; `python3 -I -B temper/scripts/old_forms.py`; `python3 -I -B tools/citations/citations.py --base origin/main`.
