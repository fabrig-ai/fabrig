# A task's activity can be read beside one of its lines

## Goal

The read a window bounded by size needs: the page next to a line, by that line's position, earlier or later. This task carries the read through the client's contract, the wire and the engine's core, and answers `Earlier` whole. `Later` reaches the store and answers an empty page there, until `beside-store` walks it. `thread-window` builds on this surface.

Acceptance:

- `c::Read::ActivityBeside` and `c::Side` exist, as the contract says, and cross the wire both ways. The family's goldens and generated code are regenerated by their tool and hold.
- In `jig-domain-core`, a read of `Earlier` at position p answers what `Read::Activity { before: Cursor::Store { after: p } }` answers, with the same access: a party who can't read `activity{n}` gets unknown.
- A read of `Later` reaches `Range { backwards: false, after: Some(position) }`, and the store answers it an empty page with no cursor. `beside-store` removes that one line.
- The engine's answer maps to the wire as the contract's *The answer* says: for `Later` a page's `next` becomes the wire's `after`, and its `before` is none.
- `jig-client-scripted-engine` answers both sides from its rows, so a world can read beside a line.
