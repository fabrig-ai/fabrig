# ui-ask-drop: what every task holds to

- **Focused and fuzzy alone.** Never `tools/tiers/run`, a `<tier>-<tree>` profile,
  `scripts/browser.sh`, a walk, a render check, a screenshot or a throwaway driver. A
  story in a slow tier (browser, process, live, the system world's slow stories, the
  real loop) is changed and compiled (`heavy cargo check -p PKG --tests`), not run: say
  so in the report. `temper-client-journeys again` is generation, not a walk: a task
  whose change leaves a journey's recording stale runs it (retry up to three times on
  "a key mark caught a moving page", each on a fresh fake box; if all fail, widen the
  mark's wait in the recording driver and say so).
- **Tests stay cheap.** temper's focused and fuzzy suites go to 30 and 120 CPU seconds in
  the gate, and a plan that adds cost is rejected there. A test moved from charter 3 to
  charter 11 keeps its cost; a new case of one behaviour is a row of an existing table
  test, not a new test; no test reaches a real host or a real program.
- **What a moved test checks stays.** A scripted run of charter 3 that becomes charter
  11's keeps its assertions on what the run did and what the engine answered; only the
  calls it makes change to charter 11's tools (`see` for `settings` and `read_docs`,
  `document` for `note` on the chat's document), and an assertion on a word the
  answer's renderer changed follows the renderer, named in the report.
- **The shapes are `temper/docs/plan/ui-ask-drop/notes/contracts.md`'s.** A number, name
  or word it gives is spelled as it gives it.
- **Charter 3 and template 3 stay in the stock until the task `stock` removes them.**
  Every other task moves its readers to charter 11 and template 5 while charter 3 still
  exists, so that each lands green on its own; none edits
  `temper/crates/temper-service/src/stock.rs` or `stock/configuring.txt` but `stock`.
- **No compatibility before v0.1.0.** A stored format, a protocol, a public interface or
  a stock number may change; the report names what did.
- **Generated files your change makes stale are yours,** regenerated by their own tool
  (`SKEIN_CODEGEN_WRITE=1` with the test that writes them; `temper-client-gallery`;
  `temper-client-journeys again`), never by hand, and named in the report with what
  moved: `temper/docs/help/reference/host-tools.md` by
  `temper/crates/temper/src/tests/commands.rs`
  (`the_page_host_tools_is_what_the_declarations_render`),
  `temper/docs/help/reference/settings-fields.md` by
  `temper/crates/temper/src/tests/settings_fields.rs`, terminal goldens by
  `temper/crates/temper-client-shell-terminal/src/tests/render.rs`. Goldens, prints and
  the gallery's `names.txt`/`tests.rs` conflict across plans: on a catch-up, regenerate
  rather than hand-merge, and keep `names.txt` sorted as it is.
- **Help pages** (`temper/docs/help/`) are read by tests (`.config/gate/read-by-tests.txt`):
  a page that names the configuring chat, `Configure`, template 3 or charter 3 says Ask
  temper, template 5 or charter 11 in the task that owns it, within its bound (12,288
  bytes for a concept page, 32,768 for a reference page), never raising it, and is named
  in the report. This departs from the implementer's text, which closes `docs/help/`:
  the request has the help say Ask temper.
- **`temper.css`:** new rules go under `/* ==== ui: settings ==== */`, never at the end of
  the file; replaced rules are removed where they stand.
- **`docs/design/` stays closed** but for the status lines a spec says to delete, as a
  stated departure from the implementer's text: the design is written, and its status
  must say what is built when the branch lands. What the code taught goes in the report.
- **Before calling a focused or fuzzy failure "outside the change",** run it once on the
  pristine base. If the base passes and your branch fails, it's yours.
- **A test's oracle or helper that your change's correct behaviour trips is yours** to
  repair in the same task, keeping what it checks for everything else, and named in the
  report.
- **Words:** "Ask temper" for the chat, in every word a person or a run reads; a code
  name that says `configure` or `configuring` for what is now Ask temper's says `ask`,
  where the spec names the rename. A name for configuring as an act (a settings
  proposal, `propose_settings`, "configuring temper by talking to it") stays.
