# test-speed: what every task holds

The request is `temper/docs/plan/test-speed/inputs/request.md`; its section *For every task of this plan* holds for every task here. The survey behind it is read from code and logs, so every cause it gives is unconfirmed until a task measures it.

- **Never raised:** a budget, a timeout or a limit a test runs under: `tools/tiers/budgets.toml`, the wall limits and `global-timeout`s in `.config/nextest.toml`, `crate::BOX_DEADLINE`, `WITHIN`, a `Patience`. No `#[ignore]`, no retries. Moving a test to escape a budget is raising it (`skein/docs/foundation/testing-strategy.md`, 8.1). `limits::DEADLINE` stays 30 s.
- **Stay out of `browser-trim`'s:** `temper/tests/client-browser/**` and the browser tiers' profiles.
- **Run one test of the tier:** `heavy python3 -I -B tools/tiers/run temper process -- -E 'test(=NAME)'`, whose prerequisites build the binaries. Once they're built, `heavy cargo nextest run --profile process-temper -p temper --test process -E 'test(=NAME)'`, with `TEMPER_TEST_CLAUDE` set as `tools/tiers/design.md`, section 1 has it.
- **Measure the tier, on one slot:** `heavy python3 -I -B tools/tiers/run --cpu DIR temper process`, with `DIR` fresh, private and untracked, then `tools/tiers/cpu-summary DIR --budgets tools/tiers/budgets.toml --pair process-temper` (`tools/tiers/design.md`, 7). One run takes about 10 minutes of wall.
- **Before and after, both reported:** the same tier on the same slot, at the task's base and at its head. Your figures go in `temper/docs/plan/test-speed/figures/<your task>.md` and no other file, with the commit, the machine and its load, the tier's wall and CPU, and the wall and CPU of each test your task names. Single runs are noisy: the same binary has cost 267 and 354 CPU s in consecutive runs, so name what a figure can't show. A test's own figures carry more weight than the tier's.
- **Status lines:** a task owns the **Not yet** entries the plan's cut wrote for it, and removes each that it closes (a departure from the implementer's text, which closes `docs/design/`). Only those lines; a gap it leaves open it says there as it stands, as **Not yet** or **Departs** with the reason. The sections themselves are written.
- **Beside this plan:** `box-small/link-hours` changes `temper/crates/temper/tests/process.rs`, `tests/fake_backends/box_link.rs` and `tests/fake_backends/walk.rs`; `sign-in-new-tab/sign-in-holds` changes `tests/fake_backends/walk/sign_in.rs` and `tests/support/person.rs`. Keep your hunks in those files small and take whatever trunk you start from as the one you measure.
- **Throwaway instrumentation** (a timeline script, a port probe, `perf` data) stays untracked and is gone before the push.
