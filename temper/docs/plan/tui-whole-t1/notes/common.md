# tui-whole-t1: what every task follows

- **The request binds:** `temper/docs/plan/tui-whole-t1/inputs/request.md`,
  *For every task of this plan* first. Its look is the mockup
  `temper/docs/design/client/tui/whole-story/launchpad.html` (and `pair/`,
  `team/` beside it), whose words, parts and order bind and whose figures
  don't (`temper/docs/design/draft/surfaces.md`, 13). The request wins over
  a spec where they differ; say so in the report.
- **The contracts:** `temper/docs/plan/tui-whole-t1/notes/contracts.md`,
  the names and shapes that cross this plan's tasks. Build to them; a
  change to one is a question.
- **Design:** each spec's `## Inputs` names the sections it builds, written
  by this plan's cut. A task deletes the **Not yet** bullet that names it
  (by its task's name and `tui-whole-t1`) in the status file its spec
  names, and edits no other design text: that departs from the
  implementer's text, which closes `docs/design/`. The drafts
  (`docs/design/draft/*`) and `docs/help/` stay closed but where a spec
  says otherwise.
- **Runs:** focused and fuzzy alone, each build and test through `heavy`,
  one command at a time. No `tools/tiers/run`, no `<tier>-<tree>` profile,
  no `scripts/browser.sh`, no process, browser or live story run, no walk,
  no render check, no throwaway driver. A slow-tier story a task writes or
  changes is compiled (`heavy cargo check -p PKG --tests`) and named in the
  report. Recording a journey again (`temper-client-journeys again`) is
  generation, and a task whose branch leaves a journey stale runs it; on
  `a key mark caught a moving page`, retry at most three times, each on a
  fresh fake box, then widen the mark's wait and say so.
- **Tests stay cheap:** a new case of one behaviour is a row of an existing
  table test; a new behaviour may take one new test function, named in its
  spec. A failing test first for each behaviour; the report names the rule
  broken by hand and the failure seen (the implementer's text, *A new test
  must bite*). Budgets and timeouts are the user's, never raised.
- **Goldens:** a golden frame is written by hand from the design's frame or
  the mockup, then checked by the test (`temper-client-tui`'s
  `tests/goldens.rs`, `check`); a golden an earlier task wrote that this
  task's change makes stale is regenerated by the test's own output and
  read line by line before it is kept: every changed line follows from the
  spec.
- **Words:** the TUI never spells what the engine or the derivation gives
  (a stop's words, a brief, a need's words); the view's words are said by
  `temper_client_view::words` and `shared`, the TUI's own by its `words`.
- **temper-client-tui is shared within a wave:** where two tasks of this
  plan change it at once, their files are disjoint but for the lines their
  specs name, kept small and apart.
- **Other plans in flight** (`plan.md`, *Overlaps*): temper/ui's P1 and P2
  (`ui-p1-rail`, `ui-p2-home`) change `temper-client-domain` and
  `temper-client-view`; `ui-reaches` changes the view's `shared` and
  `temper-client-shell-terminal`'s goldens. Touch those crates only where a
  spec says, in its own hunks.
- **Before pushing:** `cargo fmt`; `python3 -I -B temper/scripts/old_forms.py`
  (`--write` only to lower a count); `python3 -I -B
  tools/citations/citations.py --base origin/main`; clippy as the
  implementer's text says, naming every package changed.
- **Decide, don't ask** (the request): a stored format, a protocol or a
  public interface may change before v0.1.0, with no compatibility or
  migration; a small edit just outside a spec's files is made and named in
  the report.
