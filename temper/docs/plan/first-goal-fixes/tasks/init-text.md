# `temper init`'s documents take the most text their clients receive

## Goal

`documents.text_bytes` is 128 in `temper init`'s documents, and a task's text reads in pieces of it (jig's `client/domain/contract.md`, 6): one task made 8 `read_task` calls on its spec, and the goal 59 in all, each a turn. Raise it to 512, and hold that with a test. **This departs from the request's 8,192, for the reason below;** the user is being asked about the rest.

Why not the standard's 8,192: by reading, a start takes it, and the clients do not. jig's `wire` in `jig-client-protocol-link/src/limits.rs` sets `document_text_bytes` to `client.text.max(HOLD_ACCOUNT_BYTES)`; `receiving` starts from that wire; `component.rs` decodes each stream event with it; and `temper-client-shell-web` and `-terminal` both have `text` 512. So past 512, the web and terminal clients refuse a document with longer text, and no start says so. `temper-client-tools` takes 32,768.

Why it was 128: `temper/docs/design/protocol/setup.md`, 8.1 called it "temper's client's rows and text". The clients now take 512. The report gives what `git log` shows of the figure's origin, briefly.

Acceptance:

- `temper-init/template/temper.json`, `bare.json` and `temper/docs/examples/owned.json` say `"documents.text_bytes": 512`; `temper/docs/help/reference/configuration-engine.md` is regenerated by its own tool.
- A test holds it: for both of init's documents and each of the web, terminal and tools clients, the figure is at most that client's `jig_client_protocol_link::Limits::receiving().document_text_bytes`. It fails at 513.
- A start of each document's limits passes, as `temper-init`'s tests start them. If a start's check refuses 512, take the largest that passes, and the report says which bound and what it does.
- `temper-playground/src/documents.rs` stays 128 unless its size has no need of it. Default: it stays; no coordinator reads specs there. The report says what a run of its tests at 512 did, as a measure, restored after.
- `temper-service/src/tests/stock_brief.rs`: if a figure rests on it, it moves, and the report says which and from what to what.
- `temper/docs/design/protocol/setup.status.md` and `configuration.status.md`: the two **Not yet** entries on `documents.text_bytes` are deleted. **This departs from the implementer's text,** for those entries alone.
