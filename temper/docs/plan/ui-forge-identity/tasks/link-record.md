# A forge's record holds its link to a box's person

## Goal

A box's person will be known on each forge temper can vouch for by one stored fact, the forge's **link**: on this forge, that party is that user. Give it its record, its store field, its read, the connector's two new inputs and its log note, all as `notes/contracts.md`, *The link* has them. Nothing makes a link yet: both new events are handled as nothing, and `link-decide` gives them their bodies. The stored format changes in place.

This task departs from the implementer's text in one way: two status entries are yours to remove (acceptance 6), because the design already says what this task builds.

Acceptance:

1. `Link`, `ForgeRecord::person`, `PersonAnswer`, `LinkNote`, `Event::Owner`, `Event::PersonOf`, `Request::LinkNoted` and `Domain::link` exist in `temper-engine-domain-forge`, exported from its `lib.rs`, exactly as the contract has them, each with a doc comment citing its design section.
2. The store's `record Forge` gains `person: option ForgeLink`, last, with `record ForgeLink { user: u64 person: u64 }`, at `STORE_VERSION` 11 unchanged; the generated code and goldens regenerated by their tool; a row whose link has a zero `user` or `person` decodes as refused.
3. A record with a link round-trips through `records::encode` and `decode` (a row of `forge_record_round_trips_every_mode_and_state`), and the zero rows are rows of the decode refusal table the file already has; `largest_forge_record_fits_the_application_ceiling` measures a record holding a link and still passes.
4. A restored record with a link is answered by `Domain::link` and an ended or unknown forge's by `None` (rows of `a_restored_record_is_listed_and_told_to_the_routing` or the restore table beside it in `src/tests/records.rs`).
5. The root turns `Request::LinkNoted { forge, note }` into `Fact::ForgeLink { forge, note }` by `diagnostics::emit`; temper-service's `engine.rs` passes it on as a new `Note::ForgeLink { forge, note }` (`temper-service/src/lib.rs`), and `temper/crates/temper/src/host.rs`'s `note_line` writes it as the line the contract gives (`forge N's person: ...`), one row per `LinkNote` in the test there that already calls `note_line` (beside `note_line(Note::CallAdmissionRefused { .. })`); if that test is no table, make it one with its case as the first row.
6. The entries *2.1: the forge's record holds no link to a box's person.* (`temper/docs/design/protocol/forge.status.md`) and *2: family 25 `Forge` holds no link to a box's person.* (`temper/docs/design/protocol/store.status.md`) are gone.
7. Focused tests pass in `temper-engine-domain-forge`, `temper-protocol-store`, `temper-codecs-world`, `temper-engine-domain`, `temper-service`, and `temper`'s lib tests; `heavy cargo check --tests` passes for every package the compiler names with a `ForgeRecord` literal (below); clippy clean for the packages changed.
