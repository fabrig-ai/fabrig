# A written note's answer says what changed

## Goal

A write answered says how many lines the body has, how many changed, and where: what the client's tool line shows and what its
tint follows.

Acceptance:

- `jig_domain_notes::line_change(old: Option<&[u8]>, new: &[u8]) -> LineChange`, as `notes/contracts.md`, *A note's answer*, in a
  module of its own, `lines.rs`: pure, one pass over each body, bounded by them, no LCS, no allocation.
- `notes::Request::Written`, `CallPart::NoteWritten` and temper's `CallAnswer::NoteWritten`
  (`temper/crates/temper-engine-domain/src/store.rs`, both its conversions) gain them, as the note has them. They are stored with the call
  part: `core-v6.schema`'s `CallPartNoteWritten`, regenerated by the schema's own tool, its golden or fixture regenerated. `stored.rs`'
  validity holds `first <= lines` where `lines > 0` and `added <= lines`. `core::Held::NotesWritten`, which nothing makes, stays as it is.
- The tools' words, `jig-protocol-tools/src/render.rs`, add nothing: `Wrote note N revision R`, as today. temper's stay as they are too:
  the task `chat-stock` changes them.
- **The answer survives its own input.** `jig-protocol-transcript/src/lib.rs`, `translate_block`: a call's tool, then its answer, then its
  input take from the turn's text budget, so that a note's whole body can't eat the words that say what it did. A change of meaning: run
  `temper-client-view`'s tests too, whose `csv_chat_hears_its_result` and delegation cards read that budget.
- Its tests below, each having bitten.
- `jig/docs/design/domain/engine.status.md`'s line on `lines`, `added`, `removed` and `first` goes, that line alone. `jig/docs/design/client/domain/client.status.md`'s words "and an outcome
  before its input" go.

## Steps

1. `lines.rs`, with tests in `tests.rs`: `a_first_write_counts_every_line`, `an_empty_body_has_no_lines`,
   `a_trailing_newline_adds_no_line`, `a_middle_change_trims_both_ends`, `an_append_starts_after_the_old_body`,
   `a_removal_at_the_end_points_at_the_last_line`, `an_unchanged_body_changes_nothing`, `prefix_and_suffix_never_overlap` (`aXa` to
   `aXXa` by lines), and a small generated check that `added`, `removed` and `first` rebuild the new body from the old.
2. The fields through `Request`, `CallPart`, the store, temper's `CallAnswer` and every reader.
3. `jig-protocol-transcript`'s order, with `a_large_input_leaves_the_calls_answer_whole` in its tests: a call's input past the turn's text
   budget, its answer whole, its input cut, `Turn.cut` true.
4. `heavy cargo nextest run -p jig-domain-notes -p jig-domain-core -p jig-protocol-store -p jig-protocol-tools -p jig-protocol-transcript -p
   temper-client-view`; `heavy cargo check --tests -p temper-engine-smith -p temper-engine-domain -p temper-service`, and the other readers you
   changed. The store's goldens by their drift test, as `rg -n SKEIN_CODEGEN_WRITE jig/crates/jig-protocol-store jig/tests` shows it.
5. **Check,** the implementer's text, then push.
