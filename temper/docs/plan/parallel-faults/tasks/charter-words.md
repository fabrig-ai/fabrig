# The coding charter says what a delivery keeps

## Goal

The request's item 4, and the "detached" half of item 6. A run's checkout is detached, and `deliver` commits the tree on the worker's own record of the head, never on HEAD. So a run's local commits keep their files and lose their history, and `git reset --soft BASE`, commit and `deliver` on a saved start leaves the save as the head, the fold gone. All of this is as designed (`git.md` 4.7; `worker.md`, section 5, `a_saved_head_already_on_its_push_branch_delivers_with_a_guard`), and a delivery's receipt already names the pushed commit. What's missing is that a run is never told, so it folds, and later words name a commit that isn't on the branch. The host's own resume words name no commit (`smith/crates/smith-domain-run/src/prompt.rs`, `RESUME`), so those names come from the agent's own transcript or summary, which no host filter can reach. This task tells it.

Acceptance:

- `coding.txt` holds these words as one run of text, placed before its last sentence or wherever reads best, and a test in `temper/crates/temper-service/src/tests/stock.rs` holds them as the others there are held:

  > Your checkout is detached: deliver commits the tree as it stands on the host's own head and names what it pushed. Your own commits, resets and rebases keep their files, not their history, so name no commit from an earlier run: it may not be on the branch.

- `temper/crates/temper/src/tests/reference_settings.rs` still passes: the reference's charter starts with the stock's words with "You can run nothing." replaced.
