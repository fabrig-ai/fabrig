# replay-repairs: what every task holds to

- **Focused and fuzzy alone.** Never `tools/tiers/run`, a `<tier>-<tree>` profile, `scripts/browser.sh`, a walk, a render check or a throwaway driver. A story in a slow tier is written and compiled (`--no-run`), not run: say so in the report.
- **Tests stay cheap.** The focused and fuzzy limits are being tightened, and the gate rejects a plan that adds cost. A new case of one behaviour is a row of the existing table test the spec names; a new test is only one the spec sketches, in a world below the real loop. No test reaches a real host.
- **The failing test first.** Write the spec's row or story, run it, see it fail for the fault's reason, then fix. The report quotes the failure seen before the fix.
- **A new test must bite** (the implementer's text): break the rule once by hand, see the row fail, restore.
- **jig never names temper; skein names no product.** A jig or skein change carries no temper word (`tests/boundary/tests/outward.rs`).
- **Decide, don't ask, inside the spec's options.** A stored format or a wire protocol change is not among them anywhere in this plan: if a fix turns out to need one, stop with `Question:`, as the request asks, since its owner must be told first.
- **Generated files your change makes stale are yours,** regenerated by their own tool, never by hand, and named in the report.
- **`docs/design/` stays closed** but for the status entries a spec says to remove: the design is already written.
- **Before calling a failure "outside the change",** run it once on the pristine base. If the base passes and your branch fails, it's yours.
