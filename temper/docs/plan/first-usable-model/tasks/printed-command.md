# What the page prints works when pasted

## Goal

The page prints `temper program-login NAME`. On a box with its own directories it reads the wrong document, and may sign in
under another deployment's programs directory while looking successful. After the site's `./temper box`, `temper` isn't on
`PATH`. `temper serve` knows its binary and its directories: have it say the whole command, and print that.

Acceptance:

- On a standalone deployment, `DeploymentAnswer.program_login` holds the running binary's absolute path, `program-login`, and
  the three directories in effect, each quoted for a POSIX shell. Run with `NAME` after it, by `sh -c`, from another
  working directory and with no `temper` on `PATH`, it reaches the program's sign-in for that box's `programs/NAME`.
- ConnectModel, the welcome's model step and the accounts page print it with NAME. Every place printing `temper program-login NAME`
  reads the same two functions (`notes/contracts.md`).
- Engine-alone: none, a line past 8,192 bytes: none, a path that isn't UTF-8: none. The pages then print the placeholder form.
- The tools' printed act (`temper-client-tools/src/limits.rs`) is unchanged.
- Under `temper box`, `internal serve` says the same binary and directories as the box.
