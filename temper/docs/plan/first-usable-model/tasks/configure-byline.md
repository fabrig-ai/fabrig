# The configuring byline names what the run will use

## Goal

A chat read "T1 · Claude subscription · gpt-6.1-sol": Claude's account beside OpenAI's model. That is
`pages/configure.rs`, `byline`, which joins `accounts::first_usable_kind` to the project's first
model with no look at either's provider. `choice.rs`'s `eligible` is right and isn't on this path.
Draw the configuring line from the composer's line, so one provider's account never sits beside
another's model.

Acceptance:

- On a configuring chat, the line is `T<n> · ` and the words `choice::byline` draws for that task.
- On `Address::Configure` with no chat, it is the words of a new chat's byline for that project: the
  first model `me` serves whose provider's readiness is `Usable` for the person, with that provider's
  first usable account.
- With a Claude program account alone, and `me` serving `gpt-6.1-sol`, `gpt-6-luna`,
  `claude-opus-5-5` in that order, the page's line names Claude's account and `claude-opus-5-5`.
- No usable account: the line says what the composer's line says then. No models served: no line.
- A story walks every byline, the new chat's, a chat's, a configuring chat's and the Configure page's,
  over each pairing of one provider's accounts with a model list holding both providers, and refuses
  any line that names one provider's account with another's model.
