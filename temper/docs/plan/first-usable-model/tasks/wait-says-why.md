# A wait reaches the person

## Goal

The user's chat said "Starting", with dots, to the end of time. Its chat was T1, the configuring chat, and `pages/chat.rs` draws
`above_composer` only when `!configuring`, so the reasons `choice.rs` already has never showed. Elsewhere they say "Starting: waiting
for an account" in the active style, with two links to `Accounts`. Say why in the person's words, on every chat, with the act; and in
`temper ctl task show`.

Acceptance, in `temper/docs/design/client/README.md`'s words, 5.5, *A run's wait*:

- A configuring chat whose run can't start draws its wait above its composer, as any chat does.
- `Account { None, None, Empty }`: "No account can run MODEL yet.", MODEL the task's main with `w.model_name`; and "Connect a model", to `ConnectModel` with no way.
  Falls to "No account serving this work" where the task names no model.
- `Account { Some, Some, Host }`: "ACCOUNT's login isn't signed in on a host that can run this.", the source's `command` (`connect_model::command`) where the
  accounts document names it, and a link to `Accounts`.
- `Credential`: "This work needs a credential from its forge.", and a link to `Forges`.
- `Host`: "No host has room for this, or none is connected. It starts when one does."
- `account_wait`'s status line says "Waiting for an account", in `STATUS_WAITING`, never `STATUS_ACTIVE`.
- A source's own words and acts stand as they are.
- No dots on any of these (`working` reads the bar's token: `run-wait-status` did that; hold it here with a test on the chat page).
- `task show`'s text keeps its `next run:` line and adds one line after it saying why and what to run, for each wait; a wait about to end adds none. JSON is unchanged.
