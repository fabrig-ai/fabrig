# Dismiss and the subject `dismissed` on the client wire

## Goal

The wire carries the request `Dismiss`, its outcome `dismissed` and the subject `dismissed` with its
document `Dismissals` (contracts K3). No side serves or sends them yet: `dismiss-request`,
`dismissed-read` and `dismissed-facts` build on this surface.

Acceptance:

- The schema holds K3's lines; `generated/v1.rs` and the goldens are regenerated by the writer
  (`notes/common.md`); `CLIENT_VERSION` still 11, the family's header still 11, every existing
  golden byte for byte unchanged but those the new enum variants add to.
- `wire::DISMISSED`, `wire::dismissals` and `wire::decode_dismissals` exist (K3), the decoder
  refusing trailing bytes as `decode_forges` does; `limits()` sets the list's bound from `DISMISSED`.
- A test in `temper-client-protocol-wire/src/tests.rs`, `dismiss_and_dismissals_round_trip`:
  `Requesting` with `Dismiss` of `ToBegin { project: u32::MAX }`, `Watching` with `Dismissed`,
  `Answer` with `Outcome::Dismissed`, `Dismissals` with no rows and with `DISMISSED` rows, each
  round-tripping; `Dismissals` refused with a trailing byte, and refused past `DISMISSED` rows under
  `limits()`.
- `heavy cargo nextest run -p temper-client-protocol-wire` and `-p temper-codecs-world` pass;
  `heavy cargo check --tests -p temper-service -p temper-client-domain -p temper-client-view -p
  temper-client-tools -p temper-client-shell-terminal -p temper-client-world` pass.
