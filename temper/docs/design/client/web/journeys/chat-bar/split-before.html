How work would run here

So far this is temper's standard path. Nothing in this project's settings has been looked at or changed yet.

  1. An agent writes the change on a branch.
  2. Code runs CI.
  3. An agent reviews the change.
  4. An agent fixes what CI or the review found.
  5. Code queues the change by priority, brings it up to date and merges it. If there are conflicts, an agent resolves them.
  6. A person comes in only where the settings ask: an approval, a question passed up to them, or releasing a held task.
