How this project works

From your ask to main

Mechanics are code, judgement is a model's, and you decide what to build and why.

  1. You ask in a chat or a goal. A goal plans the work, splits it into changes and keeps a report.
  2. An agent produces each change on its own branch.
  3. Code runs CI on it.
  4. Gates run if the landing rules ask for them: an agent's review, a test workflow, or a person's approval.
  5. An agent repairs anything CI or a review found, and the checks run again.
  6. Code queues the change by priority, updates it and merges it. If it conflicts with main, an agent resolves the conflict first.

No agent can merge or update a branch. Code merges exactly the commit that passed the checks.

Added by T4 just now

When work stops

A task stops and waits for a decision in these cases:

  • its budget, deadline or tries ran out
  • an action failed or its outcome is uncertain
  • main changed under its work
  • the agent or procedure doing it stalled
  • a deployment limit was reached
  • a person stopped it

temper never guesses past that. The task above it, or a person, has to release it.

The three ways this project offers

This project lands work the Agents review way now.

You approve

An agent makes each change; nothing reaches main until you approve it.

  • You approve: there's no agent review. After CI and any repairs, nothing merges until you approve each change yourself.

Agents review · now

An agent makes each change, another reviews it, and code lands it.

  • Agents review (now): a second agent reviews each change, and code merges it once checks and review pass. You don't approve each change.

Draft first

You and an agent write a design draft; agents build it on its own branch, and it lands whole.

  • Draft first: you and an agent start by writing a design draft. An agent plans from it, several agents build pieces that code merges into one shared branch, and then that branch goes to main as one unit. Use it for larger work that should arrive in one piece.

Who decides changes to this

You're the project's owner. A switch to another way, or any other settings change, comes to you as a proposal that you accept or reject.
