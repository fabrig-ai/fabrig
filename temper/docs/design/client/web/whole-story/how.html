What reaches you

on vsr; each project has its own
Agents decide, then tell you
  • wording and names inside a spec
  • retrying or splitting a task
  • implementation choices a spec leaves open
  • test-only changes

Listed in Decided for you for 24 hours, to overturn.

Asks you
  • a change to the protocol core
  • a departure from a landed design
  • a new dependency

While you're away: the last two are decided with the recommended choice and listed. The protocol core still asks.

Always waits for you
  • money past a budget
  • what can't be undone: rewriting history, a force-push, deleting unlanded work
  • changes to this page

Away or not.

What follows a landing

code triggers, agents judge

vsr-rs follows vsr

Each landing on vsr's main that touches src/ or include/ makes a port change in vsr-rs, owned by Porter, vsr-rs's standing role. Its check: vsr's C tests, built against vsr-rs.

code hears the landingPorter portscode checks

Tiers on main

On main's newest landing, at most once a day: fuzzing for 6 hours, MSan and TSan builds, coverage. A red becomes a finding for its area's owner, who makes the repair.

code runsthe owner triages
