temper runs software work for you. Agents do the tasks on your project's repositories and land the results there.

  • You ask in a chat. You talk to an agent like me. A bigger request becomes a goal, which temper tracks and reports on. A goal can plan the work, split it into smaller tasks and ask you questions as it goes.
  • Agents do the work. Each task runs on a model from one of the connected accounts. It has limits on its time, how much it can spend and what it may touch. To go past those limits, an agent must propose it and someone who is allowed must accept.
  • Changes land through the forge. A coding agent writes each change on its own branch and opens a pull request. The change merges only when its CI checks pass and any required approvals are in. If a merge turns the checks red, temper sends a repair.
  • Things wait for you in your inbox. That covers questions, proposals and approvals that need you. Tasks can also be held until someone releases them.
  • Settings say how it all behaves. They cover which agent does which job and with what instructions, who must approve before a change lands, and which models run. The project's owners change settings one accepted proposal at a time, and each acceptance is recorded as a numbered revision. Running work keeps the settings it started with.

If you'd like, I can go through how this project is set up now: who approves changes, which models run, and what must pass before a change lands.

What temper does

temper runs software work for you. Agents take tasks on this project's repository, work/hello, and land their changes there.

Added by T2 3 min ago

Asking for work

You ask in a chat. A bigger request becomes a goal, which temper tracks and reports on. A goal can plan, split itself into smaller tasks and ask you questions as it goes.

Who does the work

Each task is done by an agent on a model from a connected account. These models are available now: Opus 5.5, Sonnet 5.5 and Fable 5.1. Every task has limits on its time, its spending and what it may touch. To go past them, an agent proposes, and someone who is allowed to decides.

How a change lands

Coder         writes on its own branch
  ↓
Pull request  opened on the forge
  ↓
Checks        CI, up to date, review gate
  ↓
Merge         into work/hello

To land, a change must pass CI, be up to date with its target branch and pass one blocking review gate. Right now no human approval is required. If a landing turns the checks red, temper sends a repair.

What waits on you

Questions, proposals and approvals that need you go to your inbox. A task can also be held until someone releases it.

Settings

Settings say which agent does which job, with what instructions, who approves and which models run. Owners change them one accepted proposal at a time, and each acceptance becomes a numbered revision. Work that is already running keeps the settings it started with. Everything here is still what temper starts with (revision 1).

Open questions

  • Should a person approve changes before they land, or is the agent review enough?
  • Should goals show their plans to you, and should you watch changes land?
