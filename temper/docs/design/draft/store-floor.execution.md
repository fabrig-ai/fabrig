# store-floor: execution

2026-11-15. How [store-floor.md](store-floor.md) gets built. It designs nothing: each milestone writes its own design from the draft as it runs, and lands whole, with its own tests, fixtures, workspace entries and gate rules. Each is a goal the user approves. Plans use the focused and fuzzy suites alone; walks come after landing.

## 2. Order

F1 to F3 in that order, once S7 has landed: they change the store crates S7 changes. F4 follows once dev.fabrig.ai runs S7, after F1, and in any order against F2 and F3. checkpoints' C1 (`checkpoints.execution.md`) follows F2, so that it is built on the smaller store crate. After F4, each redeploy of dev.fabrig.ai that runs jobs is followed by a landing like F4 (`store-floor.md`, section 5). Section 8's retirements are a later design of their own.
