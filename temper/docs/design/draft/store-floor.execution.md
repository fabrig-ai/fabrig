# store-floor: execution

2026-11-15. How [store-floor.md](store-floor.md) gets built. It designs nothing: each milestone writes its own design from the draft as it runs, and lands whole, with its own tests, fixtures, workspace entries and gate rules. Each is a goal the user approves. Plans use the focused and fuzzy suites alone; walks come after landing.

## 2. Order

F0 lands after S7, and dev.fabrig.ai's redeploy with S7 waits for it, so that one open runs F0's jobs and then S7's `task-logs` (`store-floor.md`, section 7). F2 needs only F0's explicit levels, so it may land before that redeploy. F1 needs the redeploy, since it removes what dev runs there. F3 comes last. checkpoints' C1 (`checkpoints.execution.md`) follows F2, so that it is built on the smaller store crate. After F1, each redeploy of dev.fabrig.ai that runs jobs is followed by a landing that drops them (`store-floor.md`, section 6).
