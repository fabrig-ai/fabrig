The reasons behind `probes-by-test.md`, from the user, 2026-11-14 and 2026-11-15.

- **What they asked:** on 2026-11-14, of a search's timeline, "would the full gates again be run after D is blamed or the queue just trusts the green coming from the bisection? (assuming bisection runs only the failing tests)". Probes ran the whole gate then, so nothing more was run. On 2026-11-15 they had probes by test drafted, from a proposal that left four points to settle: receipts by key for a probe that ran part of a gate; whether the top's whole run stands for the rest at a landed prefix; a test red at the top and green at every probe; and what the probe's input carries.
- **The draft's readings,** not the user's words: no key by selection, since a failure needs no whole run and a pass by part is never reused, as a tier's rerun makes no receipt (`probes-by-test.md`, 4); nothing landed on a probe by test, the green prefix proved with the units above it by the next round's whole gate, the one that round runs anyway, rather than a whole gate at the green prefix before its turn (one more whole gate per red that lands something) or the top's run trusted for the rest (a red hidden by a unit above, or a case the top never ran, reaching the branch with no gate seeing it) (5); every probe green blaming the top as whole probes do, its repair told so, and a rerun at the top left for later (6); the input named `temper_tests`, as a tier's, and its bounds the forge's `failing_tests` and `test_id_bytes` (3, 4).
- **A review round,** one, on Codex: its ten findings taken. Runs told apart by workflow and commit, not by gate, since temper finds a run by neither its key nor its inputs (`probes-by-test.md`, 4); only a selected failure moves the red bound, a failed receipt found for another failure kept but not used, and a probe that cannot say sending the search on whole (3, 4); a selected case absent at a lower prefix passing it; the report read as a tier's, many going whole, from a compact artifact the project uploads (3, 9); ids line-safe and a dispatch within `op_bytes`; the search's line kept until the next pull request (7); "every probed prefix" (6); the forge's facts still to record put before the milestone; the status ledger and `merge-queue.status.md` completed; the cost qualified where no units remain above (5).
