# claude-provider: status

2026-11-05. Where the design lags or departs from [claude-provider.md](claude-provider.md).

- **Design lags:** none.
- **Design departs:** 2: init writes no `documents.lines`: the `standard` profile's 16 holds the offer's three lines (`../protocol/setup/init.md`, 3), so an override would say less than it does (the `claude-always` cut, 2026-11-05, in the freedom the user gave it). 3: the program's `"fetched"` stays temper's word: smith takes absolute paths and the worker's agent has no directories, so temper hands smith a launcher's path, and every command of the source passes through it, which is how a status or a run fetches at all (`../protocol/setup/owned.md`, 6); the launcher finds the build by its size, the digest being checked when it is fetched, where Forgejo's fetch hashes a file already there, because every command passes through it and hashing 290 MB each time is too slow (the same cut). 3: "within the fetch's bounds": the bound is the pin's size, not `setup.fetch_bytes`, which the launcher has no document to read; and Claude Code has no `mirror`, a machine that cannot reach `downloads.claude.ai` using its own `claude` (the same cut). 3: "says it is fetching Claude Code": the Claude way's words are static, "If this machine has no Claude Code, this fetches it first.", on any machine, because the client does not know whether a build was found; the live lines are on the stderr of the command that fetches, in `temper program-login`'s terminal for a sign-in (`../client/pages/accounts.md`, 2; the same cut). 4: the model's figures are `temper-fake`'s program model's, as the user allowed. 5: no client world draws the Model step's cards from init's documents: a story on the shipped box does, with the real client (`bin/temper-box/tests/suite/startup.rs`, `a_fresh_box_offers_chatgpt_and_claude_with_no_claude_on_path`; `../protocol/setup/testing.md`, 1), which the request's real box asks for, so no second one was added (the same cut).
