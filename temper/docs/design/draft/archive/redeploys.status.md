- **Design departs:**
  - 5.3, *A restart said is waited for long*: a worker keeps its runs for the longer of the restart wait and its grace, not the wait alone, so a wait set below a worker's grace never shortens what it keeps (jig's `protocol/channel/restart.md`, 4). Because the word is to keep runs longer, never to cut them sooner (the designer, 2026-11-16).
  - 5.3, *What needs the engine waits*: a completion waits for a lapsed renewable grant only while its host says its renewals are held, its link to the engine lost; with the engine up, a lapse fails unsent as before (smith's `domain/session.md`, 4; jig's `domain/hosts/hub.md`, 6). Because that is how a source that must be signed in again still fails as it does now: the agent cannot otherwise tell a renewal that will come from one that will not (the designer, 2026-11-16).
  - 3.1: the host tools' contract's layout is each declaration's name, effect and input schema; what a tool means, and its description, move the version by its author's hand (`../../protocol/wires.md`, section 7). Because a description's wording is no layout a gate can judge; the goal of 2026-11-12 decided it.
  - 6.1: a job whose delivery began when the cancel after the drain reaches it lets the delivery settle and answers as it ends, finished or failed, rather than being left for the next attempt to recover; only a delivery the stop bound cuts is left to it (jig's `domain/hosts/hub.md`, 9). The delivery settles in any case, so its outcome is known and nothing need be run again (the designer, 2026-11-12).
  - 5.1, 7.1: the check reads a checkpoint, which an owner's act takes while the engine serves, not the stopped deployment (`../../protocol/binaries.md`, section 2; `../../protocol/checkpoints.md`, 3), and `upgrade --workers` reads the verdict's inputs alone again, over a checkpoint taken at the settled stop before the swap (`../../protocol/wires.md`, 10.2). Because a checkpoint is the state at one commit, which the check reads whole while the old build serves, and the stop's read catches what changed since (`checkpoints.md`, 6, the user's draft of 2026-11-15; goal 7514's designer, 2026-11-18).
  - 7.1, step 1: the backup is a checkpoint of the stopped deployment, taken mostly by links (`../../protocol/checkpoints.md`, 2.1), so that a redeploy takes one at every settled stop, rather than a copy taken with the engine stopped for a build that runs a store job. Because a checkpoint at the stop costs links and small copies, so every redeploy has its backup (`checkpoints.md`, 6, the user's draft of 2026-11-15).
  - 6.1: in one process, `temper-box serve`, the worker does not drain: it is stopped after the engine has settled its claims, so a turn it let end could not be committed, and it cancels at once as before (`../../protocol/service-process.md`, section 1; the designer, 2026-11-12).
