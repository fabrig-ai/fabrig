# journey-walks: execution

2026-11-18. How [journey-walks.md](journey-walks.md) gets built: one milestone, "Journeys as walks, not recordings", of nine goals, each named here by the title it is started under. Look requests, the browser's and the TUI's, are drawn and landed all the while (`journey-walks.md`, 8.3), so the one writer comes first and each journey moves to the world under it. Each goal writes its own design from the draft as it runs, brings the designs it changes in line in the same landing, and lands whole, with its own tests, workspace entries and gate rules. Plans use the focused and fuzzy suites alone: no goal walks a box, and the box's walks are written and compiled, never run. A goal may run `temper-client-walk print` and the journeys' reprint, which start no process (`journey-walks.md`, 5.2).

## 2. Order

- **The one writer first, alone, at once.** It ends the conflicts: from its landing no goal records a journey or commits a journey file, and a change to the wire has none to touch. The writer keeps main's pages current after each landing, walking boxes as `again` does today.
- **Look requests go on through every goal.** A request is drawn on main's pages. Whoever lands it compares by the reprint in its own tree, or, for a journey that has moved, by `temper-client-walk print`. Nothing in this order holds a request back.
- **What the one writer does not mend:** `chat-draft`, the one journey with no pages today, stays without until it moves with the sign-in and chat journeys, unless a repair of its walk lands sooner.
- **Browser journeys next:** every later goal stands on its two libraries, the reader and the walker. From it the browser's journeys leave the box one at a time.
- **The set-up journey, then the sign-in and chat journeys,** each adding what the next browser journeys need. **TUI journeys beside them,** after the browser's first: the TUI's host on the service is the largest new piece, and lands with one short journey before the three long ones.
- **The TUI's longer journeys after both:** they start `after project-landing`.
- **The old tooling goes once the last journey has moved.** The fixed clock's removal and the docs close the milestone.

## 3. Acceptance

A moved journey's own proof is the writer's first run on it, after landing. In a plan, each goal holds what its journeys need by tests on small walks of its own, and prints its journeys into scratch as it works.

- **One writer for journey pages:** no test replays, reprints or compares a committed recording or page; a recording made stale by hand fails none; `tools/tiers/budgets.toml` names no committed recording; the scans that read every tracked file still pass. The writer's command, given a tree whose journeys are current, writes nothing; given a stale recording, it asks for that journey's walk alone; a second run while a change of its own is open starts none. The delivery check refuses a journey file changed beside another file, with and without a base, and a nonempty overlay; the merge job settles a journey file's conflict with no model; the refresh keeps a request whose trailer is on main and not yet printed, and drops it once a `Printed:` commit covers it.
- **Browser journeys without a box:** a walk of the tests' own prints the same bytes twice, in one process with no child and no socket; a control that appears late is found, and one that never does stops the walk by its journey and line, the others still printed; a reload keeps the small store; a page opens from the scratch directory with its stylesheets; `pages` with one word of the view changed writes exactly the pages that draw it, and leaves a directory with no `walk` of version 2 to the other engine; the binary's dependencies hold no browser kit; a journey's measured cost is in the goal's account, and its tests sit in their layers within the budgets as they stand.
- **The set-up journey without a box:** an owned set-up's steps are drawn as the peer reports them, in order, on the simulator's time, with no step through ctl.
- **Sign-in and chat journeys without a box:** a walk with a tab reaches the page the sign-in returns to, its account connected through the client; scripts join along a chain of two.
- **TUI journeys without a terminal:** the TUI's host draws a chat's streamed reply from the simulated service; `tui approve` approves what the TUI browsed, and a TUI not approved stays on its approval; a recipe's walk signs in as before.
- **The TUI's longer journeys without a terminal:** each journey's scripts read, and a walk of the tests' own goes through a delegated question and a pane's keys.
- **The old journey tooling removed:** no `recording` or `setup` under a journeys' directory; the tool has no `again`, `normalise` or `add`; `print FILE OUT` refuses an OUT under the repository's journeys, and a file recorded at another layout by that layout's name.
- **The journeys' fixed clock removed:** no `--fixed-start`, `internal-fixed-start` or `TEMPER_INTERNAL_FIXED_START` in the code or its help.
- **Journey docs brought up to date:** the citations' gate passes, and each status file says what still lags.
