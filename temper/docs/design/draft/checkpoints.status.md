# checkpoints: status

2026-11-22. Where the design lags or departs from [checkpoints.md](checkpoints.md).

- **Design lags:** none.
- **Design departs:**
  - 3.2: a transcript whose file is missing at C is left out, its record saying so, rather than failing the checkpoint: a drop a crash cut short leaves the same, and the live store reads it as dropped (jig's `protocol/store/checkpoints.md`, 4.3). Decided by goal 5099's designer, 2026-11-16.
  - 4: the answer's held bytes are those only the checkpoint names, its copies and each linked file whose link count is one, rather than those the live store doesn't name: io's stat gives no file's identity to compare with the live store's, and the figure says what removing the checkpoint frees (jig's `protocol/store/checkpoints.md`, 4.6). Decided by goal 5099's designer, 2026-11-16.
  - 5.3: the staged generation links only the logs the checkpoint linked whose files end at their extents (ended tasks' turns logs), and copies every other log up to its extent, rather than linking each log whose file ends at its extent. The restored store appends past the extents of a live task's turns log and of every history log, and a linked file would change the checkpoint, whose files never change (2) (jig's `protocol/store/restoring.md`, 4.4). Decided by goal 6983's designer, 2026-11-17.
  - 5.3: the intent names the staged generation, the safety checkpoint and `active`'s digest, and the staged transcript tree by its fixed name, `transcripts.staged/`, rather than in its record: one restore runs at a time under the deployment's lock (jig's `protocol/store/restoring.md`, 2). Decided by goal 6983's designer, 2026-11-17.
  - 6: the redeploy that takes these steps is not built in this repository: the deployments' operator builds it outside fabrig, and temper designs and builds each step on its process: the act's checkpoint while the old build serves (`../protocol/checkpoints.md`, 3), the new build's `upgrade --check` and `upgrade --workers` (`../protocol/binaries.md`, section 2), the engine's settled stop (`../domain/root-restart.md`, 1.2), the stop's checkpoint (`../protocol/checkpoints.md`, 2.1), a worker's drain (`../domain/worker/README.md`, section 2; `../client/ctl/workers.md`) and going back (`../protocol/checkpoints.md`, 2.5). Because the user decided, 2026-11-20, that the cross-host redeploy is internal tooling that belongs outside fabrig.
  - 6, step 1: the staged build's `upgrade --workers` reads a checkpoint taken while the engine serves as well as the stop's (`../protocol/binaries.md`, section 2), so that a redeploy sending the engine alone can run it once over the check's checkpoint before the stop and refuse, with nothing stopped, a staged build that cannot read the verdict again at step 4, such as one before C3. The draft runs the check alone before the stop. Decided by goal 8397's designer, 2026-11-18, on the user's request of that day.
  - 6, step 4: the verdict's inputs are read again by `upgrade --workers`, a rehearsal of reach `Openings` that makes the stop's checkpoint's maps without their task logs in a scratch, linking the snapshot and every segment but the newest and copying the newest and the secrets, recovers them, reads the wires and the openings and ends, rather than reading the rows in place: a checkpoint's files never change, and the stores' recovery writes, though never to a linked file. No record is walked and no job runs, so it is no second rehearsal of the upgrade, and the stop's links and small copies stay those of step 3 (`../protocol/binaries.md`, section 2; jig's `protocol/store/opening-rehearsal.md`, 1). Decided by goal 7514's designer, 2026-11-18; its links by goal 8397's, 2026-11-18.
  - 6, step 6: going back after the first commit restores the stop's checkpoint with the new build, then starts the previous build, rather than restoring with the previous build: the restore's safety checkpoint opens the deployment as the new build left it, over whose registry the previous build would have to register its own layouts, which a checkpoint's open refuses (`Unready::Upgrade`, jig's `protocol/store/checkpoints.md`, 5), or meet a layout only the new build registered; no binary moves a level (jig's `protocol/store/records.md`, 3). The generation restored holds the stop's format row and registry, which the previous build opens in place; starting the previous build over the store as it stands serves only where the new build registered nothing the previous build lacks (`../protocol/checkpoints.md`, 2.5; jig's `protocol/store/restoring.md`, 4.3). Found by goal 6983's designer, decided by goal 7514's, 2026-11-18; its reason restated in registry terms by goal 9096's, 2026-11-19.
