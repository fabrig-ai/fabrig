# branch-reds: status

2026-11-14. Where the design lags or departs from [branch-reds.md](branch-reds.md).

Milestone B1 is designed, by goal 2476. `../domain/forge/reds.md` covers a goal's reds, the `red` tool (`../domain/agent/tools.md`), their end by the tool and with the goal, and the worker's read at each check's start with the files it writes. The worker's read goes through an application's ask on jig's channel (jig's `domain/hosts/hub.md`, 10; `../protocol/channel.md`; `../protocol/wires.md`, 6). The families are in `../protocol/store.md`, 2, and the bounds in `../protocol/configuration/limits.md`. The reference's check reads the file beside the tree's list, its cache keyed on the file's digest (`../../../../tools/pre-pr/design.md`, 5 and 7), and fabrig's charter texts record reds with the tool.

Milestone B2 is designed, by goal 2811. `../domain/forge/reds.md`, 5.5 to 5.8 covers the check's results file, the worker's report at each check's end, refused checks included, a change's passes kept and the reds they end when it lands, and flakes filed or counted as findings (`../domain/findings.md`, 4). The reference's check runs a failing test's process again, through one-process's `--again`, and writes the results (`../../../../tools/pre-pr/design.md`, 4 to 7; `../../../../tools/tiers/design.md`, 11.9).

- **Design lags:**
  - 8: `.temper/known-reds.md`, its cap and the merge job's rule for it stay (`../../../../tools/pre-pr/design.md`, 5; `known-reds-merge.md`), and `delivery-checks.status.md` defines inheritance by that list.
- **Design departs:**
  - 3: a red's generation is the deployment's count of records, kept in one row, `RedNumber`, not the goal's (`../domain/forge/reds.md`, 2 and 6). It still orders a goal's records as the draft asks, with no counter per goal to keep and erase (goal 2476's designer, 2026-11-13).
  - 3: a red ended by its change's landing leaves nothing in the goal's activity: no call ends it, and telling the goal would wake its coordinator at each such landing; its `red list` no longer names it (`../domain/forge/reds.md`, 5.7 and 9; goal 2811's designer, 2026-11-14).
  - 6: a change keeps each red's latest observation by its passed checks, where the draft keeps a check's results "with the change at that tree". Checked is delivered (smith's `domain/run.md`, 8.1), so a refused check's tree is never the change's: its passes change nothing, though its flakes are filed. The results file also says `failed KEY` for a red the run selected that failed, so that a later passed check takes back an earlier pass, while a key a later check doesn't run keeps the earlier pass, as a resolution's check runs less than its producer's (`../domain/forge/reds.md`, 5.5 and 5.7; goal 2811's designer, 2026-11-14).
  - 6: a check's report is sent once; one refused or lost is not sent again, so "once per identity" holds by construction, and a lost report ends less (`../domain/forge/reds.md`, 5.6 and 9; goal 2811's designer, 2026-11-14).
  - 7: a failure an entry names is not run again: it refuses nothing already, and counting it against `rerun_processes` would spend the bound on a goal's expected failures, so a recorded red that is a flake is not filed as one. A flake's second log is its run's status, since one-process keeps no passing test's output (`../../../../tools/pre-pr/design.md`, 4 and 6; goal 2811's designer, 2026-11-14).
  - 9: `reds_read_ms` and `rerun_processes` are the checkout's, `checkout.reds_read_ms` and `checkout.rerun_processes` (0 to 16), not among the forge's limits, since the worker waits for the engine's answer and writes the rerun bound for the check (`../protocol/configuration/limits.md`; goal 2476's designer, 2026-11-13; goal 2811's designer, 2026-11-14).
  - 10: a hold of a goal with reds is placed on any worker, as every hold is. A worker of the previous versions writes no reds file, so its checks judge without them, where the draft places such a hold on a worker of the new version. Placement by agreed version keeps a task off a channel only for an assignment that cannot go down (`redeploys.status.md`, 4.3), and a worker of the previous versions is gone after the next workers-in-turn redeploy (goal 2476's designer, 2026-11-13).
  - 10: the read and the report cross as an application's asks, new kinds of `jig-worker-wire` with temper's bytes in `temper-worker-wire`, both moving with their bridges, where the draft names the worker's wire alone. A worker can ask the engine nothing outside a run's own calls, and the user ruled out riding those (the user, 2026-11-13). jig's ask, a read until B2, may now carry a report the engine keeps (jig's `domain/hosts/hub.md`, 10). A worker of the new versions closes against an engine of the previous ones, so the engine goes first (jig's `protocol/channel/bridges.md`, 6.3; goal 2476's designer, 2026-11-13; goal 2811's designer, 2026-11-14).
- **Open:** none.
