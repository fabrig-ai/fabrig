- **Design lags:**
  - 5.2, 5.3: no design says where `temper-engine-service` is cut, or how its split lands (G4). `jig-domain-core`'s cut is designed (`jig/docs/design/domain/engine/README.md`, 3), and so is `temper-engine-domain-forge`'s (`temper/docs/design/domain/forge/README.md`, 3).
- **Design departs:**
  - 3.5: each context is read by one `cargo tree` and one `cargo metadata --filter-platform`, not by `cargo tree` alone. `cargo tree` names packages, and rustls's two entries are one package, so the metadata says which entry, by its name in code, each member names there (`tools/crates/design.md`, 3.3). G1's designer's reading, 2026-11-12.
  - 3.5, 7.1: that the bundle's nested build sets `selected` is pinned by `temper-client-bundle`'s step tests on its nested commands, not by the boundary suite, which can't call a build script's code (`tools/crates/design.md`, 3.3). G1's designer's reading, 2026-11-12.
  - 4.5, 7.3: each of the two client wires, `jig-client-protocol-wire` and `temper-client-protocol-wire`, holds a second, small family beside its own: the public wire's (`public_v1.rs`). So its own family is a shared crate's family, over 20,000 lines. The size check keeps the rule as written and excepts both, until each public family has a crate of its own (`tools/crates/design.md`, 3.1 and 5). G7's designer's reading, 2026-11-12.
  - 7.3: the 20,000-line bound on a family measures every package that holds generated record code, the owners of 4.2 among them, and not only codec crates (`tools/crates/design.md`, 2.2 and 3.1). G7's designer's reading, 2026-11-12.
  - 6.3: shared test code goes to a library its binaries depend on, and not always to a crate in `testing/`: a world's shared code that drives that world alone goes to the world's own library, as skein's layout has it for a world's binaries, so `temper-real-loop-world`'s 11 lines need no crate (`tools/crates/design.md`, 3.2). G8's designer, 2026-11-12.
  - 6.3: the binary's path reaches a kit from the running test's environment, which the test's runner sets, through `skein-scratch`'s `paths::binary`, as `temper-box`'s support already reads it; no argument carries it (`tools/crates/design.md`, 3.2). G8's designer's reading, 2026-11-12.
  - 7.4: two files that a library's own tests and its integration suite both compile, in `temper-client-shell-terminal` and `temper-engine-domain-ways`, which the draft's survey didn't name, stay the check's exceptions: a kit would depend on the library, and the library's own tests would meet two copies of its types (`tools/crates/design.md`, 3.2). G8's designer, 2026-11-12.
  - 4.4: the codec command that learns to write a family's generated code into its codec crate is the owner's drift test. skein-codegen's `patch` command keeps the owner's schemas, kept texts and patches and never wrote generated code; each owner's drift test already names each family's paths and writes its code when asked, and now names its codec crate there (skein's `data/codec/command.md`, section 1, and `data/codec/README.md`, section 6). skein-codegen doesn't change. G2's designer's reading, 2026-11-12.
  - 4.4: `temper-protocol-store`'s older versions' generated code, `v12.rs`, `v13.rs` and `v14.rs`, is dropped rather than moved. skein's `data/codec/README.md`, section 5, keeps one version's code, an older record being read as a generic value and patched. Of the three, nothing compiled `v13.rs`, no test used `v12`, and one test used `v14` to read a patched record, which it now reads otherwise. Moved, `v14`'s 50,000 lines would compile in every build of the codec crate (temper's `protocol/store.md`, section 4). G2's designer's reading, 2026-11-12.
  - 4.4: callers keep the owners' paths. Each store re-exports its codec crates' modules at its root under their names, with no end set, and a caller may name either path. Every caller outside the two stores depends on its store for other items too (its `codec` module, `sizes`, `keys`), so naming the codec crate would save it no build (jig's `protocol/README.md`, section 5; temper's `protocol/store.md`, section 4). G2's designer's reading, 2026-11-12.
  - 5.3, 7.3, 9: `Core` can't be cut (5.2), so `jig-domain-core`'s split moves its vocabulary, about 11,000 lines that cross its edge, to a crate below it, `jig-domain-core-vocabulary`, rather than making two halves side by side. `jig-domain-core` keeps `Core` and re-exports the vocabulary, so it isn't a facade that goes once no caller names it. The libraries that need only the vocabulary, and reach the core through nothing else, depend on the vocabulary instead (`jig/docs/design/domain/engine/README.md`, 3). `jig-domain-core` stays over 7.3's bound, at about 88,000 lines with its step tests, and keeps its exception until `Core`'s state is grouped into owned parts (`jig/docs/development/debt/D003-core-one-object.md`; `tools/crates/design.md`, 3.1). G6's designer's reading, 2026-11-12.
  - 5.3, 7.3, 9: `temper-engine-domain-forge`'s state machine, `Domain`, can't be cut either (5.2): 35 of its files add methods to it. So the forge's split moves its vocabulary, about 10,000 lines that cross its edge, to a crate below it, `temper-engine-domain-forge-vocabulary`, rather than making two halves side by side. The forge keeps `Domain` and re-exports the vocabulary, so it isn't a facade that goes once no caller names it. The libraries that need only the vocabulary, the store's among them, depend on it instead, and compile beside the forge (`temper/docs/design/domain/forge/README.md`, 3). The forge stays over 7.3's bound, at about 70,000 lines with its step tests, and keeps its exception until `Domain`'s state is grouped into owned parts (`temper/docs/development/debt/D013-forge-one-object.md`; `tools/crates/design.md`, 3.1). G5's designer's reading, 2026-11-13.
