## 2. Order

- **Mechanism before words:** A1 moves text without changing it, and A2 builds `.goal/` with no word yet telling a goal to use it. A3 switches the words once both have landed, so that nothing promises what code doesn't do yet.
- **fabrig runs unchanged** ([any-project.md](any-project.md), section 8): A1's acceptance is the same text per wake; A3's is the same rules, from fabrig's guide and overlay; A2 and A5 change nothing fabrig's goals read.
- **Main stays redeployable to dev.fabrig.ai at every landing** ([ways.execution.md](ways.execution.md), section 2). A by-hand step dev.fabrig.ai needs is named under `## Dev` in the goal's result: for A1 and A3, the charters applied again with the release's tree, and the resolved charter read back and its room measured on every wake, on staging before dev; for A5, the gate's labels.
- **A1, A2 and A5 start together.** A3 follows A1 and A2, and A4 follows A3, since a chat's snapshot without a path leans on `design`'s words. One milestone holds the five.
