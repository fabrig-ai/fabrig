# smith: code-quality review

_Kept raw. Its rubric and the reports `01..13-*.md` it links are in `2026-10-31-quality-areas.md` beside this file. Paths are relative to `smith/`, at `aa95945cc`; the run that carried it out landed in main at `0f6e45d89b`._

2026-10-31. Source: github `manual/component-kit` at `aa95945cc`, a fresh clone at `~/src/fabrig/leads/smith-review/survey`, reviewed as it stands on that branch. Paths are relative to `smith/`. Scope: about 298k hand-written lines of Rust, of which about 167k are tests, plus 26k generated.

Method:
- **A high-level pass by me:** the house rules, smith's design, the crate graph, and a rubric built on skein's: [`rubric.md`](rubric.md). It pins the score scale, so scores here are not directly comparable with skein's.
- **12 area reviewers and one cross-area reviewer,** reading production code and tests together: [`reports/`](reports/), `01..13-*.md`. They read hot spots closely and sampled the rest. This is an assessment, not a line-by-line audit.
- **Spot checks by me,** about 30 claims against the source, listed at the end.
- **Nothing was built or run.** Every size is an estimate.

## Verdict

**smith is disciplined code carrying concentrated debt.** The strict subset holds almost perfectly: no `while` or `loop` in the seven domain crates, no closures or `matches!` in step code, and 3,350 citations of which only 137 are dead (130 of those are one path). The debt sits in five places, and it is not spread evenly:

- **Economy is the weakest criterion:** 2/5 in 9 of the 12 areas. Tests and fixtures retype what already exists.
- **One test crate is a fork of another.** `tests/protocol-llm` copies `tests/agent`, and that fork also keeps part of production alive.
- **Six of the eleven largest state owners do not follow section 5.4,** for one shared reason: several lifecycles folded into one struct.
- **smith lags skein.** Several mechanisms already exist in skein and smith does not use them.
- **Bulk-generated comments** sit over otherwise careful code: stamps, filler field docs, a banned word on about 1,900 lines. Some of the docs are now false.

**Size.** The reports claim about 29k lines. De-duplicated and discounted, the estimate is **about 20k of 298k (6.7%), of which about 13k is mechanical**; treat it as 15k to 25k. Production code loses about 5%, test code about 8%. The tree is not bloated in general. As in skein, the waste is in a few repeated shapes.

## Defects found along the way

This was not a bug hunt, and none of these was run.

1. **A sub-agent's overflow can leave a run's alarms armed, and they abort it.** `crates/smith-domain-run/src/run.rs:1468` moves the run to `Winding` through `hard_stop`, then the child path returns at `:1507` with no `follow`, the only place `Alarm::Deadline` and `Alarm::Park` are cancelled. If either fires while main closes, `deadline` (`:1569`) or `park` reaches `unreachable!`. I traced this by reading, and I found no test in the crate or `tests/run` that sends a child an overflow. It needs a child's spend or usage arithmetic to overflow and an alarm in that window, so it should be rare, but the result is a fail-stop. Fix: end the child path in `follow` (02 F1).
2. **`smith-agent` can exit 1 with no message.** `run`'s doc says failures are "already logged", but the three `?`s of the program block (`crates/smith-agent-shell/src/agent_shell.rs:510-513`) write nothing, and `src/bin/smith-agent.rs` discards the error (08 F14).
3. **A test reviews the wrong seed.** `World::authenticated(21, ...)` is followed by `assert_passed(20)` (`tests/local-process/tests/suite/authentication.rs:37,43`), so a failure names the wrong seed (11 F3).
4. **Reported by reviewers, not checked by me:** `Capture::Unknown` is treated two ways in `smith-events` (04 F3); `local_failure` says "credential or endpoint unavailable" for unrelated causes (05 F9); `b"invalid answer"` is sent 19 times, also for things that are not answers (09 F3); `login.rs` omits `XDG_RUNTIME_DIR` from a retyped environment list (08 F5).

## Themes, ranked by payoff

### 1. The `tests/protocol-llm` fork

About 4,300 lines of its 5,000-line support are identical to `tests/agent/src` (05 F1, measured independently by 07, 13 and me). Other test crates barely copy text; **this is the one verbatim-copy problem in the tree.** Its cost goes beyond size:

- The world calls `Client` through its own adapter, not `Component`, so root stories never run production's finish path, against `llm.md` section 10 (05 F2).
- Production keeps a caller-handoff surface that only this bypass uses (05 F3).
- About 5,000 lines there are domain stories in a protocol world. `root_memory.rs` (1,742 lines, 2 tests) hand-prices domain types (05 F4).

**The ratio is not earned:** 17k lines of tests for 5k of production, where about 8–9k would do.

**Fix:** `smith-agent-world` becomes `World<B: Backend>`; protocol-llm keeps `wire`, `pool_peer` and the native-request half of its referee, and depends on the agent world (13 Q1 checked that this makes no cycle). **About -3,500 lines, plus -1,500 and 2,000 moved from the stories, plus -300 production.** Also delete the orphan `tests/agent/src/wire.rs` (509 lines).

### 2. Several lifecycles folded into one struct

| Owner | Fields | Follows 5.4? |
|---|---|---|
| agent `Service` | 57 | Composition, but a mode held in `Option` (07 F1) |
| `Backend` | 54 | No: process × turn × stop |
| `ProcessAdapter` | 46 | No: the host's io hub under a process's name |
| `Conversation` | 43 | Partly: compaction, final and owed sit off the table |
| host `Agent` | 39 (12 bools) | No: the run's words × the process tree |
| local `Domain` | 38 | No: chat × agent life × delivery × end |
| channel `Component` × 2 | 24, 19 | No: 255- and 280-line `drain`s, indent 15 and 16 |
| `Store` | 24 | No: 18 dataless phases, 237 arm lines |

Section 5.4 describes one machine per entity. These owners are several machines, and no single enum fits a product, so the data stays in the struct. Every exemplar above is one lifecycle pulled out into its own type. **The fix is one enum per lifecycle, not one large enum,** and defect 1 shows the cost is not only in reading.

The priority is the local host's delivery: about 790 lines of `domain.rs`, including the 300-line `git_result`, the riskiest logic in the host and the least reviewable (10 F2). `git.rs` beside it shows the form. State conversions save little (about -400 lines); the gain is clarity.

### 3. Retyped setups, and `Limits` above all

- **245 full `Limits` literals, 4,125 lines, 163 in tests.** A policy limit touches 27 files, a declared one up to 75; a wire limit touches 4. The wire is cheap and the cost is above it (13 Q3).
- `Event::Start` about 88 sites, `Turn` about 218, charters about 86.
- `tests.rs` in `smith-domain-run` is 5,279 lines. `Event::Ended {` appears 75 times.
- Tests write private state: 145 assignments in `smith-protocol-program`, 31 in `smith-agent-service`, 19 in `smith-local-domain`. This must be fixed before theme 2, or each conversion rewrites them.

**Fix:** one `Limits` preset per layer in the owner crate behind a `fixture` feature, because inline tests cannot import a world that depends on them (four crates have that cycle). Then `Limits { x, ..SMALL }`. Make `Event::Start` carry a `Start` struct. Named constructors in each world. **About -6,000 lines, mechanical.**

### 4. The host retypes the run's vocabulary

The key judgement of the review. Most parallel vocabularies are **required**: `Cap` in session and run (siblings share no domain types), the wire and store records ("records are smith's own types"), and `ModelFault`, which changes a clock base. Leave those.

**32 types in `smith-host-domain` are not.** They match the run's by variant, 22 with identical bodies, and `delivery.rs` shares 413 of 431 lines with the run's. `smith-host-domain` is no sibling of `smith-domain`: it depends on it and already names `run::Charter`. So the firewall its doc claims does not exist.

**Fix:** re-export, keeping `ModelFault` and `RunFailure`. **About -700 lines.** Then `OpenEvent`, `Below`/`Lower` and the three `Launch` structs, about -250. See decision D1.

## Decisions for you

- **D1. Host vocabulary:** recommend re-exporting the 32 types. `hosts.md`, line 391 says "as its own vocabulary" and `host.md`, section 12 leaves a vocabulary crate open, so this is the designer's call.
- **D2. Event projection:** recommend moving it to `smith-protocol-events`. No lines saved; `smith-agent-service` gets one job.
- **D3. Shared translation:** recommend splitting about 1,670 lines out of `smith-protocol-channel`, which is "the agent's half" yet is imported by host and local.
- **D4. `smith-fake-claude` in the root's `[dependencies]`:** `shell.md` says no binary links a testing crate. Recommend an optional dependency with `required-features`.
- **D5. Amend 5.4** to say one enum per lifecycle. Recommend yes; it is what the exemplars already do.
- **D6. Apply skein's D2 here:** 10 of 16 test manifests still deny `wildcard_enum_match_arm`, and benchmarks pay 581 lines for it. Recommend yes. Separately, `crates/clippy.toml` bans `Vec` and `String` in test modules, which is why 19 inner `#![allow]`s exist.
- **D7. `manual_map` in step crates:** 31 honest `expect`s, because closures are out. Recommend allowing that one lint, about -90 lines of attributes.

## Beyond the review: the north-star docs

My view of `skein/docs/foundation/programming-model.md` and `testing-strategy.md`, read in full with `notes.md` and skein's review. **I'd change a few things, but the core of both docs should stay.** They made sense and produced good code at a reasonable cost. Most of the problems come from gaps in them, not from wrong rules.

Rule dates come from the docs' history, and code dates from smith's history before the import (`8fc1567b7`), with blame on a small sample: the run's `tests.rs` and four owner structs. Treat them as indicative.

### Which problems are really legacy

| Problem | Rule dated | Code dated | Reading |
|---|---|---|---|
| Rust subset | by 10-03 | throughout | **Held**, even the rules only review enforces (no `while` in domain crates, no closures in step code) |
| 5.4 state shape | by 10-03 | `Backend` 10-20; `Conversation`, host `Agent`, local `Domain` mostly before 10-17 | **Not legacy**, though code from before 10-05 may come from temper |
| Test shape (section 10) | 10-17 | 151 of 152 tests in the run's `tests.rs` predate it | **Mostly legacy**, but `builtin_tests.rs` (10-20) still edits recorded streams with `.replace` |
| `protocol-llm` fork | no rule covers it | 10-06 | **A gap in the rules** |

Mechanical rules held, and rules that need judgement about shape didn't, so a `syn` checker isn't the priority. 5.4 also appears in neither the model's section 1 nor any `AGENTS.md`, while the subset is in both, and agents are told to read section 1 first. That's only a correlation, but the fix is one bullet.

### Changes that would prevent these problems

**Programming model**

1. **Put 5.4 in section 1 and `smith/AGENTS.md`.** This is the cheapest change with the biggest likely effect.
2. **Sharpen 5.4:**
   - One enum per lifecycle, never a product of lifecycles or a set of flags.
   - State enums don't derive `PartialEq`. Owners that follow 5.4 have 0 state comparisons and those that don't have 18–37, so making `==` a compile error forces a `match`.
   - No `return` between moving the state out and `follow`, which is exactly defect 1.
3. **Add a composition section.** The largest owners (57, 46 and 32 fields) are composition roots, and the model only sketches those. Each field should be a stage, no modes in an `Option`, and `work_pending` should use the same named gates as the passes.
4. **Say that a translation must change something:** a clock base, sealing, resolved tickets or removed content. Otherwise it's a re-export. Section 4.1 is about entities, not values, and the host's copies treat it as a firewall.
5. **Name code generation as the answer to no-generics.** The model never mentions it, yet 379 lines of schema generate 24,000, while `smith-events` keeps five hierarchies by hand.
6. **Limit exhaustiveness to decisions.** One exhaustive accessor beside the enum (`owner()`, `tool_call()`), with callers using `if let Some`. This is skein's D8 convention, but it isn't written in the doc yet.

**Testing strategy**

7. **Move a harness on its second use by any crate,** not the second service. That rule left the fork uncovered.
8. **Extend "a setup written once" across crates,** with one preset per owner for large config structs, which would address the 245 `Limits` literals.
9. **Add a home tier per behaviour** (skein's S3), and promote smith's "no copies of shipped code" into the strategy.

**Both docs**

10. **Replace "copies already landed stay as they are" with a ratchet.** Section 6.3's closing paragraph is the pattern. Make every rule name what holds it, and count the hand-written copies whenever a skein mechanism lands.
11. **Add the margin lesson from `tech-debt.md`:** a bound taken from a capture needs headroom.

**Cleanups**

- **Promised but not run:** in this repo `llvm-cov` appears only in the strategy doc, and skein and smith have no `fuzz_target!`. Wire them in or cut them. Transition coverage matters most, because defect 1 is an unreached cell, though it can only see that once each cell is its own function.
- **Stale since 10-28:** sections 10.2 and 10.3 still say "bounded containers" and justify bans with "growth without a check", yet `Map::uncapped` and `List::uncapped` exist.
- **Not north-star material:** about a quarter of the strategy is operations (budgets, nextest flags, "doubling" nine times, dated quotes). Move it out, which would also satisfy the repo's own no-history rule.
- **Decided but not written in:** D1, D3, D7, S1 and S3 from skein's review aren't in either doc. Apply those first.

### My opinion of the docs

- **The foundation is excellent.** Sans-io steps plus replaying worlds is the best decision in the system. One lifecycle everywhere and explicit flow control come next. The 10-28 memory rewrite shows the docs can correct themselves.
- **The cost looks reasonable, with one caveat.** About 298k lines in roughly four weeks, with only about 5% of production code removable, is a strong result for agent-written code. But my rubric told reviewers to accept rule-forced verbosity, so "the rules aren't the cost" is partly assumed. Nobody measured the alternative. The largest cost anyone recorded was 581 lines, in benchmarks, which aren't step code.
- **I'd keep the strict rules, leaning towards quality.** That means no closures, traits or generics in step code, no `_`, and checked arithmetic. One way to write everything suits many agents, and it makes diffs reviewable. I'd relax only the edges: `manual_map`, and lints in test crates (D2).
- **The biggest gap isn't in these docs.** They say how to write code, not when to consolidate it, and each task's diff looks fine on its own. That belongs in the process docs, as skein's S6.

If only three things change, I'd do item 1 with the lifecycle rule from item 2, then the composition section (item 3), then the general ratchet (item 10).

## Suggested order of work

1. **The three defects above.** Small, and independent of the rest.
2. **Comment and dead-code sweep** (theme 7, dead parameters, unused dependencies, the orphan). Script most of it. Also update `tech-debt.md`: its strict-subset entry is stale (`while` and `loop` are at 0).

4. **Adopt what skein has** (theme 5). Needs no skein change.
5. **Fixtures and `Limits` presets** (theme 3), including the tests that write private state.
6. **Collapse the fork** (theme 1), then trim the production surface it kept alive.
7. **skein additions, then adopt them.** `Event::owner` and `Document::member` first.
8. **`smith-events` helpers** (theme 6).
9. **The host vocabulary** (theme 4), after D1.
10. **5.4 conversions** (theme 2), one lifecycle at a time, local delivery first, each after its tests stop writing private state.

Naming and file splits go along the way, not as separate projects.
