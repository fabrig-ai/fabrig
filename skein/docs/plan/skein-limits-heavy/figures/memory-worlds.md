Each command uses `--test suite`, `NEXTEST_DOUBLE_SPAWN=0`, and the target runner from the common note. The probes include each row's specified costly and median tests. Counts include process startup; no child processes are summed. Tiny differences on unchanged tests are process and TLS variability, not claimed gains.

The retained-seed backpressure intermediate was 981,587,877 Ir, before the referee fix. `common` alone consumed 800,759,652 Ir there (81.58%). After the fix the whole test is 181,517,712 Ir. The largest-store read change leaves its peak exactly 132,257 bytes; its referee costs 4,208,798 Ir and `read_whole` 176,411 Ir after the change. At the request's CPU weights, eliminating those two causes would save about 0.00072 s and 0.00003 s respectively: both below 0.05 s. Remaining backpressure work is 80,167,477 Ir in `Proc::iterate`, including the IO stages, and metering; even removing the entire remaining test would save only about 0.020 CPU s at the request's weight.

## Found and not fixed

- **KV CRC-32C:** recovery spends 952,029,012 Ir and packing 634,821,686 Ir in the checksum after reducing rows. A four-byte table prototype increased whole-test counts to 1,766,352,475 and 1,261,092,713 Ir from 1,487,365,608 and 1,075,059,421 at the same 2,500 rows. It was discarded, including its temporary test. A different checksum algorithm would need unchanged Castagnoli bytes and block/tail verification without the extra unoptimized block-conversion and lookup overhead. No product code changes ship.
- **KV duplicate-key scans:** `has_later` is 51,242,700 Ir (3.45%) in recovery setup and 49,994,515 Ir (4.65%) in packing setup. Their combined upper bound at the request's original weights is about 0.017 CPU s, below the stop rule. Replacing it would require a per-batch last-operation index while preserving validation/refusal order. Disk and recovery commit counts stay; no smaller count was established from their assertions.
- **KV observation:** `World::files` is 36,975,270 Ir (10.27%) in the tiny-store baseline. `Observed::check` needs the snapshot start at bytes 6..14 as well as log lengths, so a stats-only replacement is insufficient. A metadata/short-header observer could avoid copying whole files while preserving the snapshot-start assertion; it is left as a measured follow-up. The 2,000-commit run observes three snapshots, last start 1,948, most retained log 64,842 bytes under 65,536 plus an 8,192-byte segment.
- **TLS real crypto:** in the memory baseline, key-exchange completion alone is 526,803,252 Ir (21.81%), key generation 309,033,251 (12.79%), and signature verification 253,164,773 (10.48%); these overlap other handshake totals. They exercise real TLS and stay. Server configuration is only 44,746,105 Ir (1.85%) and client configuration 8,759,776 (0.36%): together about 0.006 CPU s at the memory test's request weight. Moving them cannot reach the stop rule, so meter ownership and settings construction stay. The offset census reaches a distinct TLS 1.3 failure wait at offset 23; a tail cut with a few offsets of margin removes only three of 30 (about 0.027 CPU s even before unavoidable setup), so all 30 stay.
- **LLM JSON and metering:** the dense-array baseline has 780,667,328 Ir in collector input, 743,105,245 in tokenizer input and 697,153,999 in parse (inclusive, overlapping); `Json::from_bytes` is 789,685,779. Fixing retained replay conversion would reach product code outside this task; `skein-json` and `skein_heap` are explicitly closed. The fixture helpers are 21,317,574 Ir (`events`, 0.75%) and 15,204,682 (`response`, 0.54%), together about 0.0046 CPU s at the request's weight. They and the 37-byte HTTP chunks stay. The median probe's fixture helpers total 362,940 Ir. Formatted world traces remain the named ownership of `skein-world-costs`.

## Counts

- `target::many_small_rows_pack_to_the_target` and `target::recovery_stays_near_the_target_under_a_large_chunk`: 3,300 → 2,500 rows of 1,040 encoded bytes. The const assertion requires two copies of all rows (5,200,000 bytes) to exceed recovery's unchanged 4.5-target bound (4,718,592), and therefore the smaller snapshot bound (2,359,296). Normal packing produces 1,008, 1,008 and 484 rows, with a snapshot step peak of 2,121,364 and recovery transient of 1,600,220 bytes. Bite: packing to `Limits::chunk` instead of the target makes one 2,600,012-byte chunk and a 5,311,092-byte peak; the chunk-count assertion fails and the printed peak exceeds the snapshot bound. That packing-only mutation still passes recovery (3,183,958-byte transient), so it does **not** establish the spec's predicted recovery failure on its own. Mutating the shared target calculation to return `chunk` also admits a 2,600,058-byte read and a 5,281,110-byte transient; recovery fails its 1,048,576-byte read bound, and its printed transient also exceeds 4,718,592. Both mutations restored.
- `files::the_largest_admitted_store_stays_within_its_memory_ceiling`: read size 2 → 1,024 bytes; 32,768 data reads → 64, plus end-of-file. The whole file remains 65,536 bytes, the peak is 132,257 → 132,257, and the ceiling stays 170,000. The search of IO world call sites found no other large `files::world` maximum: the small stories and `fuzzy::files` use 3 and retain two-byte reads. Bite: ceiling 132,256 fails `peaks.iter().all(...)` with peak 132,257. Restored.
- `scenarios::*` using `CALM`/`CHAOS`: calm `[1, 2, 3, 4]` → `[1, 2]`; chaos `[5, 6, 7]` → `[5, 6]`. All scenario expectations and explicit assertions stay, and `fuzzy::scenarios` sweeps the same scenarios over 150 seeds of each kind. No story needed a dropped seed locally. Bite: making backpressure's server read from time zero fails at retained seed 1: 128 bytes handed to IO before 50,000,000 ns, past the unchanged 112-byte bound. Restored.
- `exchange::closes_in_every_state`: ranges `0..60`/`0..10` → named counts `0..40`/`0..6`. First exchange occurrences are Handshaking at seed 0, Room and notification at 2, Above at 4, Bytes at 19; the failed-stream Close first appears at 2. Prefixes 20 and 3 are the smallest satisfying all existing assertions, doubled for margin. Bite: forcing all closes to iteration zero fails the Room assertion, with every observed wait Handshaking. Restored.
- New referee check: making the matching-prefix path return one byte too few fails on `abc` against `abcd` (2 instead of 3). Restored. The mismatch path retains the exact first differing offset.
